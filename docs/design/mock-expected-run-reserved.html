The window cerbix reserved

Mock for FR-032 phase F — docs/specs/func-expected-run-ledger.md §7.4, §17.14, spec revision 33. The ledger gained one state: a window whose identity the core minted and committed, and for which no dispatch is recorded. It is deliberately NEITHER absence verdict, so it cannot borrow either one's cell. This page decides what it looks like — and it also carries a defect it found on the way in, which is the larger of the two changes.

The panel currently renders three different verdicts as a missed run. expectationCells maps covered, covered_late and time before ledger_from, and sends everything else to one cell — the --down outline whose whole meaning is "a run was due here and nothing ran". So unknown, issued_never_claimed and claimed_never_finished are drawn as missed runs today. The APPROVED phase-E mock already said otherwise — its verdict table gives unknown the hatch — so the implementation diverged from the drawing it was approved against, in the direction of over-claiming. With the ledger carrier OFF, which is the shipped default, EVERY window reads unknown: the panel draws a full row of missed runs on an instance where nothing was missed at all.

1 · One cell per thing the ledger can say §14, and what phase F adds to it

Seven verdicts, five cells. The rule the map has to keep is the one this requirement exists for: a cell may never claim more than the verdict behind it. Two verdicts share the outline because they say the same thing about the window — nothing ran in it — and the rest are distinct because they are.

2 · Three candidates for reserved drawn at the width the panel really uses

The same twelve windows in each row: nine covered, one late, one that nothing ran in, and one RESERVED. The cells are ~2.4px wide, which is what sixty checks across a panel gives — a candidate that only reads at four times that size is not a candidate.

Recommended: B, the neutral outline. It is the same geometry as the missed-run cell and a different HUE, which is the one difference that survives at 2.4 pixels — a dash pattern does not (A), and a second hatch collides with "the ledger holds nothing here" (C), which is a different statement: before ledger_from the ledger has no row at all, while a reserved window is a row that exists and says the dispatch is unproven. Neutral because the state is not a failure: nothing says the run did not happen, only that the core cannot prove it did.

3 · The carrier-off panel, as it draws today and as it should the divergence above

Same data, same instant, one map changed. The row on top is what an operator sees on a default installation today: eleven missed runs that never happened. The row below is what the ledger actually says — it was dispatched on a carrier that carries no identity, so nothing can be correlated and the honest cell is the one that claims nothing.

4 · What the readout and the legend say

legend
reserved — the core recorded this window before dispatching it and no dispatch is recorded. Neither a missed run nor a covered one.
hover
"reserved at 14:13:50 · no dispatch recorded" — and, when the transport is what refused the job, "· publish failed" from withheld_reason. The instant named is reserved_at, because that is the only instant this window has.
never
the word "missed", the word "late", and any count that adds reserved windows to either. A surface that totals them has decided what happened, which is the decision the state exists to refuse.

5 · What this mock does not change

The stroke. strokeSegments licenses a line only across covered windows and phase F adds no verdict that changes it — a reserved window breaks the stroke exactly as every non-covered verdict does. The observation ruler is untouched: it answers what cerbix SAW, and this band answers what it EXPECTED.
