FR-023 · a Service escalates its own outage

SPA deltas only. Two surfaces gain something; nothing else moves. The backend of this requirement is already in the branch — the ladder, its fail-closed predicates, and the write path this mock's control needs.

1 · The policy joins the paging panel it belongs to

ServiceAlerting.vue
Escalation policy on-call — payments rota ▾ audited · none → on-call
Its OWN save button, beside the declaration's — not folded into it. They are two writes with two audit actions, and one button that half-applies is worse than two buttons. The empty option is — none —, which CLEARS the policy: a service with no policy escalates nothing, and that must be sayable rather than only reachable by never having chosen.
Unchanged: the ownership checkbox, the Pages for chips, Confirm over, and the file-managed read-only note — which covers this control too, because a file's desired state includes the policy.

2 · The ladder's progress, on the incident that owns it

IncidentDetailView.vue
Checkout — service down investigating service · checkout ⛑ escalated to step 2 · 6m ago
Nothing to build here. The pill already exists and reads incident.escalation_step, which FR-023 now advances for a service incident too — so this surface works without a line of new frontend code. It is in the mock because a mock that omits it would imply it is missing.
step 1 · ops-webhook 14:02
step 2 · payments rota 14:12
step 3 · escalation-manager — not yet due
NOT built, and the reason is the backend's: this step list is drawn to show what an operator WANTS and to make the decision explicit — the API exposes no per-step state, only the current step index. Rendering three rows from one integer would be a guess presented as a record. If the list is worth having, it needs a read model first, and that is its own requirement.

3 · What is deliberately absent

—
  • No renotify field for a service. Monitors have one; services do not, and FR-023's D8 keeps it that way — the policy's own steps are the repeat mechanism. A control for a column that does not exist would be a promise the backend refuses.
  • No "escalate now" button. The ladder is a function of the incident's start and the policy's offsets; a manual push would be a page nobody can explain afterwards from the record.
  • No pause control. The ladder already pauses itself when the service's verdict goes stale or ownership is withdrawn, and acknowledgement is the operator's stop. A third mechanism would give three answers to "why is it quiet".
  • No graph hint. §14's graph annotates and links; it does not suppress, and the ladder does not consult it (D5). A UI implying otherwise would teach the wrong model.
