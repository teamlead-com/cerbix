# iter-0002 — Persistence foundation (tenants, users, memberships)

## 1. Summary

Added the persistence layer: domain entities with their invariants
(`Organization`/`Project`/`User`/`Membership`, roles and scope rules), a hand-written
pgx v5 store with embedded goose migrations, and tenant-isolation queries. Wired the
database into the CLI (`cerbix migrate` + auto-migrate and DB-gated readiness in `serve`)
and added the `cerbix_database_up` metric. Verified end-to-end against a real Postgres 16,
including tenant isolation and a readiness drop when the DB goes away.

## Role-rule / self-healing / dedup checklist

- Rule residence: role/scope validity → `domain` (source of truth), re-asserted as a schema
  `CHECK` (defensive barrier, drift noted in D-0009); tenant-scope integrity → schema FK +
  `domain`; persistence → `infra`.
- Runtime self-healing for DB init: **no** (fail-fast, exit 1).
- Duplicate checks: role/scope exists in both `domain.Role.ValidForScope` and the SQL
  `CHECK` — intentional defense-in-depth, documented in D-0009 (single source = domain).
- Regression coverage: tenant isolation and cross-org FK covered by integration tests.
- Conclusions transferred to canonical docs before artifact removal: yes.
