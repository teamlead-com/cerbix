# iter-0003 — Authentication, authorization, and the tenant API

## 1. Summary

Delivered the security core: Keycloak OIDC login (Authorization Code + PKCE), server-side
sessions, just-in-time user provisioning, a pure authorization layer with a capability-based
role matrix, and the first REST API (organizations, projects, members, `/me`) enforcing
tenant isolation on every read and write. The full OIDC callback path is verified
hermetically with an in-process mock provider; isolation is verified by authz unit tests,
API handler tests, and store integration tests. Closes FR-004, FR-005, FR-006, NFR-006.

## Role-rule / self-healing / dedup checklist

- Rule residence: authorization rules → `domain`/`authz` (single source); request shape →
  `transport` (`api`); flow orchestration → `application` (`auth`); persistence → `infra`.
- Duplicate checks: role/scope validity exists in `domain.Role.ValidForScope`, the SQL
  `CHECK` (D-0009), and is consumed by `authz` — domain is the source; others are barriers.
- Runtime self-healing: **no** — OIDC/DB init fail fast; invalid sessions → 401, never
  auto-created.
- Regression coverage: isolation (authz + api + store), OIDC verify/nonce/state, session
  lifecycle all covered.
- Conclusions transferred to canonical docs before artifact removal: yes.
