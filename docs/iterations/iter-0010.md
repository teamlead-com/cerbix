# iter-0010 — Frontend: switcher, remaining views (monitors/new/members/SLA), e2e

## 1. Summary

Completed the backend-backed frontend surface. Added a `workspace` store + a working
org/project switcher, and ported the remaining screens 1:1 from the approved mockups:
**Monitors list**, **New monitor** form, **Members & roles**, **SLA & SLO**, plus a
guarded **delete** on Monitor detail. Every view reads the shared current-project
selection and reloads on switch. Verified end-to-end through the frontend nginx proxy —
built and run entirely in Docker, no host Node. Advances FR-011 (backend-existing surface
now complete; only the FR-012 incidents/status-page views remain).

## 2. Input artifacts

- Approved mockups + tokens (`docs/design/notes.md`), `openapi.yaml` contract.
- iter-0009 wired shell + Login/Dashboard/Monitor-detail.

## 3. What changed (by role)

### Agent A — Implementation (`frontend/src/`)
- **`stores/workspace.ts`** — Pinia store: loads the caller's organizations, restores the
  last org/project from `localStorage` (falls back to the first), reloads projects on org
  switch. Getters `currentOrg/currentProject/orgName/projectName`.
- **`components/AppShell.vue`** — functional switcher dropdown (orgs + projects, checkmark
  on current, click-away overlay); nav routes to real named routes; Incidents/Status page
  shown as disabled *soon* entries (FR-012). Reads org/project from the store.
- **`router/index.ts`** — added routes `monitors`, `monitor-new` (before `monitor/:id`),
  `sla`, `members`.
- **Views:**
  - `MonitorsView` — project monitors table (name→detail, type, target, interval, status).
  - `NewMonitorView` — type selector (HTTP/TCP/Push), per-type fields, conditions editor
    with quick-insert presets, live preview aside → `POST /projects/{id}/monitors`, then
    redirect to the new monitor.
  - `MembersView` — org memberships table + add-member form (user_id + scope + role) →
    `POST …/members`, and a static capability matrix mirroring `internal/authz`.
  - `SlaView` — project SLA window cards + per-monitor SLO table with inline objective set
    (`PUT …/sla-target`, error-budget badge) + maintenance schedule/delete
    (`POST`/`DELETE …/maintenance`).
  - `MonitorDetailView` — guarded delete action (`DELETE /monitors/{id}`).
  - `DashboardView` — refactored onto the `workspace` store (current project + `watch`).

### Agent B — Tests / verification
- Frontend image build in Docker (`--network=host`): `vue-tsc` type-check + Vite build
  pass, `cerbix/frontend:iter10`. Per-view code-split chunks (SlaView 11.05 kB, NewMonitor
  10.80 kB, Members 7.68 kB, …); main bundle 108.52 kB (42.15 kB gzip).
  - Caught & fixed one type error: generated `CreateMonitor` marks `interval_seconds`/
    `timeout_seconds`/`retries`/`enabled` required (they carry OpenAPI defaults), so the
    form always sends them.
- **End-to-end through the frontend nginx proxy** (Postgres + backend `--role=all` local
  login + the frontend image, all Docker, isolated network; requests via `localhost:8000`):
  login → `/api/v1/me` (admin); create org + project; **create a monitor via the form
  endpoint** `POST /projects/{id}/monitors` → pipeline drove it up (`30d` `3/3`, `100%`);
  `PUT …/sla-target` `objective 99.9` → SLA now returns `error_budget.met=true`;
  `POST …/members` (project viewer) → `201`, listed back; maintenance `POST`→`DELETE`
  (`204`); no-cookie `GET /api/v1/me` → `401`. Every endpoint the new views consume is
  exercised through the proxy. Containers + network removed after.

### Agent C — Docs
