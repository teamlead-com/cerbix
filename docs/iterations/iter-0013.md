# iter-0013 — FR-012 phase 2b-i: service-account API tokens (machine posting)

## 1. Summary

Added **service-account API tokens**, delivering FR-012's API-first requirement: org/project-scoped
tokens with a role, hashed at rest, issued/listed/revoked by org admins, and accepted as
`Authorization: Bearer` credentials by the same auth middleware. A token builds a scoped principal,
so machines post incidents/updates/postmortems (and any role-appropriate write) without a Keycloak
session — tenant-isolated, revocable, and attributed with `source=api`. Verified with hermetic
domain/middleware/handler tests, a DB-gated store test, and a real-binary e2e. FR-012 stays
IN_PROGRESS; subscribers/webhooks/feeds, KC client-credentials, and auto-incident remain (phase 2b-ii).

## 2. Input artifacts

- iter-0011 incidents, iter-0012 status pages; plan §"API authentication — both methods" (option 1:
  cerbix service tokens), verification §"Incidents/postmortems via the API".

## 3. What changed (by role)

### Agent A — Implementation
- **Domain** (`internal/domain/apitoken.go`): `ApiToken` with `Scope()` and `Validate()`
  (role-valid-for-scope, reusing `Role.ValidForScope`).
- **Migration** `00008_api_tokens.sql`: `api_tokens` (unique `token_hash`, role CHECK, nullable
  `project_id` cascade, `last_used_at`); `TruncateAll` extended.
- **Store** (`internal/store/apitokens.go`): create (stores only the hash), `ApiTokenByHash`,
  `TouchApiToken`, list/get/delete. Hash reuses the existing `store.HashToken` (hex SHA-256).
- **Auth** (`internal/auth/{context.go,middleware.go}`): `RequireAuth` gained a **bearer path** —
  after the session cookie, `Authorization: Bearer <token>` is hashed, looked up, and turned into a
  synthetic `authz.Principal` (`{org,project?,role}` membership, `UserID="apitoken:<id>"`,
  `ViaToken=true`); `last_used_at` stamped best-effort. Store interface gained
  `ApiTokenByHash`/`TouchApiToken`.
- **authz**: `Principal.ViaToken` (attribution only; authorization stays role-driven).
- **API** (`internal/api/handlers_apitokens.go` + routes): issue (returns the secret **once**),
  list (metadata only), revoke — all org-admin. `createIncident` sets `source=api` when `ViaToken`.
- **Contract** (`openapi.yaml` → 0.9.0): `tokens` tag, `bearerAuth` scheme + global
  `cookieAuth`|`bearerAuth`, token paths, `ApiToken`/`CreateApiToken`/`CreatedApiToken` schemas.
  Frontend types regenerated, `vue-tsc` green.

## Role-rule / self-healing / dedup checklist

- Rule residence: token scope/role invariants in `domain`; hashing + persistence in `store`; bearer
  resolution in `auth`; role-driven authorization unchanged in `authz`/`api`. Contract single-sourced
  in `openapi.yaml`.
- Runtime self-healing: none — invalid role/scope → 400; unknown/expired credentials → 401; a stale
  session cookie falls through to bearer then 401; a `TouchApiToken` failure is logged, not silently
  masking a denial.
- Duplicate checks: token hashing reuses `store.HashToken` (no second implementation); bearer auth
  reuses the existing `RequireAuth` and `authz.Can` (no parallel authorization path); management
  authz mirrors the org-admin pattern.
- Conclusions transferred to canonical docs before artifact removal: yes.
