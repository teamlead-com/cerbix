# iter-0014 — FR-012 phase 2b-ii: auto-incidents from monitor transitions

## 1. Summary

The watchdog now opens incidents on its own. The ingest pipeline detects a monitor's up/down
transition (via a previous-status-returning `SetMonitorStatus`) and, on going down, opens an
incident (`source=auto`, impact major, linked to the monitor); on recovery it auto-resolves the
open one. It never double-opens while one is active, and only ever touches incidents it owns.
Auto-opens count in `cerbix_incidents_opened_total`. Verified with a hermetic ingest test, a
DB-gated store test, and a real-binary e2e that toggles a live target. FR-012 stays IN_PROGRESS;
subscribers/webhooks/feeds and KC client-credentials remain, then the Vue views.

## 3. What changed (by role)

### Agent A — Implementation
- **Domain**: `Incident.MonitorID` (set for auto-incidents; empty for manual/API).
- **Migration** `00009_incident_monitor.sql`: `incidents.monitor_id` (`ON DELETE SET NULL`) + a
  partial index on `monitor_id WHERE source='auto' AND status<>'resolved'` for the open lookup.
- **Store**: `SetMonitorStatus` now **returns the previous status** (CTE) so callers detect
  transitions; `FindOpenAutoIncidentByMonitor`; `CreateIncident`/scan persist `monitor_id`.
- **Ingest** (`internal/ingest/ingest.go`): on each heartbeat, after persisting and updating status,
  `reconcileAutoIncident` opens (`!down→down`, deduped via the open lookup) or resolves
  (`down→up`) an auto-incident. Title `"<monitor> is down"`, opening body = the failing check's
  message, author `"auto"`. All steps best-effort (log, never fatal). `Recorder` gained
  `RecordIncidentOpened` (satisfied by the metrics registry; nil recorder tolerated).
- **Contract**: `openapi.yaml` `Incident.monitor_id`; frontend types regenerated, `vue-tsc` green.

### Agent B — Tests / verification
- **Hermetic**: `ingest/ingest_test.go::TestAutoIncidentOpenAndResolve` — healthy check opens
  nothing; two failures open exactly one (down→down does **not** duplicate); recovery resolves it;
  the recorder counts one open. `TestConsumerPersistsResults` adapted to the new signature.
- **DB-gated**: `store_integration_test.go::TestMonitorStatusTransitionAndAutoIncident` —
  `SetMonitorStatus` returns pending→down→up previous values and `ErrNotFound` on a missing monitor;
  `CreateIncident` persists `monitor_id`; `FindOpenAutoIncidentByMonitor` finds while open and is
  empty after resolve.
- **Suite**: `go build`, `go vet`, `gofmt` clean; `go test ./...` green with real Postgres —
  `internal/ingest` 73.1%, `internal/store` 77.3%, `internal/domain` 90.4% (all ≥70%); every package OK.
- **Real-binary e2e** (image + Postgres + a toggleable nginx target, `--role=all`): target healthy →
  monitor up, **no incident**; `docker stop` target → monitor down → **one** auto-incident
  (`web-target is down`, `source=auto`, `monitor_id` = the monitor); still down after more intervals →
  **still one** (dedup); `docker start` target → recovery → auto-incident **resolved** (timeline
  `investigating`→`resolved`, author `auto`); `cerbix_incidents_opened_total 1`.

## Role-rule / self-healing / dedup checklist

- Rule residence: transition→incident orchestration in `ingest` (application); previous-status and
  open-incident lookup in `store` (infra); incident invariants in `domain`. Contract single-sourced
  in `openapi.yaml`.
- Runtime self-healing: none in the config/auth sense — auto-incident *is* the intended
  self-reporting behavior, and it is idempotent (deduped) and best-effort (a failure logs, never
  masks or retries silently); it only ever resolves incidents it opened.
- Duplicate checks: one open auto-incident per monitor enforced by `FindOpenAutoIncidentByMonitor`
  before create; the incidents/updates/postmortem store paths are reused (no parallel write path);
  `SetMonitorStatus` remains the single status-write.
- Conclusions transferred to canonical docs before artifact removal: yes.
