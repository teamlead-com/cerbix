# iter-0015 — FR-012 phase 2b-iii: status-page incident feeds (JSON Feed / RSS / Atom)

## 1. Summary

Status pages now publish their incident history as standard syndication feeds — JSON Feed v1,
RSS 2.0, and Atom — served both to authenticated members and publicly, under the same visibility
gate as the render (public served, unlisted needs a token, internal hidden). Built stdlib-only
(no feed dependency), read-only, hermetically tested plus a real-binary e2e. FR-012 stays
IN_PROGRESS; outbound webhooks/subscribers and Keycloak client-credentials remain, then the Vue views.

## 2. Input artifacts

- iter-0011 incidents, iter-0012 status pages, iter-0014 auto-incidents; plan §"`RSS/Atom/JSON` feeds".

## 3. What changed (by role)

### Agent A — Implementation
- **`internal/feed`**: a `Feed`/`Item` model with three serializers — `JSON()` (JSON Feed v1),
  `RSS()` (RSS 2.0), `Atom()` — each returning `(bytes, content-type)`, using only
  `encoding/xml` + `encoding/json`. RSS dates RFC1123Z; Atom/JSON RFC3339; zero times omitted.
- **API** (`internal/api/handlers_feed.go` + routes): authed `GET /status-pages/{id}/feed`
  (member) and public `GET /api/v1/public/status-pages/{slug}/feed` (on `PublicRouter`, same
  visibility gate as the public render). `?format=rss|atom|json` (default RSS). `buildFeed` gathers
  the page's incidents from `statusPageProjectIDs` (the page's own project + its monitor-backed
  components' projects), newest first, capped at 20; item summary `status · impact`, link
  `#<incident-id>` on the page URL (base from `X-Forwarded-Proto` + Host).
- **Contract** (`openapi.yaml` → 0.10.0): both feed paths (three feed content-types), a shared
  `FeedFormat` query param. Frontend types regenerated, `vue-tsc` green.

### Agent B — Tests / verification
- **Hermetic**: `feed/feed_test.go` (each format marshals, re-parses to the expected structure,
  correct content-type; empty/zero-time renders); `api/api_feed_test.go` (public feed default RSS +
  JSON + Atom content-types and item presence; internal hidden 404; unlisted token gate; authed
  member vs outsider isolation).
- **Suite**: `go build`, `go vet`, `gofmt` clean; `go test -cover ./...` green with real Postgres —
  `internal/feed` 89.7%, `internal/api` 73.5% (all ≥70%); every package OK.
- **Real-binary e2e** (image + Postgres, `--role=all`): a public page with a monitor-backed
  component + two project incidents (one resolved) → the public feed returns **RSS** (correct
  content-type, both items with `status · impact` summaries), **JSON Feed** (version marker,
  `home_page_url` reconstructed from Host), and **Atom** (two entries); an internal page's feed via
  `/public/` → 404; the same page's feed for an authed member → 200; the public feed needs no cookie.

### Agent C — Docs
- `docs/decisions.md` (D-0024), `docs/traceability.md` (FR-012 phase-2b-iii row), `docs/status.md`
  (phase split), this report.

### Agent D — Ops

  visibility boundary. All build/test/e2e in Docker.
