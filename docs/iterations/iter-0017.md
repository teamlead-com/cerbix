# iter-0017 — Frontend: Incidents views (list, open, detail + timeline + postmortem)

## 1. Summary

Wired the **Incidents** Vue views to the incident API built across iter-0011/0014/0016, closing the
incident feature loop in the UI. The Incidents sidebar entry is now live; a project incidents list,
an open-incident form, and an incident detail view (timeline + update composer + quick-resolve +
postmortem publish) are all wired and verified end-to-end through the frontend nginx proxy — built
and run entirely in Docker, no host Node. Advances FR-011. Only the public Status page view remains.

## 2. Input artifacts

- Incidents backend (iter-0011 core, iter-0014 auto-incidents), approved mockup `d5baac16`,
  generated API types (`src/api/schema.d.ts`), the iter-0010 workspace store + AppShell.

## 3. What changed (by role)

### Agent A — Implementation (`frontend/src/`)
- **`components/AppShell.vue`**: moved **Incidents** from the disabled "soon" list into the live nav
  (routes to `incidents`); only **Status page** remains "soon".
- **`router/index.ts`**: added routes `incidents` (list), `incident-new`, `incident` (detail `/:id`).
- **`lib/incident.ts`**: single source of status/impact labels + token-driven badge classes
  (`statusBadge`/`impactBadge`), lifecycle order arrays, and a `relTime` helper.
- **Views:**
  - `IncidentsView` — project incidents table (title→detail, status/impact badges, source, started),
    New button, empty-state noting auto-incidents.
  - `NewIncidentView` — title + impact + initial status + opening body → `POST /projects/{id}/incidents`,
    then redirect to the new incident.
  - `IncidentDetailView` — header badges (status/impact/source, started/resolved), the timeline of
    updates, an update composer (advance status + body) with a topbar **Resolve** shortcut, and a
    postmortem panel that renders the published postmortem or (once resolved) a publish composer
    (`PUT …/postmortem`). Uses the workspace store's current project.

### Agent B — Tests / verification
- Frontend image build in Docker (`--network=host`): `vue-tsc` type-check + Vite build pass,
  `cerbix/frontend:iter17`. Per-view code-split chunks (IncidentDetail 7.05 kB, Incidents 3.87 kB,
  NewIncident split too); main bundle 109.06 kB (42.28 kB gzip).
- **End-to-end through the frontend nginx proxy** (Postgres + backend + the frontend image, all
  Docker; requests via `localhost:8000`): SPA 200; login; create org/project; **open an incident via
  the form endpoint** → detail loads (status/impact/source, one opening update, postmortem 404); add
  an `identified` update → `resolved` → **publish the postmortem** (200); the timeline shows all three
  updates in order and the postmortem reads back; the list shows the resolved incident; no-cookie →
  401.

### Agent C — Docs
- `docs/design/notes.md` (iter-0017 section), `docs/status.md` (FR-011 incidents-views evidence),
  this report.

### Agent D — Ops
