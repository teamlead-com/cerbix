# iter-0018 — Frontend: Status page views (management + public render) — FR-011 UI complete

## 1. Summary

Wired the **Status page** Vue views, the last designed screen, completing the FR-011 UI. An authed
management view creates pages (with visibility), manages their components, and links to the public
page and feeds; a standalone **public** view renders a page at `/status/:slug` without a session —
summary banner, components with 90-day uptime, active incidents, and RSS/Atom/JSON subscribe links —
honoring the unlisted `?token=` and hidden-page (404) cases. Verified end-to-end through the frontend
nginx proxy, built and run entirely in Docker. With this, all eight designed screens are implemented.

## 2. Input artifacts

- Status-page backend (iter-0012 render + components, iter-0015 feeds, iter-0014 active incidents),
  approved mockup `d4019300`, generated API types, the iter-0010 workspace store.

## 3. What changed (by role)

### Agent A — Implementation (`frontend/src/`)
- **`components/AppShell.vue`**: **Status pages** now a live nav entry; the disabled "soon" list is gone.
- **`router/index.ts`**: `status` (authed management) and a **public** `/status/:slug` route with
  `meta.public`; the guard lets public routes through for anyone (only login bounces authed users).
- **`lib/statuspage.ts`**: single source of component-status labels + token colors (`componentMeta`)
  and the page `summaryHeadline`.
- **Views:**
  - `StatusPagesView` — list an org's pages, create (slug/title/visibility, surfaces the unlisted
    token), select a page → manage components (add monitor-backed from the current project or a
    manual status, delete), and links to the public page + `rss/atom/json` feeds.
  - `PublicStatusView` — standalone (no `AppShell`) render of `GET /public/status-pages/{slug}`
    (+`?token=`): summary banner, active incidents, components with status + 90d uptime, and a
    subscribe footer; shows a clean not-available state on 404.

### Agent B — Tests / verification
- Frontend image build in Docker (`--network=host`): `vue-tsc` type-check + Vite build pass,
  `cerbix/frontend:iter18`. Per-view chunks (StatusPagesView 11.13 kB, PublicStatusView 5.27 kB);
  main bundle 109.44 kB (42.40 kB gzip).
- **End-to-end through the frontend nginx proxy** (Postgres + backend + the frontend image, all
  Docker; requests via `localhost:8000`): create a public page + a monitor-backed component and an
  open incident via the management endpoints → the **public render (no cookie)** returns `summary:
  operational`, the component `API operational 100% (90d)`, and the active incident; the `rss`/`atom`/
  `json` feeds return their correct content-types (no cookie); the **`/status/:slug` SPA route serves
  200** (nginx fallback → the public view); an internal page is hidden from the public endpoint (404);
  the authed management list shows both pages.

### Agent C — Docs
- `docs/design/notes.md` (iter-0018 section; FR-011 UI complete), `docs/status.md` (FR-011 → DONE),
  this report.

### Agent D — Ops
- No backend change. The public route bypasses auth in the client; the server's public endpoint is
  already unauthenticated with its own visibility gate. All tooling via Docker; no host Node.
