# iter-0022 — Email (SMTP) notification channel — FR-010 complete

## 1. Summary

Added the **email (SMTP) notification channel**, the last of FR-010's channel types. A project can
now alert monitor transitions via email alongside webhook/Slack/Telegram; delivery uses `net/smtp`
and each channel carries its own SMTP settings. Verified with hermetic domain/notify tests and a
real-binary e2e against a mailpit SMTP catcher (down → recovery emails to multiple recipients).
**FR-010 is DONE.**

## 2. Input artifacts

- iter-0020 notifications (channels, dispatcher, transition seam); the plan's Notifier set
  (Telegram/Slack/Email/webhook).

## 3. What changed (by role)

### Agent A — Implementation
- **Domain**: `ChannelEmail` type; `Validate` requires `config.to`, `config.smtp_host`, `config.from`.
- **Migration** `00013_email_channel.sql`: widen the channel type CHECK to include `email` (reversible).
- **`internal/notify`**: a `sendMailFunc` var (default `smtp.SendMail`); `deliver` branches to
  `sendEmail` for email channels — builds an RFC822 text/plain message (🔴/🟢 subject + body),
  `PlainAuth` when `smtp_username` is set, port default 587, comma-separated recipients — while the
  HTTP types keep the `render`+`post` path. Best-effort, logged on failure.
- **Contract** (`openapi.yaml` → 0.14.0): `email` added to the channel type enums. Frontend types
  regenerated, `vue-tsc` green.

### Agent B — Tests / verification
- **Hermetic**: `domain/notification_test.go` (email valid + missing to/host fail);
  `notify/notify_test.go::TestEmailDelivery` — a transition sends an email via a captured
  `sendMailFunc` with the right addr/from/recipients/subject.
- **Suite**: `go build`, `go vet`, `gofmt` clean; `go test ./...` green with real Postgres —
  `internal/notify` 73.6%, `internal/domain` 92.3%, `internal/store` 76.9% (all ≥70%).
- **Real-binary e2e** (image + Postgres + **mailpit** SMTP catcher + a toggleable target,
  `--role=all`): create an email channel (SMTP → mailpit, two recipients), link it to a monitor →
  stop the target → a **🔴 … DOWN** email arrives at mailpit for both recipients; start the target →
  a **🟢 … recovered** email arrives (2 messages total).
