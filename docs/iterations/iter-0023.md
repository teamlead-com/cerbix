# iter-0023 — Monitor edit (PATCH) end-to-end

## 1. Summary

Monitors are now editable. Added `PATCH /api/v1/monitors/{id}` with partial-update semantics
(type and push_token immutable) and made the frontend monitor form a create/edit form reached from a
new **Edit** action on the monitor detail. This closes the create-only gap noted since iter-0010.
Verified with a DB-gated store test, hermetic API tests, a green frontend build, and a proxy e2e.

## 2. Input artifacts

- iter-0004 monitor CRUD, iter-0010 monitor form + the "backend gap: monitor PATCH" note.

## 3. What changed (by role)

### Agent A — Implementation
- **Store**: `UpdateMonitor(ctx, m)` — updates name/target/interval/timeout/retries/conditions/enabled
  by id (type + push_token immutable), `ErrNotFound` when gone.
- **API**: `PATCH /api/v1/monitors/{id}` (editor+ via `monitorAccess`) — a pointer-field body merges
  onto the loaded monitor (omitted fields unchanged), `Validate`, then `UpdateMonitor`.
- **Contract** (`openapi.yaml` → 0.15.0): the PATCH path + `UpdateMonitor` schema.
- **Frontend**: `NewMonitorView` is now create **and** edit — route `/monitors/:id/edit` loads and
  prefills the monitor (guarding the type-change watcher), disables the type selector, and PATCHes on
  submit; `MonitorDetailView` gained an **Edit** action; router gained `monitor-edit`.

### Agent B — Tests / verification
- **Hermetic**: `api/api_monitors_test.go` — viewer 403, editor partial update (rename+disable keeps
  type/target), conditions-only update preserves the prior name, invalid interval 400, unknown 404.
- **DB-gated**: `store_integration_test.go::TestUpdateMonitor` — fields updated + persisted, type
  immutable, missing id → ErrNotFound.
- **Suite**: `go build`, `go vet`, `gofmt` clean; `go test ./...` green with real Postgres
  (`internal/api` 73.3%, `internal/store` 76.9%). Frontend image builds green (`vue-tsc` + Vite;
  `NewMonitorView` 12.07 kB with the edit logic).
- **Proxy e2e** (Postgres + backend + the frontend image, all Docker): create a monitor → **PATCH**
  through the nginx proxy (rename + new conditions + interval + disable) → reflected and persisted;
  a partial `enabled`-only PATCH preserves the name; an invalid `interval_seconds: 0` → 400; the
  `/monitors/:id/edit` SPA route serves 200.

### Agent C — Docs
- `docs/decisions.md` (D-0030), `docs/traceability.md` (monitor-edit row), this report.

### Agent D — Ops
- No migration (existing columns). All build/test/e2e in Docker.

## Role-rule / self-healing / dedup checklist

- Rule residence: update SQL in `store`, partial-merge + authz in `api` (reusing `monitorAccess`),
  validation in `domain`. The frontend edit reuses the create form (one component, one conditions
  editor) rather than a parallel screen.
- Runtime self-healing: none — an invalid merged monitor is rejected (400), a missing one is 404;
  omitted PATCH fields are intentionally unchanged (documented partial semantics), not silently reset.
- Duplicate checks: create and edit share `NewMonitorView`; `UpdateMonitor` reuses `scanMonitor` and
  `monitorColumns`; the immutability of type/push_token is enforced by simply not writing them.
- Conclusions transferred to canonical docs before artifact removal: yes.
