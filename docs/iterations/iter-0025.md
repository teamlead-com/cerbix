# iter-0025 — ICMP prober (host reachability / ping)

## 1. Summary

Added the **ICMP prober**, completing the MVP prober set (HTTP/TCP/ICMP/Push). An `icmp` monitor
pings its target with an ICMP echo and reports reachability + round-trip latency, flowing through the
same conditions/heartbeat/notification path as the other active probers. Verified with a hermetic
prober test (skips where ICMP isn't permitted), domain tests, a frontend build, and a real-binary
e2e (reachable → up with RTT, TEST-NET address → down) with the backend granted CAP_NET_RAW.

## 2. Input artifacts

- iter-0004 prober seam (HTTP/TCP), D-0028 (ICMP deferred as privileged); the plan's MVP prober set.

## 3. What changed (by role)

### Agent A — Implementation
- **Domain**: `MonitorICMP` type; `Active()`/`Valid()` include it (target required).
- **Prober** (`internal/prober/icmp.go`): `icmpProber` via `golang.org/x/net/icmp`+`ipv4` — resolve
  target, open the ICMP socket **unprivileged-first** (`udp4`) with a **raw fallback** (`ip4:icmp`),
  send one echo, report the first echo reply as reachable + RTT (else down + error). Registered in
  `NewRunner`. Dependency `golang.org/x/net` added.
- **Migration** `00014_icmp_monitor.sql`: widen `monitors_type_check` to include `icmp` (the type is
  DB-CHECK-enforced; the domain enum alone isn't enough).
- **Contract/UI**: `openapi` (→ 0.16.0) adds `icmp` to the monitor type enums; `NewMonitorView` gains
  the **ICMP ping** type (host/IP target, `[CONNECTED]`/`[RESPONSE_TIME]` presets). Frontend types
  regenerated, image builds green.

### Agent B — Tests / verification
- **Hermetic**: `prober/icmp_test.go` — loopback ping connects (skips if no ICMP socket can open),
  unresolvable host → not connected; `domain/monitor_test.go` (icmp active + validate + no-target
  fail).
- **Suite**: `go build`, `go vet`, `gofmt` clean; `go test ./...` green with real Postgres
  (`internal/prober` 70.1%). Frontend image builds green (`vue-tsc`).
- **Real-binary e2e** (backend `--cap-add=NET_RAW`, `--role=all`): an `icmp` monitor pinging the pg
  container → status **up** with a heartbeat (RTT latency); a second `icmp` monitor to the TEST-NET
  address `192.0.2.1` → status **down**. (The migration widening the type CHECK was required — the
  create returned `internal error` until then.)

### Agent C — Docs
- `docs/decisions.md` (D-0032, incl. the CAP_NET_RAW ops note), `docs/traceability.md` (ICMP DONE),
  this report.

### Agent D — Ops
- **ICMP needs CAP_NET_RAW** (or the `net.ipv4.ping_group_range` sysctl) on the worker; the prober
  logs and reports down otherwise. Migration additive/reversible. All build/test/e2e in Docker.

## 4. Requirements advanced

## Role-rule / self-healing / dedup checklist

- Rule residence: reachability semantics in the `icmpProber` (transport); type validity in `domain`;
  the type CHECK in the migration mirrors the enum; conditions reuse the shared engine (no
  ICMP-specific condition code).
- Runtime self-healing: none masking correctness — an unopenable ICMP socket or no reply is a real
  down (logged), not a silent pass; the socket flavor falls back (unprivileged→raw) but never fakes a
  reply.
- Duplicate checks: the prober registry gains one entry; `[CONNECTED]`/`[RESPONSE_TIME]` and the
  no-conditions default are reused from the TCP path; the type CHECK is the single DB-side enum.
- Conclusions transferred to canonical docs before artifact removal: yes.
