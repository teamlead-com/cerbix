# iter-0026 — Daily-availability rollup + 90-day dashboard timeline

## 1. Summary

Realized the daily-availability rollup deferred in D-0017: a `heartbeats_daily` table maintained by a
recompute-range job on the scheduler leader, and `availability` endpoints that read the rollup for
completed days plus today live from raw. The dashboard now renders its 90-day project timeline from
the API. Verified with a DB-gated store test (incl. retroactive-maintenance exclusion), an API test,
a green frontend build, and a real-binary e2e (seeded yesterday → rolled up; today live).

## 2. Input artifacts

- D-0017 (TimescaleDB CAGG deferred; plain-PG rollup fallback intended); the iter-0009 note that the
  90-day timeline needed an aggregate endpoint; the SLI maintenance-exclusion pattern (iter-0006).

## 3. What changed (by role)

### Agent A — Implementation
- **Migration** `00015_heartbeats_daily.sql`: `heartbeats_daily (monitor_id, day, up, total)` (plain
  table; a TimescaleDB CAGG can replace it later without changing reads).
- **Store** (`rollup.go`): `RollupDailyAvailability(from,to)` — **DELETE + INSERT the range in one
  transaction** (not upsert) so zeroed days (e.g. retroactive maintenance) are removed, aggregating
  raw heartbeats per (monitor, UTC day) with maintenance exclusion; `MonitorDailyAvailability` /
  `ProjectDailyAvailability` — rollup for completed days + **today computed live from raw**.
- **Scheduler**: the leader runs the rollup on a ~1-minute tick over a trailing 95-day window.
- **API**: `GET /monitors/{id}/availability?days=N` and `/projects/{id}/availability?days=N`
  (`DailyAvailability[]`, oldest first). `openapi` → 0.17.0.
- **Frontend**: `DashboardView` renders a **90-day project timeline strip** from the project endpoint
  (per-day segment colored by uptime; today live). Types regenerated.

### Agent B — Tests / verification
- **DB-gated (in-package)**: `store/rollup_internal_test.go` — inserts heartbeats with explicit
  timestamps (yesterday + today), rolls up, asserts yesterday (from rollup, 3/4=75%) + today (from
  raw, 2/2=100%); a **retroactive maintenance window** re-rollup removes the now-empty day; project
  live aggregate. `api/api_availability_test.go` — endpoints 200 + isolation 404.
- **Suite**: `go build`, `go vet`, `gofmt` clean; `go test ./...` green with real Postgres
  (`internal/store` 77.1%, `internal/api` 73.4%, `internal/scheduler` 72.2%). Frontend builds green
  (`DashboardView` 7.96 kB).
- **Real-binary e2e** (`--role=all`): a monitor accrues today's heartbeats; a **yesterday** batch is
  seeded via SQL; within the rollup tick (~55 s) the availability endpoint returns **yesterday 5/6 =
  83.3 % (from the rollup)** and **today 17/17 = 100 % (live)**; the project endpoint spans both days.

### Agent C — Docs
- `docs/decisions.md` (D-0033), `docs/traceability.md` (rollup row), this report.

### Agent D — Ops
- Migration additive/reversible; `TruncateAll` includes the table. The rollup is single-active on the
  scheduler leader; days are UTC (Postgres runs UTC). All build/test/e2e in Docker.
