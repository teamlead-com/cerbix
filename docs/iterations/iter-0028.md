# iter-0028 — SSRF guard in the prober (resolved-IP validation)

## 1. Summary

Closed the SSRF hole in the prober: workers probed operator-supplied targets (HTTP/TCP/ICMP) with no
IP validation — the HTTP prober followed redirects on a default client, TCP/ICMP dialed the target
directly. A new `prober.Guard` validates the **resolved connect IP** through a custom
`Transport.DialContext` (so it holds across HTTP redirects and defeats DNS rebinding by pinning the
checked IP), shared by the TCP prober; ICMP checks the resolved IP before sending. The policy is
corrected for this product: **private/RFC1918 targets are allowed by default** (cerbix monitors
internal apps), while **link-local / cloud instance metadata (`169.254.169.254`) is blocked by
default**. Introduces **NFR-011**.

## 2. Input artifacts

- The reviewer prompt's P0 (SSRF) and my correction of its default (the naive "block private IPs"
  breaks an internal-monitoring tool); the existing prober registry (`httpProber` default client,
  `tcpProber`/`icmpProber`), the config loader (strict YAML + defaults), and the worker wiring in
  `cli`.

## 3. What changed (by role)

### Agent A — Implementation
- **`prober/guard.go`** (new): `Guard{allowPrivate, allowMetadata}`; `checkIP` (unspecified/multicast
  always blocked → loopback/link-local/private gated → public allowed); `dialContext` (resolve →
  reject unless a candidate IP passes → **dial the checked IP, pinned**); `resolveChecked` for ICMP;
  `blockedIPError` (no network side effect).
- **`prober/prober.go`**: `NewRunnerWithGuard(g)` builds an HTTP client on a cloned default transport
  with the guarded `DialContext` and **`Proxy=nil`** (a proxy would bypass the IP check); the TCP
  prober takes the guarded dialer; ICMP takes the guard. `NewRunner()` keeps a **safe default**
  (private on, metadata off).
- **`config`**: `ProberConfig{AllowPrivateIPs, AllowMetadataIPs}` (`prober:` block); defaults
  private=true / metadata=false. **`cli`** wires `NewRunnerWithGuard(NewGuard(...))`.
  `packaging/config.example.yaml` documents the block.

### Agent B — Tests / verification
- **`prober/guard_test.go`**: a `checkIP` matrix (metadata blocked/allowed, loopback + RFC1918 gated
  by `allow_private_ips`, public always allowed, unspecified/multicast/IPv6 link-local/ULA); a
  **literal-IP dial** rejected *before* connect (`*blockedIPError`, no conn); a **hostname** dial that
  resolves then blocks; and the **full `Runner.Run` path** — a metadata HTTP target and a locked-down
  loopback TCP target both report down with `blocked target IP …` and never dial.
- **Suite**: `go build`, `go vet`, `gofmt` clean; `go test ./...` green over Postgres —
  `internal/prober` **84.7%** (up from 70.1%), plus `store` 76.9% / `api` 73.4% / `scheduler` 72.2% /
  `auth` 74.1% (all over the 70% gate). Existing prober/ICMP tests updated to construct the guard.

### Agent C — Docs
- `docs/decisions.md` (**D-0035**); `docs/status.md` (**NFR-011 DONE**); `docs/traceability.md`
  (NFR-011 row + summary note); `packaging/config.example.yaml`; this report.

### Agent D — Ops
- No migration, no new dependency. Default policy keeps every existing internal monitor working and
  only newly blocks metadata/link-local — a safe rollout. Blocked probes emit a clear message and a
  down heartbeat (they don't crash the worker). `allow_metadata_ips: true` is the documented opt-out
  for the rare legitimate case. All build/test in Docker.

## 4. Requirements advanced

**NFR-011 DONE** — probe targets are SSRF-guarded at dial time on the resolved IP, closing the
cloud-metadata / cross-tenant-reach hole while preserving internal monitoring.

## 5. Tests run + results

See §3 Agent B. The guard is exercised through the **real** `Runner.Run` pipeline (real `http.Client`,
real transport dial), not just the unit `checkIP`, so the hermetic test is functionally identical to
what the worker runs — no live-stack e2e was required (the guard is fully in-process, no new external
dependency or DB/migration surface).

## 6. Decisions

**D-0035** — validate the resolved connect IP via a pinned guarded dialer (covers redirects +
rebinding, proxy disabled); `allow_private_ips` default true, `allow_metadata_ips` default false;
non-routable always blocked.

## Role-rule / self-healing / dedup checklist

- Rule residence: the IP policy lives solely in `prober.Guard` (infra/dial boundary); config owns the
  two flags; `cli` wires them. No duplicate IP logic elsewhere — HTTP, TCP, and ICMP all funnel
  through `checkIP`.
- Runtime self-healing: none. A blocked target is reported down with a clear reason — it is **not**
  silently retried against a different address or downgraded; the check happens before any packet.
- Duplicate checks: one `checkIP`; the HTTP transport and the TCP prober share one `dialContext`; ICMP
  reuses the same `checkIP` via `resolveChecked`.
- Conclusions transferred to canonical docs before artifact removal: yes.
