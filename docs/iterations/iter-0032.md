# iter-0032 — Outbox dead-letter visibility + replay

## 1. Summary

Closed the operational gap left by the transactional outbox (iter-0029): an event parked as `dead`
after exhausting retries was invisible and unrecoverable. Added three **global-admin** endpoints to
**list** dead outbox events (with `last_error` and payload for diagnosis) and **replay** them — one by
id or all at once — by resetting them to a fresh pending state that the existing delivery worker picks
up. No new delivery path, no schema change.

## 2. Input artifacts

- iter-0029 / D-0036 (the outbox dead-letters at `maxAttempts`, incrementing `cerbix_outbox_dead_total`
  with no way to see or retry); the global-admin authorization pattern (`authz.ActionGlobalManage`,
  as used by organization creation).

## 3. What changed (by role)

### Agent A — Implementation
- **Domain** (`outbox.go`): `OutboxEventView` (id, topic, status, attempts, `last_error`, raw JSON
  payload, timestamps).
- **Store** (`outbox.go`): `ListDeadOutbox(limit)` (dead only, newest failure first);
  `ReplayDeadOutbox(id)` (resets `status='pending', attempts=0, next_attempt_at=now(), last_error=''`;
  matches only `status='dead'` → `ErrNotFound` otherwise); `ReplayAllDeadOutbox()` (bulk, returns count).
- **API** (`handlers_outbox.go` + routes + Store iface): `GET /api/v1/admin/outbox/dead?limit=N`,
  `POST /api/v1/admin/outbox/dead/{eventID}/replay` (204 / 404), `POST /api/v1/admin/outbox/dead/replay-all`
  (`{replayed:n}`). All guarded by `requireGlobalAdmin` (403 otherwise). Replays are logged for audit.
- **`openapi`** → 0.19.0 (`admin` tag, three paths, `OutboxEvent` schema).

### Agent B — Tests / verification
- **DB-gated** (`store/deadoutbox_internal_test.go`): list returns only dead; replay resets a dead
  event to a **due pending** row (status/attempts/next_attempt_at); replaying a pending id → `ErrNotFound`;
  replay-all requeues the remainder and returns the count.
- **Hermetic** (`api/api_outbox_test.go`): all three endpoints are **403 for an org-admin**; a global
  admin lists dead events; replay → 204, unknown id → 404; replay-all returns the count and empties the
  set.
- **Suite**: `go build`, `go vet`, `gofmt` clean; `go test ./...` green over Postgres (api 73.2%,
  store 76.5% — over the 70% gate).
- **Real-binary e2e** (`--role=all`): the bootstrap global admin logs in (local login), lists a seeded
  dead event (full payload returned), replays it → 204, and the **wired worker delivers the requeued
  event pending→delivered in ~1–3 s**; the dead list then reports empty; an unauthenticated request →
  401.

### Agent C — Docs
- `docs/decisions.md` (**D-0039**); `docs/status.md` (FR-012 dead-letter-ops note);
  `docs/traceability.md` (row + summary note); `openapi.yaml`; this report.

### Agent D — Ops
- No migration, no config change, no UI (an operational/admin surface). The endpoints are global-admin
  only. Replay is idempotent in effect (re-queues to pending; a still-broken endpoint simply
  dead-letters again after retries). Pairs with `cerbix_outbox_dead_total` as the alerting signal that
  tells an operator to investigate. Frontend TS client is additive and unused here, left unregenerated.
  All build/test/e2e in Docker.

## 4. Requirements advanced

The outbox delivery guarantee (FR-010/FR-012) is now operationally complete: dead-lettered events are
inspectable and recoverable after fixing the downstream, not silently stuck.

## 5. Tests run + results

See §3 Agent B — DB-gated store test, hermetic API authz test, full suite green over Postgres, and the
full-loop real-binary e2e (login → list → replay → wired-worker delivery → empty; 401 unauthenticated).

## 6. Decisions

**D-0039** — three global-admin endpoints; replay resets dead→pending for the existing worker;
`ReplayDeadOutbox` matches only dead rows (404 otherwise).

  the iter-0029 worker.
- Runtime self-healing: none. Replay is an explicit, logged operator action; a replayed event that
  still can't be delivered dead-letters again through the normal retry path (not hidden).
- Duplicate checks: one reset statement shared in shape by single and bulk replay; `requireGlobalAdmin`
  is the single guard for all three endpoints.
