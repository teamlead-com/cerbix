# iter-0035 — Provider-agnostic OIDC, p95, global search, 1:1 UI, docs-sync

## 1. Summary

A frontend-completeness + auth-decoupling + documentation-reconciliation iteration. Three threads landed:

1. **Auth decoupling** — the identity provider is now **any OpenID Connect issuer** (Keycloak, Auth0,
   Okta, Google, Entra ID), selected purely by `oidc.issuer` discovery. The `keycloak_sub` column was
   renamed to `oidc_sub` by rewriting the original migrations (no production instance exists). A public
   `GET /auth/config` endpoint plus a configurable `oidc.button_label` let the SPA render a
   provider-neutral sign-in. (D-0043, D-0044, D-0045)
2. **Backend metrics + navigation** — `p95_latency_ms` (via `percentile_cont(0.95)`) added to monitor
   and project SLA; a tenant-scoped `GET /api/v1/search` endpoint (D-0046, D-0047).
3. **Frontend 1:1** — every SPA view rebuilt to match its approved claude.ai/design artifact, with a
   consolidated Settings page (channels/tokens/webhooks), a self-service org/project create dialog, a
   topbar global-search box, and bespoke inline-SVG charts (no TanStack Query/uPlot). (D-0048, D-0049)

Finally, the whole documentation set was reconciled 1:1 with the shipped service (this iteration): every
prose doc had drifted to Keycloak-specific framing and was silent on six shipped features.

Closes **FR-012** (status pages/incidents were effectively complete) and adds **FR-016** (global search).

## 7. Open issues / Next iteration plan

Backend API gaps surfaced while building the views 1:1 (UI adapted honestly; logged, not faked):

- **Members:** endpoint returns no identity (email/display_name/last_active) → UI shows short user-id +
  Added date; no per-member `PATCH`/`DELETE` → roles static, no remove.
- **Incidents:** single `monitor_id` (no multi-component impact); postmortem is one markdown `body`.
- **SLA:** no time-series for a budget burn-down sparkline (current-state meter shown); `burn_rate`
  computed client-side (no schema field); no export.
- **New monitor:** no HTTP `method`, no notification linking at create, no push grace-period.
- **Public status page:** render exposes only aggregate `uptime_90d` (no per-day buckets); no public
  maintenance block, incident history, or email subscribers.
- **SSE realtime** remains planned-not-shipped (SPA polls today).

Candidate next epic: "cerbix API gaps for 1:1 UI" (members identity + mutation, public render enrichment,
incident multi-component, SLA burn-down history).
