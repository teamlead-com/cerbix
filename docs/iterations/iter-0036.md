# iter-0036 — Consolidation: reliability, incidents/status pages, SLO, instance-settings, security, geo-probers, sanitization

## 1. Summary

A consolidating iteration: it reconciles `iterations/` with the code after a long series of increments
delivered as separate `decisions.md` entries **D-0050…D-0086** (sometimes without a paired iter
report). The source of detail for each item is `decisions.md`; here is a map of the themes, the A/B/C/D
roles, and the acceptance. Everything was delivered on top of the fixed architecture (roles
`all/api/scheduler/worker`, `Dispatcher` inproc/rabbitmq, transactional outbox, strict config).

The main tracks landed over the period:

1. **Check catalog extended** to 15 types (postgres/mysql/redis/rabbitmq/promql/grpc/composite/push
   plus network/TLS/DNS/WebSocket/SSH), all via the SSRF-guard; secrets in `monitors.config` are encrypted.
2. **Alert reliability (Tier 1/2)** — confirmations (consecutive-failure threshold), maintenance
   suppression, re-notify, monitor tags; all on top of the transactional outbox (retry/backoff/dead-letter).
3. **SLO/SLA** — error-budget, **burn-rate alerts** (edge-triggered, D-0079) and **scheduled weekly
   SLA reports** (D-0080); maintenance windows are excluded from SLA.
4. **Incidents and status pages** — auto/manual/API incidents, timeline, postmortems, feeds; an incoming
   **Alertmanager webhook receiver** (firing→incident, resolved→closure by fingerprint, D-0081).
5. **Authentication** — 2FA/TOTP, self-service password reset, **OIDC configurable from the UI** with
   live provider rebuild (D-0082).
6. **Instance-settings framework** (D-0083) — a singleton `instance_settings` with JSONB groups
   (branding/announcement, auth-policy, alerting/global-silence, monitor-defaults) + a
   DB→config→defaults resolver behind an atomic snapshot; **SMTP group** with an encrypted password and a live mailer (D-0084).
7. **Security** — AES-256-GCM secrets-at-rest + rotation, SSRF-guard, global silence.
8. **Geo-distributed probers** (D-0085) — a `monitors.region` column, per-region queues
   `checks.jobs.<region>`, a `--region` worker, TTL on jobs; a **live-worker picker** (RabbitMQ mgmt
   API) and **Test connection** before creation (D-0086).
9. **Repository sanitization** — internal project names removed (module path `git.example.com`,
   `acme`/`globex`), the frontend is served by the binary from `embed.FS` (no nginx), CI brought into line.
