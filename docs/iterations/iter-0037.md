# iter-0037 — Incident context: heuristic RCA context for auto-incidents

## 1. Summary

First iteration of the "reliability features" package (spec `specs/func-incident-context.md`; next —
iter-0038 burn-windows, iter-0039 confirm phase, iter-0040 dependency graph). Every
**auto-incident** automatically gets one system timeline entry with a correlation summary:
how many of the project's monitors went down in the ±5 minute window, the dominant error
class, and whether it is a single region. 80% of the on-call engineer's routine of "what else
went down and how" — without AI or external dependencies. The SPA was not changed: the entry is
rendered by the existing incident timeline.

## 2. What was done

- **domain** (`incidentcontext.go`): a pure classifier `ClassifyProbeError(msg, code)`
  (timeout / dns / connection refused / tls / http-5xx / http-4xx / condition-assert /
  other; message patterns win over the code), the `IncidentContext` type + `Render()`
  (always with the "⚡ Context:" marker — which doubles as the idempotency key) and `Empty()`.
- **store** (`incidentcontext.go`): `IncidentContext(ctx, incident)` — a single bounded
  window query (±5m, cap 2000 rows): failing heartbeats × the project's monitors; aggregation
  in Go (classes, top-5 names of co-failures, single region). `AppendIncidentContext` —
  an idempotent insert of the system entry (`INSERT … WHERE NOT EXISTS(body LIKE marker%)`),
  the entry's status is inherited from the incident's current status.
- **outbox**: in `TopicIncidentEvent`, after successful webhook delivery — for
  `incident.opened` + `source=auto`, a best-effort build and attach of the context; a context
  error is logged as WARN and does **not** fail the delivered event. The worker's Store
  interface is extended with two methods. The `RootCause` field is reserved for iter-0040.

## 3. Verification

- domain: table-driven `TestClassifyProbeError` (11 cases), `TestIncidentContextRender`.
- store (`TestIncidentContextAndAppend`, DB-gated): co-failures inside/outside the window,
  dominant class, single-region → hint / mixed → empty; append twice → one entry,
  author=system.
- outbox (`TestIncidentContextAttached`): opened+auto → attach; re-delivery → no duplicate;
  manual → no context; webhook failure → retry without attach; context error → event
  delivered.
- `-race`: 30 packages green.
- **E2E** (live binary `--role all` on the dev DB): 3 tcp monitors against a dead port →
  3 auto-incidents, each with exactly one entry
  "⚡ Context: 2 other monitor(s) … dominant error: connection refused; all failures in
  region \"core\"" — the correlation, class, and region are correct.
