# iter-0038 — Multi-window multi-burn-rate alerts (Google SRE canon)

## 1. Summary

Second iteration of the reliability package (spec `specs/func-burn-rate-windows.md`). The single
window+threshold burn alerts (D-0079) were replaced with a set of **rules** `{long_window, short_window,
threshold, severity}`: a rule fires when the burn-rate ≥ the threshold **in both windows** — the long
window cuts out noise, the short one confirms it is "burning right now". Severity: 🔥 page / ⚠️ ticket.
Defaults (SRE canon): page 14.4× (1h ∧ 5m), ticket 6× (6h ∧ 30m). Implementation started from the
approved SPA artifact (the rule-editor mockup) — per the "mockup before code" rule.

## 2. What was done

- **Migration 00044**: `sla_targets.burn_rules jsonb`; legacy targets are ported into a single
  page rule (short = long — a degenerate pair, behavior unchanged); the old columns
  `burn_window_seconds/burn_threshold/burn_firing` are removed.
- **domain**: `BurnRule` (+`Key()` for carrying latches over), `DefaultBurnRules()`,
  `ValidateBurnRules` (≤4; severity page|ticket; threshold>0; 1m ≤ short < long ≤ 7d);
  `SLATarget.BurnRules` + `AnyBurnFiring()`; `SLOBurnAlert` carries the severity + short
  window, `Message()` — "🔥 [page] … 14.4× over 1h ∧ 5m" / "✅ [ticket] … back to normal".
- **store**: `UpsertMonitorSLATarget(…, rules)` — enabling with nil rules keeps the
  existing ones (or seeds the defaults), an explicit set replaces them; **firing latches survive
  an edit** if the rule's configuration did not change (matched by Key), and are reset when it
  changes. `EvaluateBurnAlerts` — a loop over the rules, a **pair** of maintenance-excluded
  counts per rule (short==long → one), edge/latch per rule, an outbox event with the
  severity, jsonb updated with a single UPDATE per target.
- **api**: `PUT /sla-target` accepts `burn_rules` (nil = keep/seed, [] = off),
  domain validation → 400; the windows summary (`GET /sla`) returns `burn_rules` + `burn_firing`
  = any-rule. openapi: the `BurnRule` schema + updated SLATarget/SetSLATarget/WindowSLA;
  schema.d.ts regenerated.
- **SPA** (per the mockup): the checkbox is replaced with an editor — an expanded row under the SLO
  table: a table of rules (severity select, threshold ×, long/short from a fixed set 5m…24h,
  firing/quiet state badge), "+ Add rule" (cap 4), "Reset to SRE defaults"; a badge on the
  collapsed row: 🔥 page firing → ⚠️ ticket firing → gray 🔥 enabled.

## 3. Verification

- store `TestBurnRulesMultiWindow`: long firing/short not → does **not** alert (AND semantics);
  both → one alert with the severity/windows in the payload; the latch survives an unchanged edit and
  is reset on a threshold change; nil rules seed the defaults. `TestEvaluateBurnAlerts`
  (rewritten to a 1h∧10m rule): fire→latch→recovery as before.
- api: validation (long ≤ short → 400); domain units; `-race` 30 packages.
- frontend: `vue-tsc` + `vite build` clean.
- **E2E** (live binary, dev DB): migration 44 applied; PUT of a pair of rules → 200 and an exact
  round-trip; an invalid pair → 400 "long window must be longer…"; GET /sla → 2 rules.

## 4. Decisions

D-0098. Out of scope (recorded in the spec): routing severity into escalations, burn rules on
project-level SLA. Next iteration — iter-0039 (confirm phase), starting with the mockup.
