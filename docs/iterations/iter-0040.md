# iter-0040 — Monitor dependency graph + cascading-alert suppression

## 1. Summary

Final iteration of the reliability package (spec `specs/func-monitor-dependencies.md`; earlier:
0037 incident-context, 0038 burn-windows, 0039 confirm phase). A monitor declares
parents (`depends_on`, M2M, same project); while any (transitive) parent is down,
the child's alert **delivery** is muted — the data (heartbeats/status/incidents/SLA) is written
honestly. The "parent/child" role is not a property of the monitor but the direction of the edge:
the root of the cascade is computed at the moment of each event (`DownAncestors`). Implementation
started from the approved SPA mockup. **E2E: a parent + 2 children → exactly one alert.**

## 2. What was done

- **Migration 00046**: `monitor_dependencies (monitor_id, depends_on_id)` PK pair,
  CHECK against a self-edge, FK CASCADE in both directions, an index on the parent.
- **domain**: `Monitor.DependsOn []string`; the "⏸ Suppressed:" marker (idempotency
  of the timeline note); `IncidentContext.RootCause` is now populated.
- **store** (`dependencies.go`): `ReplaceMonitorDependencies` — a transactional
  replace-set with validation (same-project/self → `ErrDependencyForeign`; a cycle, including
  a transitive one, — a recursive CTE with depth-cap 10 → `ErrDependencyCycle`);
  `DownAncestors` — an upward CTE, ancestors with status=down **or** an open auto-incident;
  `AppendSuppressionNote` — one system note per incident (marker prefix);
  `depends_on` is returned via a correlated aggregate in `monitorColumns` (all monitor
  selects get it for free). `IncidentContext` pulls in the root cause.
- **outbox**: `dependencySuppressed` — **fail-open** (a lookup error does not mute a real
  alert); a down transition and a **firing** burn alert of a child with a down ancestor →
  delivered no-op + an `alert_suppressed_by_dependency` log line + a note in the timeline. **Recovery is
  never suppressed**; instance-silence and escalation flat-down suppression — as they were.
- **escalation**: `AdvanceEscalations` skips incidents of monitors with a down ancestor
  (NOT EXISTS + a recursive CTE) — the ladder freezes and resumes after the ancestor's
  recovery, if the child is still down.
- **api**: `depends_on` in create (graph errors roll back the monitor creation) and update
  (validation before the fields are written); typed 400s ("would create a cycle" /
  "must be other monitors of the same project"). openapi + regen schema.d.ts.
- **SPA** (per the mockup): a "Depends on" multiselect in the form (chips with status dots,
  candidates with a client-side transitive cycle check — disabled + tooltip);
  a "⏸ suppressed by <root>" badge in the monitor list (a transitive walk over the loaded
  list); a **Dependencies** block in the details (depends on / required by with statuses and
  the "← suppressing this monitor's alerts" annotation).

## 3. Verification

- store `TestMonitorDependencies`: round-trip, foreign/self/cycle (direct+transitive),
  DownAncestors (status and an open auto-incident; the root has no ancestors), the idempotent
  ⏸ note, the cascade on parent deletion.
- outbox `TestDependencySuppression`: down suppressed + note, recovery delivered,
  burn firing suppressed / recovery delivered, a healthy graph alerts, a lookup error —
  fail-open.
- `-race` 30 packages; vue-tsc + vite build.
- **E2E** (live binary, dev DB): migration 46; a parent←childa/childb graph via the API;
  a cycle via PATCH → 400; children up → parent down (one alert) → children down →
  2× `alert_suppressed_by_dependency` in the log, ⏸ notes in both child incidents,
  the child's RCA context got "likely root cause: dep-parent".
