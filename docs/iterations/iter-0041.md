# iter-0041 — Multi-region quorum via composite (variant B)

## 1. Summary

Closing the last item of the reliability plan — geo-quorum, deliberately deferred until
discussion. **Variant B** was chosen (spec `specs/func-multi-region-quorum.md`): instead of
a full per-monitor multi-region (variant A — rejected: a hypertable migration breaking the
unique key `(monitor_id, ts)`, a rethink of SLA semantics, XL), the quorum is assembled
from existing primitives — N single-region monitors + a **composite with a new
`quorum` mode**. The heartbeats/SLA model is not touched at all; per-region SLA comes for free (the
child's SLI = the view from its region). Implementation started from the approved SPA mockup.

## 2. What was done

- **domain**: `CompositeMode()` understands `quorum`; `CompositeQuorum()` (safe
  parsing of `config.quorum`); `Validate()` — mode ∈ {all, any, quorum}, for quorum
  1 ≤ M ≤ len(children).
- **prober/composite.go**: the quorum branch — the composite is **DOWN only with ≥ M non-up children**
  (the original wording "2 out of 3 confirmed the failure"); a pending/deleted child =
  a down vote (consistent with the all mode); the msg carries a tally: `"2/3 children down (quorum 2)"`.
- **SPA** (per the mockup):
  - the composite section: an All/Any/**Quorum** mode segment + a "Down when ≥ M of N
    members report down" field (edit mode picks mode/quorum up from config);
  - the **"Multi-region set" wizard** (pure frontend sugar, the backend only knows the mode):
    a toggle in the active-monitor form → region chips (dead ones disabled, the existing
    liveness picker), M defaulting to "majority" (⌈(N+1)/2⌉), the creation plan shown in
    the form; on submit: N children `name @ region` (region=selected, `auto_incident=false`,
    no channels) + a composite `name` (mode=quorum, channels/escalation live on it);
    **rollback of the already-created ones on a mid-way error**;
  - a `quorum M/N` badge on the composite in the monitor list.
- No migrations; the backend surface is only domain+prober.

## 3. Verification

- domain `TestCompositeQuorumValidation` (valid 1..N; 0/N+1/empty/non-number/foreign
  mode → rejected); prober `TestCompositeQuorum` (1/3 down < M=2 → up; 2/3 → down with the tally;
  M=1 ≙ all; M=N — down only when all are down, missing = a down vote).
- `-race` 30 packages; vue-tsc + vite build.
- **E2E** (live binary): 3 tcp children (2 alive, 1 dead) + a composite with quorum=2 →
  phase 1: 1/3 down → composite **up**; an invalid M=5 → 400 with a clear message;
  phase 2: kill the second one → composite **down**, heartbeat msg `2/3 children down (quorum 2)`.

## 4. Decisions

D-0101. Limitations: grouping the set in the list is by the `@ region` naming convention (no
UI tree in v1); the wizard is only for newly created active monitors with a target.
**The reliability plan is fully closed** (0037–0041); variant A remains rejected with
recorded revisit triggers (see D-0101).
