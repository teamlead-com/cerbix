# iter-0042 — Members moves into Settings, "Administration" group

## 1. Summary

Information-architecture consolidation (spec `specs/func-settings-members.md`), the first
of two iterations around user management. The org-scoped Members screen leaves the sidebar
("Manage" was a one-item section) and becomes a Settings tab in the **Organization**
group; the global-admin-only tab group formerly labeled "Instance" is renamed
**Administration** and will host the Users page (iter-0043). Frontend-only — the members
API is untouched. Implementation started from the approved SPA mockup.

## 2. What was done

- **`components/settings/MembersPanel.vue`** — the whole `MembersView` content (invite by
  email with org/project scope, searchable member table with role editing and removal,
  the role-permission reference matrix, the audit log) extracted into a self-loading panel
  (own `load()` on mount + reload on `ws.orgId` change). One behavior fix along the way:
  an action error (failed role change/removal) no longer hides the member table — the
  original view chained `v-else` off the error banner.
- **`views/SettingsView.vue`**: new `members` tab (`scope: "org"`, first in the group);
  `scopeLabels.instance` → `"Administration"` (the scope *key* stays `instance` — pure
  display change); group order is now Project → Organization → Administration → Account;
  the active tab initializes from `?tab=<key>` when the key names a tab visible to the
  current user (deep links).
- **Routing/nav**: `/members` route replaced with a redirect to `/settings?tab=members`
  (old bookmarks keep working); the "Manage" section removed from `AppShell.vue`;
  `views/MembersView.vue` deleted.

## 3. Verification

- `npm run build` (vue-tsc + vite) — green.
- **E2E on a live stack** (`--profile single`, Playwright): sidebar has no "Manage"
  section; `/members` lands on `/settings?tab=members`; the nav shows
  Project/Organization/Administration/Account with Members first under Organization and
  no "Instance" label; adding `testuser@example.com` as editor shows the member row with
  a role select and an audit entry; the org switcher reloads the tab.

## 4. Notes

The "Add to org" quick action planned for the Users page (iter-0043) grants org-scoped
memberships only, so its role picker will offer `org_admin/editor/viewer` —
`project_admin` is valid only for project-scoped grants and stays in the Members invite
flow (Scope = project).
