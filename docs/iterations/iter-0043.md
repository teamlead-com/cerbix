# iter-0043 — Instance-wide Users administration

## 1. Summary

The second half of the user-management pair (spec `specs/func-admin-users.md`, mockup
shared with iter-0042). Users were only visible through org member lists, so OIDC
JIT-provisioned accounts with no membership could authenticate yet appeared nowhere. The
new Settings → Administration → **Users** page gives the Global Admin the full instance
picture and management: grant/revoke the global-admin flag, add a user to an organization,
delete a user.

## 2. What was done

- **Migration `00047_admin_users.sql`** — `audit_logs.org_id` becomes nullable: global
  actions have no organization. `RecordAudit` maps an empty OrgID to NULL (same pattern
  as the NULL actor). No other schema work — every FK to `users` already cascades
  (memberships, sessions, TOTP, reset tokens) and the audit actor is `SET NULL`.
- **Store** (`users_admin.go`): `ListAllUsers(q)` — user-keyed rows (one row per user,
  memberships aggregated with org/project names, empty list for org-less users),
  `auth_type` derived from `password_hash`/`oidc_sub` (`local|oidc|both|none`),
  `last_active` from sessions as in `ListOrgMembers`, case-insensitive substring search;
  `DeleteUser` (cascade via FKs); `CountGlobalAdmins`.
- **Domain**: `AdminUser` + `AdminUserMembership` (user-keyed DTO, unlike the
  membership-keyed `Member`).
- **API** (`handlers_users.go`, behind `requireGlobalAdmin`):
  - `GET /api/v1/admin/users?q=` — the list;
  - `PATCH /api/v1/admin/users/{userID}` `{is_global_admin}` — self-change rejected
    (400), demoting the last global admin rejected (400); audited as
    `user.global_admin` with a NULL org;
  - `DELETE /api/v1/admin/users/{userID}` — self-deletion and deleting the last global
    admin rejected (400); audited as `user.delete`. Deleting the sole org_admin of some
    org is allowed by design — the global admin appoints a replacement.
  - "Add to org" reuses the existing `POST /organizations/{orgID}/members` with
    `user_id` (already supported by the handler; more precise than the LIMIT-1 email
    lookup when a local and an OIDC account share an address).
- **OpenAPI**: paths + `AdminUser`/`AdminUserMembership`/`UpdateAdminUser` schemas,
  `schema.d.ts` regenerated. Store interface growth propagated to the api fakeStore.
- **SPA** (`components/settings/UsersPanel.vue`, tab `users` first in Administration):
  search, auth-type pills, membership chips (`Org · role (Project)`), a red
  **"⚠ no organization"** badge for org-less users, last active, global-admin pill;
  row actions Grant/Revoke admin, Add to org, Delete-with-confirm; the self row is
  locked with tooltips. The add-to-org form renders as a panel above the table (a
  row-anchored popover was clipped by the table's overflow container — caught on the
  E2E screenshot); the role picker offers the org-scope set only (`viewer/editor/
  org_admin`) — `project_admin` is granted from Members with a project scope.

  `audit_logs` shows the three actions with `org_id = NULL`.
