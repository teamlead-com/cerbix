# iter-0044 — Docs & config example accuracy

## 1. Summary

First (easiest) slice of the audit-gap package (`specs/func-audit-gaps.md`): the audit
found the config docs promising keys that do not exist and omitting ones that do. The
config itself is clean — all 41 leaf fields have live consumers — so this iteration only
touches documentation. Dangerous because the loader is strict (`KnownFields`): copying
`docs/overview.md` examples produced hard startup failures.

## 2. What was done

- `deploy/config.example.yaml`: added the one missing key —
  `local.login_rate_limit_per_minute: 10` (enforced at login and password-reset; the
  file claims to list "every section and key").
- `docs/overview.md` config table: `oidc.admin_emails` (nonexistent — would fail decode)
  → `bootstrap_admin_emails`, plus `post_logout_redirect_url`; `admin_email/password`
  moved from the `local` row to `security` where they actually live; `rabbitmq` row
  gains `management_url`; a `pull` row added (regions/token/agents/server_url).
- `docs/overview.md` CLI: the role list gains `agent`; the worker example command gains
  the missing `serve` subcommand (`cerbix --role …` exits 2).

## 3. Verification

A throwaway test parsed `deploy/config.example.yaml` through the strict `config.Load` —
passes. Every key mentioned in the overview table now matches a `yaml:"…"` tag in
`internal/config/config.go`.
