# iter-0045 — Expired-row purge + dead interface surface

## 1. Summary

Second slice of the audit-gap package. `DeleteExpiredSessions` and `DeleteExpiredAuthFlows`
existed and were integration-tested but nothing ever called them — the `sessions` and
`auth_flows` tables grew without bound on any long-lived instance. Separately,
`ListMembershipsByOrg` sat on the api Store interface with zero callers (`listMembers`
uses the enriched `ListOrgMembers`), forcing every Store implementation to carry a method
nothing invokes.

## 2. What was done

- **`internal/scheduler/scheduler.go`**: the hourly leader maintenance tick
  (`maintainPartitions`) now finishes with auth housekeeping — `DeleteExpiredSessions` +
  `DeleteExpiredAuthFlows`, warn-on-error, info log with the purged count (same pattern
  as the pull-job and agent-heartbeat purges). Store interface += both methods.
- **`internal/api/api.go`**: `ListMembershipsByOrg` removed from the Store interface
  (the store implementation stays — it is exercised by integration tests and harmless);
  the api fakeStore stub deleted.

## 3. Verification

`TestSchedulerLeaderMaintainsPartitions` extended: the leader must invoke the session and
auth-flow purges alongside partition/retention on becoming leader (counter-based fake).
`go vet` + `-race` for scheduler/api green; store-level purge behavior already covered by
`store_integration_test.go` (expiry-only deletion).
