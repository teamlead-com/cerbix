# iter-0047 — SPA display gaps

## 1. Summary

Fourth slice of the audit-gap package (mockup approved as an artifact): data the backend
already served but no screen rendered. Implemented per the mock.

## 2. What was done

- **Monitor detail** (`MonitorDetailView.vue`): the target line and the Configuration
  card show the real HTTP `method` (was hardcoded "GET"); new rows — failure threshold,
  confirm interval, re-notify cadence (when set), grace period for push monitors,
  escalation policy (name resolved from the project's policies, linked to Escalation),
  and `updated_at`.
- **Incident detail** (`IncidentDetailView.vue`): "acknowledged **by <name>**" (new
  backend enrichment `acknowledged_by_name` on the detail endpoint — display name or
  email, best-effort), a `monitor →` link to the source monitor, and the
  `external_key` chip for Alertmanager-correlated incidents.
- **Settings tables**: "Created by" column for API tokens and webhooks —
  `created_by_email` resolved in the list handlers via a small shared
  `resolveUserEmails` helper (distinct-id lookups; lists are small).
- **AppShell**: a "Live updates reconnecting…" chip in the header when the SSE stream
  drops (`live.connected` was tracked and never rendered; new `live.started` flag keeps
  the chip off pages that never subscribed), and a skeleton in the org switcher during
  the initial workspace load (`ws.loading` was dead state).
- OpenAPI: `Incident.acknowledged_by_name`, `ApiToken/Webhook.created_by_email`;
  schema.d.ts regenerated.

## 3. Verification

`-race` api+domain green; vue-tsc build green. Live E2E: monitor config card shows the
new rows; tokens table shows `admin@cerbix.local` in Created by after issuing a token;
acknowledging a live incident renders "by Administrator" plus the monitor link
(screenshots taken); enrichment verified at the API level too.
