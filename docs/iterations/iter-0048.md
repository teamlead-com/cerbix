# iter-0048 — Branding logo

## 1. Summary

Fifth slice of the audit-gap package (mockup approved): `branding.logo_url` was doubly
dead — publicly served by `/api/v1/public/branding` yet with no form input and no
consumer anywhere in the SPA.

## 2. What was done

- Branding form (Settings → Administration → Branding) gains the **Logo URL** input
  (state/hydration/submit already carried the field).
- The logo renders in three places with the current accent-glyph as fallback when empty:
  the sidebar brand block (`AppShell`), the sign-in card (`LoginView`) and the public
  status-page header (`PublicStatusView`). `object-contain`, fixed square box — no layout
  shift for non-square images.
- Bonus fix caught on the way: the sign-in card showed a hardcoded "cerbix" — now it
  uses `branding.productName` like the rest of the app.

## 3. Verification

vue-tsc build green. Live E2E: saved a data-URI SVG via the branding API → the image
renders on the login page, in the sidebar, and on `/status/limonad-status`; cleared the
URL → glyph fallback everywhere; dev branding restored.
