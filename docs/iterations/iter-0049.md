# iter-0049 — Push monitor onboarding

## 1. Summary

Sixth slice of the audit-gap package (mockup approved), the top-severity finding: push
monitors ("dead-man's switch") were unusable from the SPA — the backend generated and
served `push_token`, but no screen showed the token or the heartbeat URL, so a created
push monitor sat pending and went down forever unless the user dug the token out of the
API by hand.

## 2. What was done

`MonitorDetailView` gains a **Push endpoint** panel (only for `type=push`, above the
Configuration card): the full heartbeat URL (`{origin}/api/v1/public/push/{token}`)
with a Copy button and "Copied ✓" feedback, a ready-to-paste cron example, and a plain
explanation of the up/down rule (`interval + grace`) plus a token-is-a-secret note.

## 3. Verification

vue-tsc build green. Live E2E: created a push monitor via the API, POSTed one heartbeat
to the public URL (200 → monitor Operational), opened the detail page — panel, URL,
grace note (60s + 120s) and the Copy feedback all render; test monitor removed.
