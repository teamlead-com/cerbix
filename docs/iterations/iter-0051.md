# iter-0051 — Webhook & notification-channel enable toggle

## 1. Summary

Eighth slice of the audit-gap package (mockup approved): the "Status: enabled" column in
both tables was decoration — no PATCH route existed, so a noisy webhook or channel could
only be deleted (losing its signing secret / config). Delivery paths already filtered on
`enabled` (`ListEnabledWebhooksForProject`, `ListEnabledChannels*`); only the management
surface was missing.

## 2. What was done

- **Store**: `SetWebhookEnabled`, `SetNotificationChannelEnabled` (ErrNotFound on
  unknown id).
- **API**: `PATCH /api/v1/webhooks/{webhookID}` (org-manage, audited as
  `webhook.toggle`) and `PATCH /api/v1/notification-channels/{channelID}` (project
  write) with body `{enabled: bool}`; 400 on a missing field, the usual 404-then-403
  resource guards; responses never expose the webhook secret. OpenAPI `ToggleEnabled`
  schema + both paths; schema.d.ts regenerated; api fakeStore extended.
- **SPA**: the Status cells become switches (green/off, tooltips) for users with manage
  rights — read-only text otherwise; failure reloads the list and shows the error.

## 3. Verification

`TestWebhookToggle`/`TestChannelToggle` (403 viewer, 400 missing field, 200 + state
change, 404 unknown); `-race` api+store green; vue-tsc green. Live E2E: created a
webhook → PATCH false → true → deleted; state round-trips.
