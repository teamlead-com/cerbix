# iter-0052 — Status pages: working preview + component fields

## 1. Summary

Ninth slice of the audit-gap package (mockup approved). Two defects: (a) "View public
page" 404'd for `internal` pages (the creation default!) and for `unlisted` ones — the
token was printed next to the link but never appended, and the authed render endpoint
built for exactly this was never called by the SPA; (b) the public page grouped
components by `group` while the component form could not set `group`, `description` or
`position` (curl-only), and `description` was missing even from the render DTO.

## 2. What was done

- **Preview**: the editor link now carries `?token=` for unlisted pages and
  `?preview=<pageID>` for internal ones; `PublicStatusView` falls back to the authed
  `GET /status-pages/{pageID}/render` when the public fetch 404s and the preview id is
  present, showing a "🔒 Internal page — members only" banner. Anonymous visitors keep
  getting 404 — nothing leaks.
- **Component form** gains Group (with a datalist of groups already used on the page),
  Description and Position; the create body sends them (the API accepted all three all
  along).
- **Render DTO** (`componentView`) gains `description`; the public page shows it muted
  next to the component name; OpenAPI + schema.d.ts updated.

## 3. Verification

vue-tsc + api tests green. Live E2E: component created with group/description/position →
public page renders the "Core services" group heading and the description; page switched
to internal → public view hides it, `?preview=` renders it with the banner; switched
back, test component removed.
