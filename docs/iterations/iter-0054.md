# iter-0054 — Status-page subscribers view

## 1. Summary

Final slice of the audit-gap package (mockup approved): subscribers were stored and
received incident emails, but a page owner could not see them at all — no list endpoint,
no UI, not even a count. Confirmation problems (SMTP deliverability) were invisible.

## 2. What was done

- **Store**: `ListSubscribersByPage` (newest first, confirmed and pending alike),
  `DeleteSubscriber(pageID, id)` — the page id in the WHERE guards against cross-page
  deletion by id.
- **API**: `GET /api/v1/status-pages/{pageID}/subscribers` and
  `DELETE .../subscribers/{subscriberID}` behind the existing `statusPageAccess`
  (org admin); removal audited as `subscriber.remove`. The confirm token never leaves
  the server (`json:"-"`). OpenAPI `Subscriber` schema + both paths; fake extended.
- **SPA**: a Subscribers card in the status-page editor under Components (org admin
  only): count + confirmed count, per-row confirmed / "pending confirm" pill (with a
  deliverability tooltip), subscribe date, Remove with inline confirm.

## 3. Verification

Full `-race` suite green (30 packages); vue-tsc green. Live E2E: the dev page's two
real subscribers render with "pending confirm" pills and the "2 · 0 confirmed" counter;
list endpoint verified at the API level too.
