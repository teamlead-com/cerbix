# iter-0058 — Escalation progress on the incident

## 1. Summary

Fourth slice of package 2 (mockup approved): the escalation engine wrote
`escalation_step`/`last_escalated_at` on incidents and no API response carried them —
an on-call responder deciding whether to acknowledge could not see how far the alarm
had already walked the policy.

## 2. What was done

- `domain.Incident` gains `escalation_step` (omitempty) and `last_escalated_at`;
  `incidentColumns` + `scanIncident` read both (all incident SELECT/RETURNING sites go
  through the shared const). OpenAPI schema + schema.d.ts updated.
- `IncidentDetailView` header shows a "⛑ escalated to step N · <rel time>" pill —
  only while the incident is unacknowledged, unresolved and the step is > 0 (after
  acknowledge the "acknowledged by" line already tells the story).

## 3. Verification

`-race` store+api green; vue-tsc green. Live E2E: staged `escalation_step=2` on an open
incident → the API returns both fields and the pill renders "escalated to step 2 ·
<time>"; staging reverted.
