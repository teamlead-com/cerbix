# iter-0060 — Editable escalation & on-call, safe deletes

## 1. Summary

Sixth slice of package 2 (mockup approved): `PUT /escalation-policies/{id}` and
`PUT /oncall-schedules/{id}` existed and were documented with zero UI — the only way to
"edit" was a one-click, unconfirmed delete with silent data loss (a policy delete
detaches every monitor via `ON DELETE SET NULL`; a schedule delete cascades all
vacation-cover overrides).

## 2. What was done — `EscalationView`, frontend-only

- **Edit**: an Edit button on each policy/schedule card loads it into the existing
  composer ("Edit policy: <name>" + editing badge); submit switches POST → PUT;
  Cancel resets to create mode. Deleting the entity being edited also resets.
- **Safe deletes**: both Delete buttons open an inline confirm that states the
  consequence — "N monitor(s) use this policy — they will silently fall back to flat
  notifications" (count from the project's monitors, now loaded alongside) /
  "N override(s) will be deleted with it".

## 3. Verification

vue-tsc green. Live E2E: created a policy → Edit → renamed → Save changes (PUT)
persisted → Delete → confirm block with the consequence note → confirmed → gone;
seeded channel cleaned up.
