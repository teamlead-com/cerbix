# iter-0061 — TOTP policy honesty for SSO

## 1. Summary

Final slice of package 2 (mockup approved). `require_totp` is enforced on local login
only — the OIDC callback issues sessions without a TOTP gate. **Decision: keep it that
way** — SSO users authenticate at the identity provider, which owns their MFA — but the
narrowing was stated nowhere, and a user locked out by a newly enabled policy got a flat
error with no way forward (`totp_setup_required` had no SPA handler).

## 2. What was done

- `domain.AuthPolicy` doc comment states the local-only scope explicitly (with the
  decision reference), so the narrowing is contract, not accident.
- Settings → Authentication hint expanded: "Applies to local sign-ins only … SSO users
  are unaffected — multi-factor for them is enforced by your identity provider."
- `LoginView` handles `totp_setup_required`: the dead end becomes guidance — sign in
  via SSO and enroll under Settings → Security, or ask an admin to relax the policy.

## 3. Verification

vue-tsc + vet green. Live E2E: set `require_totp: all` → the local login API returns the
`totp_setup_required` discriminator and the login page renders the new guidance message;
policy restored.
