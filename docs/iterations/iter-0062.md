# iter-0062 — Full E2E suite

## 1. Summary

The session-long practice of ad-hoc Playwright scripts becomes a committed, repeatable
suite: `e2e/` — Playwright Test in the official docker image (no local node), run
against a live stack. 23 tests across 8 specs cover every functional area.

## 2. What was done

- **Structure**: `e2e/playwright.config.ts` (workers=1 — one shared instance;
  `CERBIX_URL` env, traces/screenshots on failure), `tests/helpers.ts` (API
  arrange/cleanup via the page's cookie-sharing request context; Go's `null` empty
  lists normalized), `run.sh` (docker runner).
- **Sessions**: a `setup` project signs in once and stores `storageState`; every spec
  reuses it. This is load-bearing: local logins are rate-limited
  (`login_rate_limit_per_minute`), so per-test logins flake the whole run — and a spec
  must never `POST /auth/logout` on the shared session (the suite's first bug).
  `auth.spec`/`oidc.spec` opt into empty state for real login-flow testing.
- **Coverage**: auth (bad password, local login, version footer, logout, 401 on
  anonymous API); monitors (CRUD + full config card, pause/delete, push endpoint panel
  + live public heartbeat, instance-defaults prefill, explicit-zero pointer semantics);
  incidents (open → acknowledge with resolved actor → resolve; no escalation pill on a
  fresh incident); escalation (channel → policy create → edit via PUT → confirmed
  delete); settings (branding round-trip rendered to an anonymous login page, global
  silence expiry, live min password length, API tokens with issuer column, webhook
  pause/resume, agent tokens issue/revoke); users administration (invite/role/remove
  with the membership-only note, grant/revoke admin, add-to-orgs expansion, self-guards
  400); status pages (grouped component with description, internal preview + banner,
  authed feed, public 404, subscribe → pending subscriber → removal); OIDC (full
  authorization-code round-trip through Keycloak, skipped cleanly without the sso
  profile).
- Tests self-clean (`e2e-` prefix, idempotent re-runs); docs: CLAUDE.md commands
  section.

## 3. Verification

Two consecutive full runs: 23/23 green in ~12s (the first run also exercised the OIDC
spec against the sso profile). Failures during stabilization were all suite bugs
(rate-limited logins, a shared-session logout, strict-mode locators on leftovers) —
each is now structurally prevented.
