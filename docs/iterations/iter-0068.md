# iter-0068/0069 — Operational logging expansion (one report)

## 1. Summary

Spec `func-observability-logging`: the log was failures plus scheduler housekeeping —
no access log, no actors, no transitions, no delivery confirmations. Both iterations
landed together.

## 2. What was done

- **HTTP access log** (`internal/logging/access.go`, wired around the app mux in cli):
  `http_request` with method, path, status, bytes, `dur_ms`, remote IP. `/api/*` and
  `/auth/*` at INFO; the SPA/static catch-all at DEBUG (visible with `log.level:
  debug`); the SSE stream skipped (hours-long requests would only log disconnects).
  The wrapper preserves `http.Flusher` for streaming handlers.
- **Error hygiene**: `serverError` downgrades `context.Canceled` to DEBUG
  `request_canceled` — a user closing a page mid-load is not a server failure.
- **Lifecycle events with actors** (`h.logEvent` stamps the principal): monitor
  created/updated/deleted, incident opened/acknowledged/update-posted, settings saved
  (per group), API token issued/revoked, agent token issued, webhook toggled, member
  added, admin user actions (global-admin change, delete).
- **Engine narrative**: `monitor_status_changed` (prev→cur, suppressed) at the ingest
  transition point; `outbox_delivered` (topic, attempt) on successful delivery.

## 3. Verification

Middleware unit test (INFO fields for API paths, DEBUG for static, SSE skipped);
`-race` suite green; full E2E 34/34; live check on the stack — one request produced
the access line, and create→flip→delete produced monitor_created (with user_id),
monitor_status_changed, monitor_deleted and outbox_delivered.
