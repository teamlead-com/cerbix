# iter-0071 — AMQP connection supervisor

## 1. Summary

Closing slice of `func-transport-resilience`, the serious half: a runtime RabbitMQ loss
killed every AMQP consumer permanently — the delivery channel closed, the consume loop
returned, the process stayed "healthy" while probing stopped until a container restart;
the scheduler meanwhile logged a publish error per due monitor per tick.

## 2. What was done

- **Supervisor** (`internal/dispatch/amqp.go`): a goroutine watches
  `conn.NotifyClose`; on loss (distinguished from our own `Close()` via ctx) it logs
  exactly one `broker_lost`, redials with exponential backoff (1s → 30s cap, sparse
  `broker_reconnecting` — first attempt then every fifth), and on success swaps the
  connection + publish channel under locks, resets the queue-declare cache, closes the
  `reconnectedCh` signal and logs one `broker_reconnected`.
- **Resilient consumers**: `consume` and the test-RPC server become
  session-loop wrappers (`consumeOnce`/`serveTestsOnce`) — when a delivery channel
  dies they wait on the reconnect signal and resubscribe (re-declaring their queues
  against the new connection). The forwarding Go channels never close: workers ride
  the outage out with no restarts.
- **Publish safety**: the publish channel is swapped under the existing `pubMu`;
  `RunTest` takes the connection via the `current()` accessor (RWMutex).
- **Scheduler**: publish failures aggregate into one `jobs_publish_failed count=N`
  WARN, throttled to one line per 10s (a 1s tick would still have produced a line per
  second during an outage).

## 3. Verification

- `TestAMQPSupervisorRecovers` (opt-in, live broker): round-trip → sever the
  connection → round-trip again; asserts exactly one broker_lost / broker_reconnected
  pair.
- **Live on the distributed compose profile** (single runs inproc — AMQP unused
  there): monitor probing over AMQP baseline `up` → `docker stop rabbitmq` → one
  `broker_lost` per role, sparse reconnecting, publish warns exactly every 10s →
  `docker start rabbitmq` → one `broker_reconnected` per role and a fresh heartbeat
  within seconds, **zero container restarts**.
- Full `-race` suite (incl. both AMQP integration tests) and E2E 34/34 green.
