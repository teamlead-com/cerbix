# iter-0072 — notify SMTP timeout

## 1. Summary

First slice of `func-hardening`. Audit P0: email notification channels sent through
raw stdlib `smtp.SendMail` (no dial timeout, no session deadline, no context), inside
the single outbox worker goroutine. One blackholed `smtp_host` blocked that goroutine
on the OS TCP timeout (~130s) per event and froze the entire alert pipeline —
webhooks, Slack, Telegram, escalations, SLA reports — while the process stayed healthy.
The timeout-bounded sender already existed one package over (`mailer.sendMailTimeout`),
just not reused here.

## 2. What was done

- `internal/mailer`: exported `SendMailTimeout` (thin wrapper over the existing
  `sendMailTimeout` — dial 10s, session deadline 30s, implicit-TLS-on-465).
- `internal/notify`: `sendMailFunc` now defaults to `mailer.SendMailTimeout` instead of
  `smtp.SendMail`. Everything else (auth, recipients, message build) unchanged; the var
  seam keeps existing tests capturing without a live server.

## 3. Verification

`go build ./...`, `internal/notify` + `internal/mailer` tests green. A dead SMTP host
now fails a channel delivery within ≤30s (and only that channel's delivery) instead of
stalling the worker indefinitely.
