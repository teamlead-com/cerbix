# iter-0074 — Backfill FK race + status ErrNotFound

## 1. Summary

Third `func-hardening` slice: the deleted-monitor race fixed in `InsertHeartbeat`
(D-0126) had two uncovered siblings. (a) `InsertHeartbeatsBulk` (the pull agent's
backfill path) runs a pgx batch — one implicit transaction — so a single FK 23503 for a
monitor deleted while the agent buffered aborts every insert and wedges the whole
backfill on every retry, losing the buffer's SLA data forever. (b) `RecordCheckStatus`
returning `ErrNotFound` for the same race logged at ERROR.

## 2. What was done

- `store.InsertHeartbeatsBulk`: pre-filters heartbeats by the live monitor set
  (`SELECT id FROM monitors WHERE id = ANY(...)`) and skips the rest, so a deleted
  monitor no longer aborts the batch. Self-healing — the next retry excludes the
  confirmed deletion. Read loop bounded by the actually-queued count.
- `ingest`: `RecordCheckStatus` → `ErrNotFound` now logs one INFO
  `status_for_deleted_monitor` instead of ERROR (matches the insert-path treatment).

## 3. Verification

New `TestInsertHeartbeatsBulkSkipsDeletedMonitor` (batch mixing a live and a deleted
monitor → live lands, batch not aborted); existing deleted-monitor and bulk-idempotent
tests still green; `-race` store + ingest green.
