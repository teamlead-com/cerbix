# iter-0075 — Agent region-scope bypass + channel-secret redaction

## 1. Summary

Fourth `func-hardening` slice — two boundary leaks the deep audit surfaced, both letting
data cross a trust boundary the architecture says is strict.

- **Region affinity bypass (HIGH).** Region affinity is "strict by design" — a monitor
  belongs to one region and only that region's prober may report for it. But the pull
  transport didn't enforce it on the write path: `/agent/results` and `/agent/backfill`
  accepted a *region-less* post, `agentAuthorized`/`agentDBAuthorized` authorized it with
  ANY configured per-region token (or any live DB token), and `enforceRegionScope`
  short-circuited to `true` when the region was empty. So a token minted for `geo1` could
  post heartbeats for any monitor in `geo2`/`core` — forged up/down facts, forged
  incidents. `/agent/test-results` had no region check at all: a valid agent could
  overwrite another region's pending test result by guessing its id.
- **Channel-secret exposure (HIGH).** `listChannels` (gated `ActionProjectRead`, i.e.
  viewer+) and `listMonitorChannels` returned each channel's `config` map verbatim —
  including the decrypted Telegram `bot_token`, SMTP `smtp_password`, and secret-bearing
  Slack/webhook `url`. Any viewer could read another team's delivery credentials.

## 2. What was done

### Region scope

- `agentAuthorized`/`agentDBAuthorized`: dropped the region-less acceptance path. A
  per-region config token or a DB token now authorizes *only* a request carrying its own
  region; the instance-wide catch-all token (`pull.token`) may still reach a handler
  region-less, but every handler then requires a region.
- `enforceRegionScope`: an empty region is now a `400`, not a silent pass. `/results` and
  `/backfill` therefore require a region and verify every heartbeat's monitor is in it.
- `agentTestResult`: requires `?region=` and passes it to the store.
- `store.SavePullTestResult(id, region, result)`: the `UPDATE` is now scoped
  `WHERE id = $1 AND region = $2`, so a region's token can never populate another region's
  test row even with a correct id (a mismatch updates zero rows → the waiting
  `/monitors/test` poll times out, exactly as for an unknown id).
- `internal/agent`: the agent already sent `?region=` on results/backfill; it now sends it
  on `/test-results` too.

### Channel secrets

- `domain.SecretChannelConfigKeys` (`url`, `bot_token`, `smtp_password`) +
  `NotificationChannel.Redacted()` (returns a copy with those values blanked, original
  untouched).
- `listChannels`, `listMonitorChannels`, and the `createChannel` response now go through
  redaction. There is no config-edit endpoint (channels are create + enable-toggle +
  delete), so blanking the values round-trips nothing — the create/edit UI re-collects a
  secret when one is (re)entered.

## 3. Verification

- `TestAgentPerRegionTokenScope`: a per-region token posts results for its own region
  (200) but not another region (401), and a region-less post is rejected (401) — the old
  bypass is closed.
- `TestAgentTestEndpoints`: a cross-region test-result post (right id, wrong region) does
  not populate the test; a region-less post is 400; the own-region post stores it.
- `TestAgentResults`/`TestAgentBackfill`: region-scoped happy path + region-less rejection.
- `TestPullTestLifecycle` (store): a wrong-region `SavePullTestResult` leaves the result
  unset; the own-region save populates it.
- `TestNotificationChannelSecretsRedacted`: viewer list and create responses blank
  `bot_token`/`url` while keeping non-secret `chat_id`; no secret substring leaks.
- Full `-race` suite green (hypertable mode); `go build`/`go vet` clean. Agent endpoints
  are agent-token routes, absent from `openapi.yaml`, so no schema regen. No
  heartbeats/retention storage-mode branch touched → no dual-DB run required.
