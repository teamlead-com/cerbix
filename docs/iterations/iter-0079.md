# iter-0079 — Pool sizing, SLA-report deadlock, per-cadence timeouts

## 1. Summary

Eighth `func-hardening` slice — three leader-loop / pool robustness gaps.

- **Pool starvation.** `pgxpool.New(dsn)` used the pgx default `MaxConns` of
  `max(4, numCPU)`, but the process pins several connections for its whole lifetime: the
  scheduler's leadership advisory lock and the confirm/pull LISTEN notifiers. On a 2-CPU
  host that is 3 of 4 connections gone, leaving one for all query traffic.
- **SLA-report self-deadlock.** `EnqueueDueSLAReports` opened a transaction (holding one
  connection) and then computed each due project's SLIs via `s.ProjectSLI`, which uses
  `s.pool` — a SECOND acquire while already holding one. Once the pool has no spare
  connection the nested acquire blocks forever, and the leader's report cadence wedges.
- **Unbounded cadence calls.** Every periodic leader task ran on the process-lifetime
  context. A single hung query (lock wait, slow aggregate) stalled the whole leader tick —
  no dispatch, no other cadence — until the query returned.

## 2. What was done

- `store.Open`: `ParseConfig` + `NewWithConfig` with a floor — `MaxConns ≥ 12`,
  `MinConns ≥ 2`, `MaxConnLifetime 1h`, `MaxConnIdleTime 30m`, `HealthCheckPeriod 1m`. A
  larger operator-set `pool_max_conns` in the DSN is still honored; the floor only lifts a
  too-small value.
- `store`: `projectSLI(ctx, q sliQuerier, …)` computes SLIs on any querier (pool or tx);
  `ProjectSLI` delegates with `s.pool`, and `EnqueueDueSLAReports` now passes its `tx` — no
  nested acquire, no self-deadlock.
- `scheduler.lead`: each sub-cadence (rollup, partition/purge maintain, snapshot refresh,
  stale-push, renotify, burn, SLA reports, region-worker, pull-stats, escalation) runs via
  a `withTimeout` helper under a bounded child context — `subCadenceTimeout` 30s, and
  `maintainTimeout` 2m for the heavier partition/`drop_chunks`/purge sweep.

## 3. Verification

- `store.TestEnqueueDueSLAReportsNoSelfDeadlock` (new): drives `EnqueueDueSLAReports`
  against a MAX-1-connection pool. **Confirmed it deadlocks (30s) on the pre-fix code and
  passes (0.2s) on the fix** — a genuine regression guard.
- Existing `TestEnqueueDueSLAReports`, SLA/SLI, leadership, renotify, and the full
  scheduler suite still green (`-race`).
- Full `-race` suite green; `go build`/`vet` clean; image rebuilt; E2E 34/34.
- **Live**: the single stack holds 5 backend connections (leader lock + 2 notifiers + min
