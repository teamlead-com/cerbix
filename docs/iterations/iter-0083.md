# iter-0083 — Consilium-driven security & reliability hardening

## 1. Summary

A dedicated audit pass (run as Claude+Gemini *consilium* sessions) surfaced a prioritized
set of P0/P1 security, correctness, reliability and supply-chain findings beyond the
`func-hardening` epic (which closed at iter-0082). Every accepted finding was fixed,
each as its own `-race`-and-E2E-verified commit. Thirteen commits, grouped below by the
audit blocks. Where the consilium's first instinct was wrong, the calibrated decision is
recorded (see D-0141 and "Notes").

## 2. What was fixed

**Audit pre-work (consilium diagnostics)**

1. **Login user-enumeration timing oracle (CWE-203)** — `LocalLoginHandler` returned
   immediately on an unknown username but ran a full Argon2id verify on a known one, so
   response time distinguished the two. A `verifyPasswordFn` seam now runs a decoy verify
   (`a.decoyHash`, generated in `New()`) on the not-found path, equalizing timing.
2. **`defer rows.Close()` in `InsertHeartbeatsBulk`** — idiomatic cleanup on the bulk
   insert path (pgx auto-release still held, but the explicit defer removes the footgun).
3. **Go toolchain → 1.25.12 (GO-2026-5856)** — govulncheck confirmed the crypto/tls ECH
   leak reached mailer/websocket/HTTP probers; the fixed 1.25 line is 1.25.12. Bumped
   `go.mod` + `Dockerfile` + `.ci` (which was on EOL 1.24). Residual: local
   `GOTOOLCHAIN=local` builds on 1.26.x remain the operator's responsibility — the
   already-present govulncheck CI job (`.github/workflows/security.yml`) is the gate.

**A/B — secret exposure**

4. **PATCH channel redaction + push-token from viewers** — `updateChannel` returned the
   channel un-redacted (`ch.Redacted()` now applied, matching create/list); and a monitor's
   `push_token` was visible to read-only viewers. `getMonitor`/`listMonitors` now strip it
   via `WithoutPushToken()` unless the principal has `ActionProjectWrite` (`principalCan`).

**C — SSRF egress**

5. **Webhook/notify/SMTP delivery through the SSRF guard** — outbound delivery used bare
   HTTP/SMTP dialers, so a user-controlled webhook/OIDC/SMTP host could reach internal
   addresses. `prober.Guard` now exposes `HTTPClient()` (IP-pinning dialer, `Proxy=nil`,
   redirect cap) and `EgressDialContext()`; `cli.go` wires them into `webhook`, `notify`,
   and the mailer (TLS ServerName preserved). CGNAT `100.64/10` is blocked too.

**D — search tenant scope**

6. **Search scoped in SQL before ranking/LIMIT** — global search ranked the top-N across
   ALL tenants and only then filtered, so a permitted row sorting after N foreign matches
   was crowded out. `Search` now takes a `SearchScope` and scopes with `= ANY($orgIDs)` /
   `ANY($projectIDs)` *inside* the query; `authz.VisibleScope` computes it; the handler
   short-circuits an empty scope.

**Outbox**

7. **Claim-token CAS** — a stale outbox worker could regress a row already delivered by
   another. `ClaimDueOutbox` now stamps a `claim_token` (migration 00050) and
   `MarkOutboxDelivered`/`FailOutbox` CAS on it, so a stale worker's write is a no-op.

**#5 — auth fail-closed**

8. **OIDC allowlist / email_verified + TOTP fail-closed + full key-rotation coverage** —
   the OIDC callback now, when an email allowlist is enforced, requires a non-empty,
   verified, permitted email (was a bypass); a mandatory-TOTP login refuses (500) rather
   than issuing an MFA-less session when the user record can't be loaded; the OIDC client
   is 15s-bounded; and `ReencryptSecrets` gained the two columns it had missed — monitor
   config secrets and `users.totp_secret` — so a key rotation no longer orphans them.

**#6 — architecture (the reliability spine)**

9. **AMQP publisher channel-level recovery** — the publish channel was replaced only on a
   full redial, so a channel-level exception (the connection staying up) wedged the
   publisher behind a healthy `broker_up=1`. `onPubChannel` now reopens the channel on the
   live connection and retries once.
10. **Single-transaction result recording + dedup/freshness** — the ingest hot path did
    `InsertHeartbeat` then `RecordCheckStatus` in two transactions, so a duplicate
    re-delivery re-bumped the failure counter and a crash between them could apply a status
    change with no heartbeat. `RecordResult` now does insert + status flip + transition
    event in ONE tx, gated by the probe timestamp against `monitors.last_result_ts`
    (migration 00051): a duplicate is deduped, a stale/out-of-order probe is kept for SLA
    but does not override newer live state. Incident reconciliation stays a separate
    concern (as in D-0138).
11. **Pull-job lease + ack** — pull-served regions claimed jobs with DELETE-on-claim
    (at-most-once): a crash or a lost claim response silently dropped a probe cycle. Claims
    are now leased (`claim_token` + `lease_expires_at`, migration 00052); the agent acks by
    echoing the tokens on its results POST (`AckPullJobs`); an un-acked lease lapses and the
    job re-delivers. Safe now that #10 dedups. The scheduler also stops advancing a pull
    monitor's cadence on a failed enqueue.

**Follow-ups / infra (#8)**

12. **Body caps + poison dead-letter + reproducible SPA build + dependabot paths** —
    `MaxBytesReader` on the public (64 KiB) and agent (16 MiB) routers; unparseable
    job/result messages now go to a durable `checks.dead` queue instead of Nack-dropping
    (results keep NO time-TTL — a slow ingest must never drop real results); `Dockerfile`
    uses `npm ci` + the copied lockfile; dependabot's `gomod`/`docker` streams repointed
    from the stale `/backend` to `/` (the module moved to root, so they were silent no-ops).
13. **Push-token encrypt-at-rest + blind index** — the last plaintext secret column.
    `monitors.push_token` becomes `push_token_hash` (SHA-256 blind index, UNIQUE, for O(1)
    ping lookup) + `push_token_enc` (encrypted via the keyring, plaintext dropped),
    migration 00053. `ReencryptSecrets` covers it (upgrades the migration's seeded plaintext
    to ciphertext + rotation). No API/UI change — authorized reads still decrypt and reveal.

## 4. Notes / deferred

- **Consilium calibration** (recorded so the reasoning survives): `rand.Read` after seeding
  is not a security defect; the heartbeat fix needed a real single transaction, not just
  idempotency; SMTP needed its own egress model (TLS ServerName ≠ pinned IP);
  PushToken split hotfix (viewer hiding) → full (encrypt-at-rest); GO-2026-5856 is not
  absolute for locally-toolchained builds.
- **Deferred:** AMQP result-queue *time-TTL / broker-native DLX* — intentionally NOT added
  (results must not be dropped by time, and mutating an existing durable queue's args
  breaks redeclare); poison forwarding covers the real loss path instead. Push-token
  **rotate/revoke** UI — the encrypt-at-rest model preserves reveal, so a rotate action is a
  future convenience, not a gap.
