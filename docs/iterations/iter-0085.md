# iter-0085 — Result-protocol implementation + hardening backlog (P0a→P0b→P1→P2) + push-watermark fix

## 1. Summary

Implements the whole backlog that iter-0084 §5 deferred — the P0a/P0b result-ingest
correctness spine (contract in `func-result-protocol.md`, D-0142), P1 reliability, and the
P2 hardening list — then closes a follow-on review's **push-watermark blocker** discovered
after P0b. Each item shipped as its own `gofmt`/`go vet`/`-race`-verified commit; schema
commits verified in **both** storage modes (timescale + throwaway `postgres:16-alpine`);
image rebuilt and **E2E 34/34** green. Two decision records: **D-0143** (backlog delivery,
incl. the follow-on P2 #14/#12/#2) and **D-0144** (push liveness watermark & re-arm).

## 2. What was implemented

**P0a — result timestamp hygiene + typed origins** (`func-result-protocol` §2/§4)

1. Foundation (inert): `heartbeats.observed_at` (migration 00054), the strict `result:`
   config block (`allowed_skew`, `revision_mode`), and low-cardinality `result_*` outcome
   metrics — added ahead of behavior so P0a is the expand phase (`06a31a5`).
2. `RecordScheduledResult` — the ordered pipeline: missing-ts→reject, `FOR UPDATE` lock +
   `statement_timestamp()` clock, timestamp bounds BEFORE insert (future→quarantine,
   outside-retention→ignore), INSERT ON CONFLICT, duplicate→dedup, watermark compare
   (out-of-order→SLA-only | fresh→apply) (`21fda59`).
3. Dedicated push entrypoint `RecordPushResult` via `PushResultRecorder` (NOT the shared
   `ResultSink`) + a shared post-commit `ingest.Reconciler` (SSE + auto-incident) reused by
   every origin (`33a1eda`).
4. `RecordHistoricalResults` — SLA-only bounded backfill (per-row timestamp bounds,
   idempotent, never touches live state or revision) (`cbb0d47`).

**P0b — execution_revision config-generation gate** (§3)

5. Activated the gate: `monitors.execution_revision` (migration 00055), bumped only by
   `UpdateMonitor`, evaluated under the row lock BEFORE the heartbeat insert; missing→reject
   in `enforce` / tolerated+counted in `observe`, present-mismatch→reject always (`3339ded`).
6. `RecordDeadmanResult` — the scheduler leader's typed entrypoint: atomic staleness
   re-check under the lock, DOWN through the same `recordCheckStatusTx`, periodic
   down-sampling (edge-only → periodic, D-0142) (`1458bc3`).

**P1 — reliability**

7. Readiness-gated push-token encrypt-at-rest backfill — no plaintext bearer token is served
   during the upgrade window (`990964b`).
8. Pull ACK/lease correctness — malformed jobs are not acked (they re-deliver), claim batch
   is bounded (`a49ab72`).

**P2 — hardening list** (audit findings #1/#3/#4/#5/#7/#8/#9/#10/#11/#13)

9. Monitor resource caps in `Monitor.Validate` (interval/timeout/retries/grace/synthetic
   steps upper bounds — #3) (`24acbdf`).
10. Strict env-expand (`expandEnvStrict`, undefined `${VAR}` fails Load — #11), `TruncateAll`
    refuses non-`test` DBs (#8), migrate advisory lock serialises racing migrators (#10)
    (`ed652d0`).
11. Fail-closed crypto RNG (secret generation errors out, never silently weak — #13) +
    public-DTO redaction (`IncidentUpdate`/`Postmortem` `PublicRedacted()` strip
    author/ids — #9) (`d7be189`).
12. Atomic password reset (`ResetPasswordWithToken` — consume+set in one tx, #7), TOTP
    lockout fixes, subscriber unsubscribe link preserved (#6) (`77a0424`).
13. Delivered-outbox purge (`PurgeDeliveredOutbox` — #4), outbox CAS returns an `applied`
    signal (#1), dependency-graph advisory lock closes the concurrent-edit cycle race (#5)
    (`af5ea59`).

**Follow-on P2 (config/migration-bearing, #14/#12/#2)** — see D-0143

14. `#14` rate-limit `server.trusted_proxy_cidrs`: honors XFF only when the direct peer is in
    a trusted network, then walks the chain skipping trusted proxies (supersedes the hop-count
    model when set) (`1d26b68`).
15. `#12` OIDC identity keyed by `(issuer, subject)` (migration 00056, partial unique index):
    `UpsertUserByOIDCIdentity` threads the ID-token `iss`, with a one-time legacy-issuer claim;
    closes cross-IdP account takeover (`eae7869`).
16. `#2` outbox `state_sequence` (migration 00057): a monotonic per-monitor counter bumped on
    each applied transition, carried in the transition event, checked at delivery so a stale
    DOWN/reminder superseded by a newer transition is dropped (`45492db`). Realizes the item
    D-0142 §9 deferred.

**Follow-on review — push-watermark blocker** — see D-0144

17. Preserve push liveness on edit; re-arm the dead-man on re-enable via `push_armed_at`
    (migration 00058) (`2a3dc99`). An ordinary edit (even a rename) of a live push monitor no
    longer fires a false synthetic DOWN.
18. Dropped stale "gate INERT in P0a" code comments (the gate is live since P0b) (`c0e1951`).

## 4. Notes

- **Clears iter-0084 §5.** All four deferred blocks (P0a/P0b/P1/P2) are shipped; the review's
  P2 list is complete including the three config/migration-bearing follow-ons (#14/#12/#2).

  prober stamping, and a concurrent `UpdateMonitor`-vs-result test; the shared
  transaction-scoped config-update helper for atomic bundle apply (a monitoring-as-code
  concern, not this iteration).
