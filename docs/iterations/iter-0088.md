# iter-0088 — Monitoring as Code: ownership & persistence (FR-017/NFR-014, phase 2a)

## 1. Summary

The ownership spine of the persistence phase (spec §20.2): the provenance schema, a
schema-enforced tenant-safe ownership model, the typed write-path split, and API
`409 managed_by_file` enforcement — all atomic at the store boundary, not just in a
handler. The full atomic bundle-apply transaction is carried into iter-0089 to keep this a
reviewable, independently-verified change (AGENTS: prefer small PR-like changes).

## 3. Mandatory role outputs

### Agent A — Implementation

- **Migration 00059 `file_provider_bundles`**: one row per resolved (provider, org, project)
  bundle — relative source path, canonical content hash (LKG), monotonic generation, status
  (`pending|applied|rejected|error|degraded`), bounded error; composite FK
  `(project_id, org_id) → projects(id, org_id)` proves project∈org.
- **Migration 00060 `managed_monitors`**: `monitor_id` PRIMARY KEY (⇒ ≤1 provider per
  monitor), unique `(provider, org, project, source_uid)`, `orphaned_at`; composite FKs
  `(monitor_id, project_id) → monitors` and `(project_id, org_id) → projects` schema-prove
  `monitor.project_id == provenance project` (spec §13). Adds the `monitors_id_project_key`
  unique the first FK targets (guarded, idempotent).
- **`internal/store/managed.go`**: `ErrManagedByFile`, `FileManagement` (provider/uid/relative
  path/orphaned), `MonitorProvenance` + `MonitorProvenanceBatch` (list metadata, no N+1),
  and `assertNotFileManagedTx` — the ownership check runs under the monitor's row lock so a
  concurrent file apply serializes behind it (atomic, not handler-only; spec §8/§9.2).
- **`internal/store/monitors.go`**: extracted `updateMonitorTx` (the shared D-0142 config-write
  helper — bumps `execution_revision`, applies watermark/push-rearm), reused by the user path
  and (iter-0089) the file-apply path. `UpdateMonitor`/`DeleteMonitor` now run in a tx: lock
  the row, `assertNotFileManagedTx`, then write. Ownership blocks regardless of orphan state
  (no automatic release, §10).
- **`internal/api`**: `MonitorProvenance` added to the `Store` interface; `rejectIfManaged`
  maps `ErrManagedByFile` → `409` with `{error, management:{source,provider,uid,path,read_only}}`.

### Agent B — Tests

- `store.TestFileManagedOwnershipGuard` (real PG): unmanaged CRUD works and has no
  provenance; after a `managed_monitors` row exists, `UpdateMonitor` and `DeleteMonitor`
  both return `ErrManagedByFile` atomically; `MonitorProvenance` returns the tenant-safe
  fields; the monitor stays in its project (composite FK). Green on **both** storage modes
  (timescale + `postgres:16-alpine`); migrations 00059/00060 apply on both.
- `api.TestFileManagedMonitorReadOnly` (hermetic): PATCH and DELETE of a file-managed monitor
  → `409 managed_by_file` with the provenance body; the same monitor when unmanaged → `200`.
