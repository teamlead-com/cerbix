# iter-0089 — Monitoring as Code: atomic bundle apply (FR-017/NFR-014, phase 2b)

## 1. Summary

The functional heart of the persistence phase (spec §9): `ApplyFileManagedBundle` reconciles
one desired project bundle into PostgreSQL in a single transaction, with the D-0142
revision-safe write contract, per-project fault isolation, orphan-grace/restore semantics,
and the scheduler `monitor_config_changed` NOTIFY. Watching/HA (iter-0090) and ops/UI
(iter-0091) still to come; the provider is not yet wired into a role.

While implementing, a genuine spec tension surfaced between §7 (dependency UIDs in the
canonical hash) and §9.2/D-0142 (dependency-only change must not bump `execution_revision`).
Resolved and recorded as **D-0146** (canonical monitor hash excludes dependencies; deps are
a separate comparison axis). No spec weakening.

## 3. Mandatory role outputs

### Agent A — Implementation

- `internal/store/fileapply.go`: `ApplyFileManagedBundle(providerID, desired, sourcePath,
  orphanGrace)`:
  - resolves the tenant in one org-constrained query (`ErrBundleTenantNotFound` otherwise);
  - takes the project dependency-graph advisory lock (same key as the API path);
  - `readManagedSet` builds `[]fileprovider.CurrentMonitor` (+ id/orphan/enabled lookups)
    from `managed_monitors ⋈ monitors ⋈ monitor_dependencies` mapped back to source UIDs;
  - `fileprovider.Plan(desired, current)` → deterministic actions;
  - Phase 1 applies monitors + provenance: `create` (server-minted push token, provenance
    row), `update`/`restore` (shared `updateMonitorTx` → revision bump, clear `orphaned_at`),
    `dependency_update`/`noop` (provenance-only: advance generation / refresh path, NO
    monitor write), `orphan` (first absence sets `orphaned_at`);
  - grace-elapsed disable: an already-orphaned, still-enabled, still-absent UID past its
    window is disabled through the config-write path (never a hard delete);
  - Phase 2 reasserts dependency edges for created/restored/dep-changed monitors, UID→id
    resolved from Phase 1;
  - upserts `file_provider_bundles` (monotonic generation, content hash, `applied` status);
  - emits `monitor_config_changed` NOTIFY only when execution config changed (§12), bounded
    payload;
  - one commit — no partial monitor/dependency/ownership state.
  - Extracted `insertMonitorTx`/`getMonitorTx`; `generatePushTokenStore` (fail-closed).
- `internal/fileprovider/canonical.go`: dependency UIDs removed from the semantic hash
  (D-0146); the planner already compares dependency sets separately.

### Agent B — Tests

- `store.TestApplyFileManagedBundle` (real PG, **both** storage modes): create (2 monitors +
  dep edge + server push token) → **canonical no-op** (no revision bump, `updated_at`
  unchanged, generation advances, `Changed=false`) → **semantic update** (interval change →
  revision bump) → **dependency-only update** (edge dropped → NO revision bump) → **orphan**
  (first absence marks, still enabled) → **grace(0) disable** on the next scan (enabled=false,
  rows still present — no hard delete) → **restore** (same DB ids + same push token,
  re-enabled). Tenant-not-found rejects with no mutation.

## 4. Decisions

- **D-0146** — canonical monitor hash excludes dependency edges; no-op iff config-hash AND
  dependency-set both unchanged; `dependency_update` never bumps `execution_revision`.
