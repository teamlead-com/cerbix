# iter-0090 — Monitoring as Code: filesystem scan & bundle grouping (FR-017, phase 3a)

## 1. Summary

The bounded filesystem contract of the hot-reload phase (spec §11, §9.1): a non-recursive,
resource-bounded directory scanner and the snapshot grouping that enforces one-file-per-
project and the unbound-error orphan-suspension rule. Pure/hermetic (temp dirs, no DB, no
process wiring). The live reconcile loop, per-provider advisory-lock leadership, and
`--role api`/`all` wiring are the remaining part of phase 3 (continues in iter-0090b/0091).

## 3. Mandatory role outputs

### Agent A — Implementation

- `ScanDirectory(dir, limits)`: sorts entries deterministically; accepts only regular
  immediate children ending `.yaml`/`.yml`; skips dotfiles, subdirectories, sockets/devices/
  FIFOs (non-recursive); resolves symlinks and rejects any whose canonical target escapes the
  provider root; enforces `max_files`, `max_file_bytes`, `max_total_bytes` with bounded
  per-file diagnostics (never partial-accepts an over-limit file); a directory-unreadable
  error is returned at the top level (caller keeps last-known-good and marks degraded — not a
  desired deletion, §11).
- `GroupBundles(cands, scope)`: decodes each candidate under the provider scope and groups by
  resolved tenant; a project declared by more than one file is dropped from `Valid` and both
  candidates get a `duplicate_project` error (freeze, §6); a file that cannot be bound to a
  tenant sets `SuspendOrphan` (unbound_error, §9.1) while independently valid bundles still
  group for a non-destructive apply. Returns tenant-safe relative provenance paths.
