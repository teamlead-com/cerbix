# iter-0091 — Monitoring as Code: reconcile loop, HA leadership & role wiring (FR-017, phase 3b)

## 1. Summary

Completes the hot-reload/HA phase: the live per-provider reconciler — leader-elected, poll-
watched, resync-safe — wired into `--role api`/`all`. It ties the pure scan/group contract
(iter-0090) to the atomic apply (iter-0089) so file changes are reconciled without a restart
or reload signal. Metrics, the diagnostics API, the provenance UI, and the no-restart
real-binary E2E remain for iter-0092.

## 3. Mandatory role outputs

### Agent A — Implementation

- New package `internal/fileprovider/runtime` (imports the pure `fileprovider` + `store`; no
  import cycle since `store` imports only the pure package):
  - `Provider.Run`: contends for a per-provider PostgreSQL session advisory lock via the
    store's `TryBecomeLeader`; a follower stays ready and retries; the leader runs the loop
    and steps down on lock loss/ctx cancel. `leaderKeyFor(name)` namespaces the key
    (`0x…1000 | fnv32(name)`), distinct from the scheduler (`…0001`) and migrate (`…0002`)
    keys (§12).
  - `leaderLoop`: initial reconcile, then reconcile on a debounced directory change (a single
    dirty bit, not an unbounded queue — §17), on the mandatory periodic resync (lost/coalesced
    events must not stall progress — §11), and steps down when the same-session `check` reports
    the lock lost. `fingerprint` (name+size+mtime, no content read) detects changes and treats
    a vanished directory as a change handled by `reconcile` (keep LKG, never orphan).
  - `reconcile`: `ScanDirectory` → `GroupBundles` → `ApplyFileManagedBundle` per valid bundle
    (per-project fault isolation), then whole-project-disappearance orphan (apply an empty
    desired for an owned project absent from the snapshot) UNLESS `SuspendOrphan`; a directory
    read error degrades and keeps the committed runtime.
- `store.FileProviderProjects`: the owned (org, project) slugs a provider currently has a
  bundle for (disappearance detection).
- `cli.startFileProviders`: starts providers for `api`/`all` only (spec §12); fail-fast when a
  provider is configured without a DB or with an unreadable/absent directory (§4.1); each runs
  under the shutdown WaitGroup.

### Agent B — Tests

- `runtime` (hermetic, temp dirs + fake applier): valid bundles applied; whole-project
  disappearance orphaned with an empty desired; an unbound (broken) file suspends orphaning
  while valid siblings still apply; an unreadable directory degrades with no apply/orphan;
  `leaderKeyFor` derives distinct, namespaced, stable keys that never collide with the
  scheduler/migrate keys.
- The advisory-lock mutual-exclusion primitive itself is already covered by
