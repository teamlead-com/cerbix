# iter-0092 — Monitoring as Code: observability, provenance & live no-restart proof (FR-017, phase 4a)

## 1. Summary

The observability + provenance slice of phase 4, plus a real-binary no-restart proof: the
`cerbix_file_provider_*` metrics wired into the reconcile loop, the read-only `management`
provenance block on monitor responses, a spec-conformance fix for `orphan_grace_period: 0`
(immediate disable), the runbook HA/alerting section, and `e2e/mac-smoke.sh` demonstrating a
live `--role all` process reconciling create → orphan-disable → restore WITHOUT restarting.

FR-017/NFR-014 remain IN_PROGRESS: the frontend UI (badges/read-only/source filter), the
tenant-aware provider diagnostics API + OpenAPI `management` schema, and an explicit
two-replica leadership-failover race test are still required before DONE.

## 2. Mandatory role outputs

### Agent A — Implementation

- Metrics (`internal/metrics`): seven `cerbix_file_provider_*` series (leader gauge;
  reconcile_total{outcome} with bounded `applied|noop|rejected|error`; reconcile duration;
  last-success timestamp; managed/orphaned monitor gauges; bundle-errors gauge) — provider
  label only, never file/project/monitor ids. Emitted from `WritePrometheus`; absent entirely
  when no provider is configured.
- Runtime wiring (`internal/fileprovider/runtime`): a nil-safe `MetricsSink`; after each
  reconcile the loop records the outcome, duration, last-success time, and managed/orphaned
  counts (`store.FileProviderCounts`); leader gauge toggled on acquire/release.
- Provenance (`internal/api`): monitor list/detail responses carry a `management` block
  (`source: file|ui`, provider, uid, tenant-safe relative path, read_only) via
  `MonitorProvenanceBatch`, promoted alongside the monitor fields.
- **Spec-conformance fix**: `providers.file.<n>.resync_interval` and `orphan_grace_period`
  became `*Duration` so an ABSENT key (nil → contract default) is distinguishable from an
  EXPLICIT `0`. Per spec §4.1 an explicit `orphan_grace_period: 0` now means immediate disable
  after a valid absence — previously it was silently coerced to the 30s default.

### Agent B — Tests

- `metrics.TestFileProviderMetrics` (all seven series + absent-when-unconfigured);
  `api.TestMonitorManagementProvenance` (file vs ui `management` block, fields still promote);
  `config.TestProviderOrphanGraceZeroIsImmediate` (explicit 0 vs absent default).
- **Real-binary no-restart smoke** (`e2e/mac-smoke.sh`, run against a throwaway
  `cerbix_mac_smoke` DB): `serve --role all` with a file provider; dropping a bundle creates
  monitors live (push token server-generated); editing bumps `execution_revision`; a broken
  file preserves last-known-good; removing the file disables (grace 0) without hard delete;
  restoring reuses the **same DB id and push token**; `cerbix_file_provider_reconcile_total`
  reflects the activity — all while the **same PID stays alive** (no restart). Verified
  interactively; the script is committed for reproducibility.
- `go test -race ./...` — 32 packages green; `go vet`; `git diff --check`. `golangci-lint`
  unavailable (`Error 127`).

### Agent C — Docs + Traceability

- `docs/runbook.md` Monitoring-as-Code section (shared-directory HA invariant, fleet
  stale-success + bundle-errors alerts, degraded-vs-down, smoke pointer). `docs/status.md`
  FR-017 evidence extended; `docs/traceability.md` iter-0092 row; this report.

### Agent D — Observability + Ops

- Delivered the metric contract (§16) and the alerting/HA runbook guidance. The remaining ops
  surface — the tenant-aware diagnostics API (global-admin/org-admin/project-member) — is the
  iter-0093 deliverable alongside the UI.

## 3. Decisions

  §4.1 (not a new ruling): the previous scalar could not distinguish absent from explicit 0.
