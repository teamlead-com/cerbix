## 2. Mandatory role outputs

### Agent A — Implementation
- `store.FileProviderDiagnostics(ctx, orgID)`: bundle status (provider, org/project slugs,
  relative source path, generation, status, bounded error, applied_at); an empty orgID
  returns all (global-admin), a non-empty orgID filters IN SQL to that org (org-admin) — no
  cross-tenant leak.
- `internal/api/handlers_fileproviders.go`: `GET /api/v1/admin/file-providers` (global-admin,
  all) and `GET /api/v1/organizations/{orgID}/file-providers` (`InOrg` + `ActionOrgManage`,
  own-org only). Paths are relative; absolute filesystem paths are never exposed (§14/§15).

### Agent B — Tests
- `api.TestFileProviderDiagnostics`: global-admin sees all bundles; a non-admin is refused;
  an org-admin sees only its own org's bundles and cannot read another org's.
- `runtime.TestProviderLeadershipFailover` (real PG, DB-gated): at most one holder of a
  provider's advisory lock at a time; after the holder releases, a candidate fails over and
  acquires (§12 anti-split-brain, distinct per-provider key).
- `go test -race ./...` — 32 packages green; `go vet`; `git diff --check`. `golangci-lint`
  unavailable (`Error 127`).
