## 2. Accepted findings (from the review)

- **P0 — invalid/duplicate/scan-error could orphan live state (§9.1 violation).** A
  duplicate-target project was dropped from `Valid` but did NOT freeze, and a scan-level
  rejection did not suspend orphaning — so the reconcile loop saw the project as absent and
  applied an empty desired, disabling live monitors. Confirmed and fixed.
- **P0 — leadership does not fence the in-flight apply (§17).** The advisory lock is on a
  dedicated connection while `ApplyFileManagedBundle` uses a pool connection; a lock loss
  mid-apply is not fenced. Accepted; NOT yet fixed (see remaining).
- **P0 — bounded-work gaps.** `max_monitors_per_bundle` was unenforced (now fixed);
  `max_managed_monitors`, an apply-tx deadline, a global reconcile-concurrency cap, and an
  explicit YAML depth/tag policy remain. A TOCTOU let a file grow between stat and read past
  the byte limit (now fixed by re-checking actual bytes).
- **P1 — transactional audit missing (§9 step 10).** The apply tx writes no audit rows. Accepted.
- **P1 — diagnostics thinner than claimed (§15).** `status`/`last_error`/`attempted_at` are
  never persisted on rejection; invalid bundles don't appear as invalid; no leadership/last-scan/
  counts/configured-but-empty providers; `last_success` advances on scans that only had
  rejections; no error rate-limit. Accepted.
- **Evidence mismatch.** `e2e/mac-smoke.sh` proves only create → remove → orphan-disable →
  process-alive (NOT update/LKG/restore/id+token/scheduler-exec as iter-0094 stated); the
  update/LKG/restore checks were done interactively but are not in the committed script. Doc drift
  (traceability planned/IN_PROGRESS rows, spec "spec-before-code" header, iter-0094 "no
  undocumented deviation") accepted.
- **Fair pushback (agreed):** the v1 type set (D-0145) and dep-hash split (D-0146) are proper
  decisions, not defects; 9 of 16 types are supported (7 absent, incl. the credentialed ones);
  polling is a legitimate architecture choice (now recorded, D-0147); a diagnostics UI page is
  backlog, not a spec violation; `golangci-lint` NOT RUN is an unmet repo DoD, not a product defect.

## 3. What was fixed here (Agent A/B)

- **Orphan safety (§9.1).** `GroupBundles` now marks a duplicate-target project `Frozen`
  (per-project, kept out of orphaning) WITHOUT setting the provider-wide `SuspendOrphan`; the
  reconcile loop skips `Frozen` keys and, additionally, suspends orphaning provider-wide when
  ANY scan-level rejection exists (`len(scanErrs) > 0`) — an unbindable rejection can never
  read as deletion. Tests: `fileprovider.TestGroupBundlesDuplicateFreezesNotSuspend`,
  `runtime.TestReconcileDuplicateDoesNotOrphan`, `runtime.TestReconcileScanErrorSuspendsOrphan`.
- **TOCTOU byte re-check** in `ScanDirectory` (actual bytes vs stat size).
- **`max_monitors_per_bundle` enforced** in the reconcile loop (whole-bundle reject + freeze).
- **D-0147** records the poll-based watcher decision.
