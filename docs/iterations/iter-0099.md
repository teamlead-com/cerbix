## 2. Changes (Agent A/B)

1. **`max_managed_monitors`, provider-wide serialized.** `applyBundleTx` takes the provider
   quota advisory xact lock `pg_advisory_xact_lock(hashtext('file_provider_quota'), provider)`
   BEFORE counting, so two concurrent applies can't both read free quota (iter-0096 §3). It
   counts the provider's owned monitors + the plan's creates; if that exceeds
   `max_managed_monitors` the WHOLE bundle is rejected (`max_managed_monitors`) and its LKG is
   kept. Threaded through `ApplyFileManagedBundle` (pool + LeaderSession) and the runtime.
   Test: `store.TestApplyBundleMaxManagedMonitors` (real PG).
2. **YAML depth/node/custom-tag policy.** `Decode` now walks the parsed node tree first
   (`checkYAMLPolicy`): max depth 32, max 10000 nodes, and a core-schema tag allowlist — a
   custom `!Foo` or non-core `!!binary` rejects. Adds the explicit Cerbix bound on top of
   yaml.v3's alias-expansion protection. Test: `fileprovider.TestDecodeYAMLPolicy`.
3. **Apply-tx deadlines.** `applyBundleTx` issues `SET LOCAL statement_timeout='20s'` and
   `lock_timeout='10s'`, so a stuck statement/lock aborts the apply instead of wedging the
   reconcile loop (§17).
4. **Process-wide reconcile concurrency.** A semaphore shared by all providers
   (`WithReconcileLimiter`, cap `maxConcurrentReconciles=4`, wired in cli) bounds how many
   providers reconcile at once; `reconcile` acquires it and honors ctx. Test:
   `runtime.TestReconcileConcurrencyGate` (full sem → reconcile blocks then respects ctx; freed
   → runs).
