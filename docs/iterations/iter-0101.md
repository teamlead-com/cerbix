# iter-0101 — Monitoring as Code: runtime diagnostics surface (FR-017, IN_PROGRESS)

## 1. Summary

Closes P1 #1 from iter-0100 §4: the RUNTIME half of diagnostics (§15). A process-local status
registry now backs the admin diagnostics API so global admins see, per configured provider,
this process's live view — leadership, last scan, last successful generation, managed/orphaned
counts, and the last rejection reason — **including configured-but-idle providers** that have
never reconciled. The persisted per-bundle status (iter-0100) was the DB half; this is the
runtime half. FR-017/NFR-014 stay IN_PROGRESS; the remaining P1 work is the storm/two-replica/
full-real-binary test matrix (iter-0102).

## 2. Changes (Agent A/B/D)

1. **`runtime.StatusRegistry` (new, `internal/fileprovider/runtime/status.go`).** Process-local,
   thread-safe (`sync.RWMutex`) map of `ProviderStatus`. `register` seeds an entry at
   `Provider.WithStatus` so a configured-but-idle provider is visible **before** its first
   reconcile; `setLeader` mirrors this process's leadership; `update` records the post-reconcile
   outcome and keeps `last_success_unix` **sticky** (a later failed reconcile advances the scan
   time and surfaces the error but does not clear the last known good success). `Snapshot()`
   returns a name-sorted slice (deterministic diagnostics).
2. **Provider wiring (`provider.go`).** New `status *StatusRegistry` field + `WithStatus(reg)`
   (nil-safe; registers scope). `setLeader` updates the registry; `publishMetrics` no longer
   early-returns on a nil metrics sink and updates BOTH the metrics sink and the status registry.
   `ReconcileReport.LastError` is set on every reject path (scan-failed, bundle-error,
   max-monitors, apply-error) and flows into the registry.
3. **API surface (`api.go`, `handlers_fileproviders.go`).** New `FileProviderRuntimeStatus` DTO
   + `FileProviderStatusSource` interface + `Handler.WithFileProviderStatus`. The global-admin
   endpoint now returns `{bundles, providers}` (persisted diagnostics + runtime status); the
   org-admin endpoint returns `{bundles}` (renamed from `providers` for consistency — it never
   carried runtime status). Runtime status is global-admin only (leadership/paths are
   instance-level operational data, not tenant data).
4. **cli wiring (`cli.go`).** `startFileProviders` builds one `StatusRegistry`, wires an
   `fpStatusAdapter` into the api handler (thin bridge — the api package must not import
   runtime), and chains `.WithStatus(reg)` onto every provider. Registry is created even when
   the handler is nil (worker/scheduler never reach here — api/all only).
5. **OpenAPI + TS schema.** `openapi.yaml`: response shapes updated to `{bundles, providers}`
   (admin) and `{bundles}` (org) + new `FileProviderRuntimeStatus` schema; `frontend` TS schema
   regenerated (`npm run gen:api`).
