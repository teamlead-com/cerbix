## 2. Changes (Agent C)

1. **Event-storm bound (`runtime.TestLeaderLoopEventStormBounded`).** Runs the real `leaderLoop`
   with a tight poll (3ms) + 40ms debounce, then rewrites the watched file ~continuously for
   300ms (each write a different size so every poll observes a change). Asserts the reconcile
   count stays a small constant (observed: 281 changes → 2 reconciles), proving the watch is a
   SINGLE dirty bit + debounce (§17 backpressure), not a per-event queue. Hermetic (no DB).
2. **Two live replicas (`runtime.TestTwoLiveReplicasSingleLeaderAndFailover`, DB-gated).** Two
   real `Provider.Run` loops share a provider name + empty directory on real Postgres; the test
   samples both replicas' status registries and asserts (a) never two leaders at once
   (anti-split-brain at the Run level, not just the session layer) and (b) killing the current
   leader's context lets the survivor take over. Complements `TestProviderLeadershipFailover`
   (session-layer) and `store.TestLeaderSessionFencing` (fencing).
3. **Full real-binary lifecycle (`e2e/mac-smoke.sh`).** Extended from create+orphan to the whole
   §18.4 matrix against a live `serve --role all` on a throwaway DB, with the process asserted
   alive throughout: create (http + push monitors) → **scheduler-exec** (a heartbeat is written
   for the file-managed http monitor, proving the inproc scheduler picked it up via the
   `monitor_config_changed` NOTIFY) → **in-place update** (rename → same DB id, generation bump)
   → **last-known-good** (invalid YAML neither disables, mutates, nor bumps the generation) →
   **orphan-disable** (file removed → disabled, never hard-deleted) → **restore** (re-added →
   same DB ids AND same push-token hash preserved across orphan→restore).
