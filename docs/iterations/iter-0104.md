# iter-0104 — Monitoring as Code: P0 orphan-safety + reconcile error accounting (FR-017, IN_PROGRESS)

## 1. Summary

Fixes the external review's P0 and P1#3. Reopened from the premature iter-0103 DONE.

**P0 (§9.1):** valid bundles used to apply — including `ActionOrphan` and grace-disable for a
UID absent from a PRESENT project — BEFORE `suspendOrphan` was computed, so an unbound/scan
error could still disable a live monitor. Trust of absence is now decided **provider-wide,
before any apply**, and threaded into the store as `allowAbsence`. When false, an apply is
strictly non-destructive (create/update/dependency/noop/restore only): it never marks
`orphaned_at` and never grace-disables, so every absent UID keeps its last-known-good.

**P1#3 (§16):** an owned-set lookup failure, an orphan-apply failure, and a counts-lookup
failure used to pass as a clean reconcile (last_success advanced; counts silently zeroed). They
now degrade the reconcile / suppress a false success and never publish misleading zero gauges.

## 2. Changes

1. **`allowAbsence` contract (`internal/store/fileapply.go`).** `ApplyFileManagedBundle` (pool +
   `LeaderSession`) and `applyBundleTx` take `allowAbsence bool`. `case ActionOrphan` is a no-op
   when false; the grace-elapsed disable block is gated on `allowAbsence && orphanGrace >= 0`.
2. **Ordering fix (`internal/fileprovider/runtime/provider.go`).** `reconcileInner` computes
   `suspendOrphan := grp.SuspendOrphan || len(scanErrs) > 0` and `allowAbsence := !suspendOrphan`
   BEFORE the apply loop, and passes `allowAbsence` to each present-project apply (the
   whole-project orphan path passes `true`, since it only runs when absence is trusted).
3. **Error accounting (`provider.go`).** Owned-lookup failure → `rep.Degraded`,
   `LastError="owned_lookup_failed"`. Orphan-apply failure → `rep.Rejected++ + Degraded +
   LastError`. `publishMetrics`: when counts are unknown (degraded scan OR failed lookup) it no
   longer advances last_success and no longer publishes zero gauges; a new
   `StatusRegistry.updateNoCounts` preserves the last-known counts in diagnostics.

## 3. Tests
- `store.TestApplyBundleAbsenceGuard` (real PG): seed A+B; apply `{A}` with `allowAbsence=false`
  twice → B stays enabled AND unmarked (no `orphaned_at`); then a trusted apply marks the first
  absence (still enabled), and the next trusted apply (grace=0) disables it — proving the guard,
  not a missing plan entry, protected B. This is the "UID inside a PRESENT project" case.
- `runtime.TestReconcileAbsenceGuardThreadedToApply` (hermetic): a clean scan applies the
  present project with `allowAbsence=true`; an ambiguous scan (oversized sibling → scan
  rejection) applies the SAME present project with `allowAbsence=false`.

- `go test -race` — `internal/store`, `internal/fileprovider/...`, `internal/api`, `internal/cli`
