# iter-0105 — Monitoring as Code: idempotent apply + restore/dep semantics + fenced attempts (FR-017, IN_PROGRESS)

## 1. Summary

Fixes review P1#4, P1#6, and P1#7. All in the store apply path + reconcile wiring.

- **P1#6 (§7/§17):** a semantic no-op used to rewrite provenance and bump the bundle generation
  on every resync (write amplification), and `reconcile_total{outcome="noop"}` was unreachable
  because every apply incremented `Applied`. Now the apply tracks what actually changed; a
  steady-state no-op writes NOTHING and returns `NoChange`, the generation only advances on a
  real state change, a rename refreshes just the provenance path (no bump), and the reconcile
  loop leaves `Applied` at 0 for a no-op.
- **P1#4 (§10):** `ActionUpdate` and `ActionRestore` were merged, so a restore-within-grace with
  unchanged config bumped `execution_revision` (resetting the scheduler watermark) and audited.
  Restore is now split: a semantic write happens only when the monitor was disabled (must
  re-enable) or its config changed; otherwise it just clears `orphaned_at`.
- **P1#7 (§9/§15/§17):** audit now fires on a dependency-only mutation (graph changed) as well as
  on execution changes; `RecordBundleAttempt` moved onto `LeaderSession` so it runs on the
  leader's fenced connection (a former leader can't overwrite a new leader's applied
  diagnostics); duplicate (tenant-bound/frozen) rejections are now persisted to diagnostics.

## 2. Changes (`internal/store/fileapply.go`, `internal/fileprovider/runtime/provider.go`)

- `ApplyResult.NoChange`; `applyBundleTx` tracks `execChanged` (NOTIFY+audit) / `depChanged`
  (audit only) / `stateChanged` (bump generation + upsert bundle) / `pathChanged` (refresh path
  only). Orphan-mark and no-op path use `RowsAffected` so a repeat writes nothing.
- `ActionRestore` split into re-enable/config-changed (full write, `execChanged`) vs pure
  un-orphan (clear `orphaned_at`, no revision bump). `ActionDependencyUpdate` separated from
  `ActionNoop`.
- Bundle-row write is conditional: upsert+generation on `stateChanged`; path-only refresh on
  `pathChanged`; nothing otherwise. Audit on `execChanged || depChanged`; NOTIFY on `execChanged`.
- `recordBundleAttempt` extracted over a `rowExecer` (pool or conn); `Store.RecordBundleAttempt`
  (pool) + `(*LeaderSession).RecordBundleAttempt` (fenced). Runtime `LeaderSession` interface
  gains `RecordBundleAttempt`; `Applier` loses it; `persistAttempt` takes the session; the
  reconcile loop persists frozen (duplicate) rejections via the session; `Applied` only
  increments when `!NoChange`.
