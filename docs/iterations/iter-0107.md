# iter-0107 — Monitoring as Code: apply-tx deadline + enumeration/parse hardening (FR-017, IN_PROGRESS)

## 1. Summary

Fixes review P1#5 and the enumeration/parse "remaining gaps".

- **P1#5 (§17):** the apply set a per-statement `statement_timeout`/`lock_timeout` but no overall
  bound — a bundle of thousands of statements could still run for minutes. The whole apply
  (Begin → plan → writes → Commit) now runs under a 60s `context.WithTimeout` in both the pool
  and leader-fenced wrappers.
- **Bounded enumeration:** `os.ReadDir` materialized (and sorted) the ENTIRE directory before
  `max_files` applied. Scan + fingerprint now enumerate via batched `os.File.ReadDir` capped at
  `maxDirEntries` (50k); a larger directory is truncated → treated as an ambiguous scan
  (`SuspendOrphan`, keeps last-known-good), and the fingerprint folds truncation state in.
- **Startup readability:** `startFileProviders` only `os.Stat`-ed the directory (which passes for
  a non-enumerable dir). It now also opens it and does a one-entry `ReadDir` — fail-fast (§4.1).
- **EvalSymlinks overlap:** the canonical-root overlap check used `filepath.Clean` only, so two
  dirs symlinking to the same real path were not detected. It now compares `EvalSymlinks`
  results (falling back to `Clean` when the path doesn't exist yet).
- **YAML aliases:** `checkYAMLPolicy` walked `Node.Content` but not `AliasNode.Alias`, so an
  alias bomb expanded only at decode. It now follows aliases and counts the referenced subtree
  against the same node/depth budget on every use → a billion-laughs bundle is rejected up front.

- `internal/cli/cli.go`: startup open+`ReadDir(1)` readability probe.
- `internal/config/providers.go`: `EvalSymlinks` in the overlap check (fallback to `Clean`).

- `internal/api/handlers_fileproviders.go` + `internal/cli/cli.go` + `openapi.yaml` + TS schema:
  the runtime-status DTO now carries `scope_org`/`scope_project` (the registry already tracked
  them; the API DTO had dropped them).
