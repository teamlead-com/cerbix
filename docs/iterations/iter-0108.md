# iter-0108 — Monitoring as Code: real alert rules + browser E2E surface (FR-017, IN_PROGRESS)

## 1. Summary

Closes the remaining review coverage gaps: a **real, promtool-validated Prometheus alert rule
file** (the runbook previously only described alerting) and a **browser E2E spec** for the
file-managed UI surface, plus dev-stack wiring so the spec can run end-to-end.

## 2. Changes

1. **Alert rules (`deploy/alerts/monitoring-as-code.rules.yml`).** Three real rules over the
   documented low-cardinality metrics: `CerbixFileProviderStaleSuccess`
   (`time() - max by(provider)(…last_success_timestamp_seconds) > 90`, 10m),
   `CerbixFileProviderBundleErrors` (`max by(provider)(…bundle_errors) > 0`, 15m),
   `CerbixFileProviderNoLeader` (`max by(provider)(…leader) == 0`, 10m, critical). Validated with
   `promtool check rules` (prom/prometheus image): **SUCCESS, 3 rules found**.
2. **Alert-rule guard test (`internal/metrics/alerts_test.go`).** Parses the shipped rules and
   asserts each alert's expr references a metric this package actually emits (drift guard), has a
   `for:` window, a `severity` label, and a `summary` annotation.
3. **Browser E2E (`e2e/tests/file-providers.spec.ts`).** (a) Global-admin diagnostics endpoint
   returns the `{bundles, providers}` contract (skips on a pre-FR-017 build). (b) When a
   file-managed monitor exists, asserts the monitor-list named-provider filter chip + the
   "Managed by file" badge, and the detail page's hidden edit/delete/pause controls; skips
   cleanly when no file provider is configured.
4. **Dev-stack wiring.** `config.dev.yaml` gains a representative instance-scoped `platform`
   provider; `docker-compose.yml` mounts `deploy/monitoring.d`; `deploy/monitoring.d/` ships a
   README + `example.yaml.example` (the scanner reads `.yaml`/`.yml` only, so the provider is
   idle until an operator renames it) — making the browser spec's full assertions reproducible.
