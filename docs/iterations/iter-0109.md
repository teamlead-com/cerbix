# iter-0109 — Monitoring as Code: second-review P1 refinements (FR-017, IN_PROGRESS)

## 1. Summary

Fixes the six P1 refinements from the second external review. All are correctness/observability
fixes on top of iter-0104…0108; the P0 stays closed.

1. **Restore enabled-semantics (§10).** The restore write decision compared `!enabledByUID` (any
   disabled monitor forced a full write), so a declarative `enabled: false` that reappeared
   unchanged bumped `execution_revision`/reset the watermark/audited. Now it compares ACTUAL vs
   DESIRED enabled: `enabledByUID[uid] != desired.Enabled || hash changed`. A declarative-off
   monitor un-orphans without a write; a desired-on but grace-disabled monitor re-enables (write).
2. **Bundle diagnostics lifecycle (§15).** The bundle row was written only on `stateChanged`/
   `pathChanged`, so a stale `rejected`/`last_error` never cleared, a rename of an empty/
   all-orphaned bundle didn't refresh `source_path` (no monitor entries → no `pathChanged`), and
   the first empty bundle wasn't recorded. The row now lives on an independent axis: it is read
   up front (existence + status + last_error + source_path), the first (even empty) bundle
   records generation 1, a clean no-op clears a stale status/error WITHOUT a generation bump, and
   `source_path` is compared directly. A steady-state clean no-op still writes nothing.
3. **Counts-error outcome (§16).** A `FileProviderCounts` failure suppressed `last_success` but
   still recorded the pre-computed applied/noop outcome and skipped the gauges entirely. Counts
   are now read BEFORE the outcome; a failure makes the outcome `error`, and duration/error
   gauges still publish via the new `SetFileProviderReconcileStats` (preserving the last-known
   managed/orphaned rather than zeroing them).
4. **NoLeader alert reliability (§16).** Followers that never won leadership exported no
   `cerbix_file_provider_leader` series, so `max by(provider)(…) == 0` matched an empty vector
   and the critical alert never fired. `startFileProviders` now registers a zero leader gauge for
   every configured provider before election, so the series always exists.
5. **Invalid known-path diagnostics (§9.1/§13).** Unbound decode/scan errors were log-only. A
   fenced `RecordBundleAttemptByPath` now marks an EXISTING bundle row (matched by provider +
   relative source path) rejected — a known LKG bundle whose YAML no longer decodes — without
   deriving a tenant from broken YAML. A brand-new unknown invalid file matches no row and stays
   process-local (documented).
6. **Audit contract (§9, D-0148).** Audit now fires on ANY persisted state change (`stateChanged`
   — incl. first orphan-mark and un-orphan), not just exec/dep changes. The scheduler NOTIFY
   stays gated on `execChanged` only. Recorded as decision D-0148.
