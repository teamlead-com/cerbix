# iter-0116 — Secret inventory dispatch and acceptance close-out (FR-020/NFR-015)

## 1. Summary

Completed the two remaining delivery slices of
[`func-secret-inventory.md`](../specs/func-secret-inventory.md) after the iter-0115
foundation. Credential references are now accepted by API/UI and Monitoring as Code only
through the domain-owned typed settings gate, persisted with tenant-safe normalized refs,
and dispatched through an authoritative ciphertext-only materializer. Credential jobs and
tests cross a physically versioned v2 barrier and carry a per-region AAD-bound envelope;
workers and pull agents decrypt only at probe time and report bounded diagnostic errors
without mutating liveness.

The final live smoke uses a real DB-less pull agent twice: wrong regional key bytes produce
`decrypt_auth_failed`, zero heartbeats, local readiness 503 and central
`credential_ready=false`; a correctly keyed replacement recovers and executes a real
PostgreSQL probe. FR-020 and NFR-015 are therefore closed as `DONE`.

## 4. Contract evidence

| Contract | Evidence |
| --- | --- |
| Tenant/reference integrity | Every inventory/ref store method predicates project scope; composite FKs and joined equality carry tenant identity; save/apply locks referenced secrets and atomically maintains `monitor_secret_refs`; DB tests cover cross-project resolution, rename/apply and delete guards. |
| Plaintext boundary | AAD inventory ciphertext uses `(project_id,secret_id)`; snapshots and API DTOs omit secret config keys without decrypting; the materializer uses byte APIs and wipes buffers best-effort; persisted v2 pull rows are decoded in tests and contain an envelope but no inline/inventory value; live core/agent logs are scanned for the test value. |
| Linearization/fencing | One authoritative read supplies the whole execution row and secret join. Changes committed before it alter target/region/interval/value/revision; changes after it leave an old job in flight whose result is rejected by execution revision. Disabled monitors neither dispatch nor accept results. |
| Wire barrier | v2 AMQP jobs/tests have distinct queues; pull rows carry `protocol_version` and v1/v2 claim queries are physically separate. Credential dispatch requires a v2 AMQP consumer or at least one live v2 `credential_ready` pull agent. No capable executor is a dispatch rejection, never DOWN. |
| Executor outcome | Missing/wrong/auth-failed/future key paths emit typed `probe_error`; no heartbeat/status/SLA mutation occurs. Stale revision and SLA-only normal results do not clear diagnostics; a live-applied revision-valid UP or DOWN does. Persistent key failures degrade readiness; future protocol versions do not claim the current keyring is broken. |
| Rotation | Inventory rotation bumps referencing execution revisions without MaC generation drift. Re-encryption uses exact-old-ciphertext CAS, a bounded rescan loop and final zero-old-key proof. Dispatch keyrings decrypt primary+previous and have a separate TTL/dead-queue retirement runbook. |
| Egress | Ref-based PostgreSQL defaults to encrypted `require` (not identity verified); MySQL/Redis default to verified TLS with explicit skip/disable only; RabbitMQ management defaults to HTTPS. Existing non-ref behavior is unchanged per the spec. |

## 6. Intentional boundaries (not defects)

- Legacy inline monitor ciphertext remains AAD-less at rest; enforced dispatch still
  re-wraps it. Retrofitting stored legacy rows is the explicit non-goal in §3/D-0155.
- A job materialized before a config/value change cannot be recalled; its result is fenced
  and its retained ciphertext expires through ACK/TTL/dead-queue policy. Immediate
  revocation is performed at the monitored target.
- `security.dispatch.default` may deliberately widen regional trust only with
  `shared_trust_acknowledged: true`, a metric and an informational alert.
- File-provider support remains limited to the prior common-field types plus postgres,
  mysql, redis and rabbitmq. Composite, synthetic and promql still lack a strict v1 file
  schema and remain rejected.

No product or verification gap remains open for the approved FR-020/NFR-015 contract.
