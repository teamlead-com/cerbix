# iter-0119 — Secret inventory r7: conformance audit, spec amendment and slice 4 (FR-020/NFR-015)

## 1. Summary

A read-only conformance audit of the shipped FR-020 implementation against
[`func-secret-inventory.md`](../specs/func-secret-inventory.md) found **three blockers and
one P1**, each independently confirmed. Two of the three were holes in the SPECIFICATION,
faithfully implemented — the r6 §9 matrix never asked for the tests that would have caught
them, which is how a green suite and a closed acceptance report (iter-0116) coexisted with
a defect that silently stopped monitoring.

This iteration amended the spec (r7, two adversarial design rounds), recorded **D-0160**,
and delivered slice 4. The distinguishing discipline was that **every regression was
verified to fail when its fix is reverted**: the three blockers all passed a green suite, so
"the tests are green" was not admissible evidence here, and the report records the mutation
for each.

The audit findings, in the order they were closed:

1. **Pull-claim blindness (blocker, availability).** The wire barrier was implemented
   symmetrically. Ordinary monitors are enqueued on the legacy carrier and an `enforced`
   region's agent necessarily holds a dispatch keyring, so a capable claim that returned
   only its own generation left every ordinary monitor's row to expire by TTL: no probe, no
   heartbeat, no DOWN, no alert. Enabling a security feature silently disabled monitoring
   for the whole region.
2. **No execution binding (blocker, security; a spec hole).** The AAD bound a credential to
   whose it was and when, but not to what the job asked it to do. Anyone able to WRITE to a
   carrier kept a valid envelope, edited the target and received the plaintext credential at
   an endpoint of their choosing.
3. **Envelope stripping (blocker, security; a fail-open the spec never required a test
   for).** The envelope was opened only when present, so deleting the JSON member skipped
   every credential check: a `redis` monitor then skipped `AUTH`, PINGed, and an auth-less
   target answered Up. No key and no forgery needed.
4. **Publish-failure storm (P1).** The backoff floor covered materialization but not
   publish, so a broker outage — the one fault that hits every credentialed monitor at once
   — turned each tick into a full read + decrypt + seal storm.

Two further P0s were introduced **by this iteration's own work** and caught by review and by
the live smoke rather than by the suite; both are recorded in §5 because how they were found
matters more than that they were fixed.

## 3. Design decisions taken (D-0160)

- **Option A — the carrier is trusted.** A party who can author carrier routing metadata is
  permanently outside the threat model. The cost is recorded without softening: someone with
  broker write — a credential usually distributed more widely than the core database's — can
  emit a legacy-generation job for a credentialed monitor and obtain an anonymous probe that
  reports Up. **Option B** (a root `job_auth` MAC on every enforced job, including
  credential-free ones) is the construction that actually closes that path and is recorded
  as declined-for-now with its own cost, so the trade-off is not rediscovered as a surprise.
  This was an owner decision, not a technical preference.
- **Carrier generation is the policy boundary.** Generation 1 is the pre-FR-020 wire and
  honours an inline credential; generation 2+ never consults it. This is what keeps
  `secrets.enabled: false` meaning "nothing else changes" while leaving stripping fatal
  where an envelope is expected.
- **Envelope and carrier are numbered separately.** Generation 2 already means envelope v1
  to every deployed executor, so binding the execution body had to arrive on a NEW carrier
  (generation 3) rather than redefine v1 — a silent redefinition breaks a rolling upgrade in
  both directions.
- **The digest binds credential use, not the whole job.** Excluded state/display fields stay
  mutable in transit by design; full-job integrity is a separate decision.

## 4. Contract evidence

| Contract | Evidence |
| --- | --- |
| One-directional barrier | The claim predicate leases every generation at or below the caller's capability in ONE atomic operation under one shared `max` and one lease, ordered by age so generations cannot starve each other; mirrored for `pull_tests`. A capability-1 claim never reaches generation 3; a claim understating its capability is refused. The server stamps each row's generation and the agent refuses a response whose stamps are absent-vs-malformed ambiguous. |
| Execution binding | `body_digest` is SHA-256 over a versioned canonical DTO — type, target, timeout, retries, ordered condition values, and every non-secret setting of the effective schema taken from the registry. Golden vectors pin the bytes; equivalence cases (shuffled map order, excluded fields, renamed ref, nil vs empty conditions, absent vs explicit defaults) and difference cases (every bound member) are both covered, plus an ambiguity probe that `("ab","c")` and `("a","bc")` do not collide. |
| Structural gate | One package function, taking the keyring, called unconditionally on all six executor paths — AMQP jobs, AMQP test-RPC (both generations), pull jobs, pull tests, local/inproc test. Fixed order: carrier, tri-state requirement, exact field set, AEAD. Six tampering shapes refused before any target connection, each with a non-oracular reason. |
| Feature-off contract | With the feature disabled a credentialed monitor still reaches a real prober on the worker (inproc/AMQP) and the pull agent, and does not move credential readiness; a legacy job whose inline credential is missing or empty is still refused. |
| Generation rollout | A region is emitted into generation 3 only when its own transport proves a live capability-2 consumer; the checks are per transport, so a pull region's readiness cannot be satisfied by an AMQP consumer. The carrier→envelope mapping is total, and an unknown carrier degrades to the OLDEST envelope. |
| Backoff | A publish failure moves next-eligible to `now + backoff` and increments a counter kept separate from credential failures; success clears it and restores cadence. Asserted as state, not as a wall-clock rate. |
| Registry | One declarative source for validation, normalization, expected credential fields and execution-binding keys. Every field declares a binding class whose zero value is invalid, and the single-slot contract is asserted rather than implied. |

## 5. What the suite did not catch (and what did)

Recorded deliberately, because it is the most transferable result of this iteration.

- **The structural gate broke the feature-off contract.** Requiring an envelope for any
  credential-required schema stopped every existing credentialed monitor whenever FR-020 was
  disabled — the exact opposite of §4.1. No test covered a legacy credentialed job with the
  envelope off, so `-race` stayed green across 32 packages. Found by review of the diff, not
  by the suite. Fixed by making the carrier the policy boundary; the mutation that removes
  the legacy allowance reproduces the reported failure verbatim.
- **The capability ceiling did not move with the generation.** The heartbeat's ceiling lives
  in `internal/api` while the generation it bounds lives in `internal/dispatch`. Introducing
  envelope v2 left it at 1, so every capability-2 agent's heartbeat was rejected with 400,
  the region looked dead to the readiness check, and core would never have emitted the
  generation those agents exist to consume — a security rollout that silently disables
  itself. Found by the **first live `make secret-smoke` run**, not by any unit test. The
  guard now asserts against the constant, not a literal.
- **A claimed guarantee that the code did not keep.** `tls_skip_verify` has an effective
  default the stored config does not materialize, so the digest encoded absent as `""` and
  explicit as `"false"` — two configs describing the same probe digesting differently,
  against §4.7. Found by review; fixed by separating a field's canonical value from whether
  normalization writes it.
- **Coverage that proved nothing.** The generation stamp was asserted on the store row and
  fed directly into an agent fake, but nothing exercised the handler between them: deleting
  the stamp from the response left every claimed regression green. Found by review; the fake
  now models real generations and the bridge is asserted.

## 7. Intentional boundaries (not defects)

- **Backoff scope.** The publish floor governs the credentialed materialize→publish path
  only. A failed publish on the plain snapshot path costs a marshal and an enqueue attempt,
  with no DB read, decrypt or seal behind it, so a prompt retry there is cheap and aids
  recovery. The regression was retargeted when it first exposed this, rather than widening
  the change silently.
- **`make secret-smoke` is not wired into `make dev-test`.** §10 asked for it, but D-0158
  fixes that an E2E goal never starts, stops or redirects a stack, and this smoke owns its
  whole world — it builds the binary and provisions its own throwaway database. It is a
  peer target instead. §10's wording is corrected accordingly.
- **Option A's residual.** For legacy-generation traffic the residual is exactly today's
  pre-FR-020 property. It is stated in §2 rather than left to be inferred, together with the
  option-B end state and why it was declined.
- Legacy inline monitor ciphertext remains AAD-less at rest (unchanged non-goal).

## 8. Not closed — FR-020/NFR-015 stay `IN_PROGRESS`

The three blockers and the P1 are fixed with mutation-verified regressions and a green live
smoke, and the spec's availability gate for pull regions can be lifted. Acceptance is **not**
re-declared, because three items of the amended §9 matrix are not yet evidenced:

1. **The fail-open case is pinned at unit level, not against a live target.** §9 asks for it
   against a live auth-less redis that would otherwise answer PING and report Up. The gate
   is proven to refuse before any dial; the end-to-end lie is not yet demonstrated.
2. **No browser E2E for the Secrets panel lifecycle** (create → bundle → rotate → rename
   blocked/re-pointed → delete → 409). The shell smoke covers the API and dispatch path, not
   the SPA surface.
3. **Generation 3 has never run in a live mixed-capability fleet.** Its emission gate,
   claim predicates and queue isolation are unit- and component-tested, and the smoke
   exercises a single capable agent; a rolling upgrade with one capability-1 and one
   capability-2 executor in the same region has not been executed.

Declaring DONE on the strength of the first two blockers being fixed would repeat exactly
the mistake this iteration exists to correct.
