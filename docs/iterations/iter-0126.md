# iter-0126 — FR-021 round 2: nine P0s, three of them introduced by the pass that fixed the first twelve

## 1. Summary

iter-0125 fixed twelve P0s and was rejected in round 2 with nine more. Four were verified
against the code and the live database before the report was accepted; all nine are real.

The finding that matters more than the count: **three of the nine were introduced by
iter-0125's own fix pass, and a fourth was made reachable by it.** The suite stayed green
through all four, because each new test exercised the property its author had in mind rather
than the contract around it — the same shape as iter-0124's defect, one level up.

- A composite `ON DELETE SET NULL` nulls **every** referencing column, so the tenant-safe owner
  FK made a referenced escalation policy undeletable (`project_id` is NOT NULL). Reproduced on
  live PostgreSQL 16 before accepting it.
- The epoch bump was moved into the row-write helper, which runs **one statement too early**:
  every caller replaces `monitor_secret_refs` afterwards, and the snapshot reads credential
  generations from those refs. The defect was relocated, not removed.
- The per-project service cap was claimed in an AC and enforced on one of two writers.
- Making `DeleteMonitor` succeed exposed `maintenance_windows.monitor_id ON DELETE CASCADE`:
  elapsed and archived windows now vanished with the monitor, and the next recompute silently
  rewrote sealed history without the exclusion.

## 2. The nine

| # | Defect | Fix |
| --- | --- | --- |
| 1 | Epoch built from the OLD credential identity — refs are replaced after the bump | The ORDER is the shared contract: row → refs → epochs, for every caller |
| 2 | Forward slice checked its deadline only between buckets; one blocked statement held the dispatch tick | Deadline covers BEGIN→commit plus server-side `statement_timeout`/`lock_timeout` |
| 3 | "Preview" showed only the current numbers; annul tokens named no window; audit covered one axis | Real projection through the same reducer, target-bound tokens, both axes, mutation audit with actor and token |
| 4 | UI delete rewrote FILE-owned declarations (§15.1 UI→file cell) | Refused with `ErrServiceManagedByFile`; the monitor survives the refusal |
| 5 | Monitor deletion cascaded away retained maintenance provenance | FK dropped; the window keeps its scoped identity, because NULL already means "project-wide" |
| 6 | Project cap on one writer, and an invented 500 instead of the spec's numbers | One owner for both writers; default 50/50/10, hard max 200/200/25, configurable and clamped |
| 7 | Composite owner FK made referenced routing undeletable | Column-list `ON DELETE SET NULL (owner_column)` |
| 8 | Historical batch sorted by monitor, not by the keys it locks | Keys resolved first, sorted globally by `(service_id, bucket_start)` |
| 9 | A service that declared silence could never report again | A declared discontinuity starts a new contiguity ERA; the watermark is computed within it |

## 3. Tests that were wrong before they were right

Three of the new regressions passed against the broken code on their first writing, each for a
different reason, and all three are worth recording because the failure mode is the one the
review keeps finding:

- **The credential-ref test** asserted that the epoch hash MOVED. It does — the ref *name*
  reaches the snapshot straight from `Config`, whichever order the writes happen in. Only the
  *generation* comes from the refs table, so that is what it asserts now.
- **The monitor-binding preview test** used a monitor that was not an SLI member, so the window
  affected nothing and no preview was required at all — correct behaviour, and it hid the hole.
  Rebuilt so both mutations resolve to the same affected set and only the binding can fail.
- **The era test was wrong twice.** First it put the new era in the future, where nothing can
  seal. Then it still had no gap at all, because every bucket in the "silent" period had been
  materialized under the previous epoch. It now carves the hole explicitly and says why
  constructing the state beats sleeping through it.

Each was caught by re-applying the shipped behaviour as a mutant and finding the test still
green. A regression that cannot fail on the old code is not one.

Migrations 00070–00072. The `maintenance_windows → monitors` FK is deliberately not restored
on the down path: rows may reference monitors that no longer exist, which is the provenance the
migration exists to keep.

One honest note on the suite: a `./...` run once failed a single store test that passes alone
and in a full `-race` run. Packages execute in parallel against one test database and truncate
each other; it is contention, not a defect, and it is a property of the project's test setup
rather than of this change.

## 5. Also closed, because this pass caused them

- The preview/confirm flow reaches the SPA. Switching DELETE to archive and adding the gate
  left an operator with a 409 and nowhere to go; the SLA view now previews the change, shows
  availability before and after per service, and confirms with the token.
- `openapi.yaml` and the TS schema document `/maintenance/preview` and `/maintenance/{id}/annul`.
- The store sentinels added in iter-0125 map to actionable 4xx instead of 500.
- Preview expiry moved onto the database clock, like the rest of the protocol.

## 6. Still open

The reviewer's remaining P1s are not addressed and are not claimed: composite `service_id` in
the epoch/fact FKs, UI/declaration audit beyond the events added here, archive semantics for a
future window and the legacy suppression queries that ignore `archived_at`, a tx-scoped
coalescer for maintenance invalidation, `ServiceDetail`'s multi-snapshot assembly, the range
deadline over a whole repair slice, service fact partition maintenance, the `NO TRANSACTION`
migrations and the slug-suffix overflow, interval-aware revision resolution in
`servicesAffectedByWindow`, MaC routing lock order, service metrics and readiness, and the
`origin_id` overclaim (no production writer enqueues declaration- or epoch-origin work yet).
