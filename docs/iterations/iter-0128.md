# iter-0128 — FR-021 round 4: the clipped projection, the honest budget, and the connection my own fix was killing

## 1. Summary

Round 2/2 rejected iter-0127 with two P0s and seven P1s. This iteration closes both P0s and
six of the P1s, and its strengthened tests found a fresh defect in my own round-3 fix that no
review had seen yet — which is by now the expected outcome rather than a surprise.

## 2. The two P0s

**The projection clips.** iter-0127 fixed the gate's interval overlap and left the projection
reducing whole buckets: an operator previewing `[10:00:30, 10:00:45)` confirmed splits summing
to sixty seconds for a fifteen-second question, violating the payload's own conservation
contract. Both sides now reduce `[max(bucket_start, from), min(bucket_end, to))` from one
shared read; each side conserves to `(to − from)` exactly; the before side is the same clipped
reducer, not a whole-bucket column sum; and time no epoch governs is UNKNOWN on both sides
rather than silently dropped.

**The budget bounds the operation.** iter-0127's wall budget lived inside one loop: every
service's aggregate ran under the project's membership lock with no deadline check, and a
fired `statement_timeout` aborted the transaction into a 500 instead of the promised
`approximate`. Now the wall check runs before every service, each projection runs in a
savepoint with bounds re-derived from the remaining budget, exhaustion delivers the
approximate token, and the pre-projection phase keeps a statement floor so a spent budget
skips services instead of blowing up the query that lists them.

## 3. The defect the new test found

The reviewer asked for the leader-session test to exercise the ERROR path. Doing so found
that my round-3 fix set the client-side context deadline to the same instant as the server
timeouts. The two race; when the client cancel wins, pgx closes the connection mid-query —
and on the leader path that connection owns the advisory lock. **One blocked bucket would
have cost the node its leadership**, a strictly worse failure than the session poisoning the
fix was for. The client deadline is now a cushioned safety net behind the server bounds, on
the forward and repair paths both, so the server always speaks first: an SQL error, a
rolled-back transaction, a surviving session. The regression drives the error path on a real
`LeaderSession`, then demands `SHOW` defaults, a live leadership check, and a successful
release-and-reacquire.

## 4. The P1s taken

- **Retention fails closed at the preview** (422 with the earliest repairable instant), not
  after showing a "complete after" the confirm was always going to refuse. The response also
  carries `earliest_repairable` on success.
- **`projected: false` carries a reason** — `range_too_long`, `wall_budget`, `evidence_gone` —
  through the store, OpenAPI and the SPA. Three different remediations; a bare boolean forced
  the operator to guess between narrowing the range, retrying, and a range that can never run.
- **SlaView's main `load()` is generation-guarded** on success, error and finally; collections
  reset on project switch; unmount invalidates; a committed component test drives the
  deferred-response race in both directions (late list, late mutation error).
- **The forward driver re-derives its statement bounds per bucket** from the remaining budget.
- **Four proofs strengthened**: the token-expiry test executes the migration's own statements
  read from the embedded file; the health-axis proof constructs a GOOD-but-DEGRADED bucket
  where excluding the down member moves health and not one microsecond of availability; the
  opposite-order backfill test holds the middle key hostage and provably parks both writers at
  their lock waits (observed in `pg_stat_activity`) before releasing; the blocked-preview test
  is a real lock wait, not a pre-loop shortcut.
- **The shipped config examples show the services caps**, with the fail-fast rule spelled out.

Not taken: `archived_at` exposure in List/Get and the legacy suppression queries (still the
standing backlog), and the rest of iter-0127 §5.

## 5. Honest limits

- The per-service wall SKIP has no independent mutant kill. A hybrid mutant that disables the
  skip but keeps the savepoint statement bounds still satisfies the observable contract
  (bounded time, approximate token, lock released) — the bounds deliver it alone. The REAL
  iter-0127 shape, without savepoints, is killed by the committed test. The skip stays as
  belt-and-braces and this file says so instead of claiming a kill that does not exist.
- Two early mutant runs in this round scored "survived" on mutants that did not compile —
  the same false-negative shape as counting a green suite that never ran. Both were re-run
  compilably: one died, one exposed the gap above.
- The migration-statement parser in the test suite splits on `;` after stripping comments
  because a semicolon inside a comment sentence otherwise leaves its tail masquerading as
  SQL — found the hard way, in this round.
