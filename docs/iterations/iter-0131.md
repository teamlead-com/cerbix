# iter-0131 — FR-021 round 7: BEGIN was outside the envelope, and false meant two things

## 1. Summary

The final round-2/2 verdict on iter-0130 rejected with one P0 and two P1s, all three verified
against the code before a line changed. All three are closed here. The shared shape, for the
fifth consecutive round: a boundary case the mechanism did not reach — this time the ONE
statement no server bound can speak for, and a guard whose return value already had a meaning.

## 2. The P0 — the claim's BEGIN

`claimRepairRangeBounded` measured `remaining` from the caller deadline, ran `BEGIN` on the
caller's root context, and minted `time.Now().Add(remaining)` AFTER it returned. A stalled
BEGIN was therefore unbounded, and the time it consumed was granted a SECOND time to the
statements after it: 100ms left, BEGIN eats 90ms, the claim receives a fresh 100ms and
returns at ~190ms — on the advisory-lock connection. The previous claim test locked the
table after BEGIN succeeded and could not see the gap.

Now one absolute `claimBy = min(caller deadline, now + cap)` is fixed BEFORE BEGIN. The cut
lands AT the budget everywhere and the tolerance only ever covers observing it: the
statements are cut by the SERVER (bounds derived from the remainder to `claimBy`, net one
tolerance behind so the server speaks first), and BEGIN — the one statement with no server
bound to speak — is cut by ITS OWN net at `claimBy` itself. The same instant feeds
`deadlineTx`, so a BEGIN that returns past `claimBy` finds every subsequent statement
refused. The demanded regression drives a delayed-Begin `dbConn` both ways: a
net-interruptible 400ms stall returns bounded with nothing claimed, and a self-resolving
150ms stall past the cap is refused — no claim after expiry.

## 3. The P1s

**Repair-first held by the boundary, not by a flag with two meanings.** The undersized-tail
guard lived inside `RunServiceRepairSlice` and returned `(false, nil)` — and `false` there
means "the repair queue is empty", so `RunServiceSlice` ran the FORWARD pass on a short tail
with a repair backlog still pending. The guard moved to `RunServiceSlice` itself: an
undersized tail (< claim worst case + closing-write reserve) runs NEITHER phase. The
regression constructs pending repair + due forward + a 100ms deadline — under the 140ms tail
floor, above forward's 60ms commit reserve — and asserts no claim, no lease, and a forward
cursor that did not move.

**The pass threshold is the contract, verbatim.** `cadenceLimit + measuredOverhead` was still
wider than §10.10: an uncapped runtime sample added to the bound can grow under contention
until it green-lights the regression under test — the fixed-150ms failure mode with extra
steps. Every assertion now compares against `budget + max_scheduling_tolerance` and nothing
else; `measuredOverhead` stays as a per-run diagnostic LOG beside the contract, never as
slack. The whole timing pack holds at the flat thresholds over five `-race` runs.

## 4. Honest limits

- BEGIN's net at `claimBy` means a genuinely stalled BEGIN is cut at the budget, not a
  tolerance past it — which is what lets the delayed-Begin assertion hold the flat
  `budget + tolerance` contract by the same arithmetic as every server-bounded case. The
  round-1/2 shape netted BEGIN at `claimBy + tolerance` and then needed a second tolerance
  to observe the cut; that double grant is gone rather than renamed.
- A net-killed BEGIN on the leader path still costs the connection (and with it the advisory
  lock) — nothing else can bound a statement the server never started executing. The verdict
  accepts this; the test's case (b) covers the other, cheaper path where the stall resolves
  and the refusal is client-side with the session intact.
- The tail guard and `lifecycleReserve` remain lease-avoidance belt-and-braces without
  independent behavioural kills (iter-0130 §5); what iter-0131 adds is the repair-first kill
  for the guard's PLACEMENT, which is behavioural and dies on the iter-0130 shape.
