## 3. What changed, by item

**T1 (P0).** `ArchiveMaintenanceWindow` cuts a FUTURE window at its own start — the empty
interval `[starts_at, starts_at)` — because with `cancel_effective_at` left NULL its declared
end kept counting in every reducer and the archive silently un-archived itself when the
window's time arrived. Every legacy consumer (MonitorSLI, ProjectSLI, burn-rate windows,
MonitorInMaintenance, three rollup sites, the RecordCheckStatus maintenance CTE) now reduces
ONE shared expression, `maintEffectiveEnd = LEAST(ends_at, COALESCE(cancel_effective_at,
ends_at))` — the same rule the service axis already reduced. `maintenanceColumns`/domain/
OpenAPI/TS expose `archived_at` + `cancel_effective_at`; the status page skips archived
windows; SlaView filters them on load — the reload that used to resurrect an archived window
is a committed component test. The archive itself is atomic with its audit row (T7).

**T2 (P1).** `invalidateForMaintenance` enqueues through `enqueueRepairRangeTx` (pending
same-reason union-absorb) instead of a raw INSERT, with the WINDOW as the range's origin.
Two mutations over one service now leave ONE pending maintenance range spanning their union.
A merged range keeps an origin ONLY when provenance is unambiguous: a union required by two
windows carries NULL — stamping it with the latest origin would let that origin's cancellation
discard the part the other window still requires, violating §10.8's exact-union preservation.
The claim is scoped honestly: cancel-by-origin is proven at the STORE layer (a single-origin
range cancels; an ambiguous union refuses), and NO production canceller for maintenance
origins is wired yet — nor do declaration/epoch enqueues exist that would write those origins.
Both facts are stated here and in §5 instead of implied away.

**T3 (P1).** `EnsureServiceFactPartitions` (monthly, both storage modes — facts are native
range partitions by design, no hypertable branch) runs on the scheduler's partition cadence
beside the heartbeat twin. Migration 00064 seeded partitions around its own run date only;
six months after an install every fact insert would have landed in DEFAULT forever. Facts are
never purged: they are the sealed product, and raw retention governs heartbeats.

**T4 (P1).** The §21 surface, conformant: `cerbix_service_repair_ranges{state}` over all
five states, `cerbix_service_watermark_lag_seconds` (counts from `era_start` when nothing is
sealed — that IS a lag — and clamped at zero, because a fresh adoption's era is legitimately
in the future), `cerbix_service_slices_total{outcome}`, `cerbix_service_late_arrivals_total`
+ overflow, and `cerbix_service_epochs`. **Readiness IS gated, as §21 demands**: the wedged
component (a terminally parked `error` range, or watermark lag beyond 3600s — bounded and
defined in code and runbook) fails the scheduler's `/readyz` through the same component
pattern credential readiness uses, and recovers on the next 15s cadence. HA-correct: a
deposed leader clears its service gauges AND its wedge verdict on step-down, so two
schedulers never describe one cluster from different moments.

**T5 (P2).** The §15.4 spec analysis was already corrected in an earlier round; what was
missing was its ACCEPTANCE. Now committed: barriered concurrency tests (pg_stat_activity-
observed lock waits) proving a service-owner create cannot deadlock a policy or schedule
delete — the owner path's explicit FOR KEY SHARE is the mechanism — and the monitor-versus-
policy-delete race run and DOCUMENTED as the spec demands: bounded, resolving as a clean FK
refusal in the observed runs, not asserted safe.

**T6 (P2).** The derived-slug collision suffix fits the shape: the digit-only-name path
yields exactly the 63-char boundary and the old `%s-%d` made the first collision candidate 65
chars — an invalid slug the loop never re-validated, dying on the CHECK constraint as a 500.
The base is trimmed so the counter fits. The NO TRANSACTION migrations (00043/00064/00065)
are crash-resumable: 00064's twenty-five bare CREATEs and 00065's bare ADD CONSTRAINT would
each brick a resumed run on "already exists"; all are guarded now, and a committed test
re-executes each Up section against the migrated schema — the resume, statement for statement.

**T7 (P2).** `service.declaration_put` (with the actor label), `service.deleted`,
`maintenance.window_archived` — each written IN the transaction that performed the act,
following the `service.member_retired` pattern.

**T8 (P2).** `ServiceDetail` reads its six queries under ONE `REPEATABLE READ, READ ONLY`
transaction: six pool round trips each saw their own instant, so a declaration landing
mid-assembly produced a detail whose epoch did not belong to its revision.

**Closed by inspection, no code:** composite tenancy FKs for epochs/facts — migration 00064
already declares `(service_id, project_id)` / `(epoch_id, project_id)` composite FKs on every
service-scoped table (verified: zero single-column references to services remain).
Interval-aware `servicesAffectedByWindow` and the whole-slice repair deadline — fixed in
rounds 5–8, recorded here only because the old backlog lists still name them.

## 7. Round 1/2 disposition — the fix pass

Round 1/2 rejected with one P0 and six P1s; all closed here, each with a regression that
fails on the round-1 code.

- **P0, archive vs in-flight repair**: the archive now bumps `project_maintenance_generation`
  in its transaction — recompute is NOT horizon-bounded, so a batch over a window's future
  span could re-read an unchanged generation and commit an exclusion the operator had just
  cancelled. `TestArchiveFencesAnInFlightRepairBatch` parks a real batch mid-work
  (pg_stat_activity-observed), archives, releases: the stale batch fails its CAS and re-arms;
  the rerun's facts keep the covered time excluded and carry ZERO exclusion after the cancel.
  Mutant (no bump): the stale batch runs to `state=complete` — the exact P0 — killed.
- **Origin provenance**: ambiguous unions carry NULL origin (mutant "latest wins" killed on
  the union); claims narrowed as above.
- **DEFAULT-month adoption**: `isDefaultPartitionConflict` + `adoptDefaultServiceFactMonth`
  (move rows, attach, one transaction); regression strands a real fact in DEFAULT and proves
  adoption + post-adoption idempotence.
- **Migration 00065 backfill**: the DO-block trims its base so the uuid suffix fits the
  shape; the regression reconstructs the pre-upgrade schema (slug NULL, no constraint) and
  executes the REAL Up section — the untrimmed mutant bricks on the shape constraint exactly
  as the verdict predicted. Test DB recreated after the migration edit.
- **§21 conformance**: T4 rewritten above; `TestServiceWedgedGatesReadinessAndClearForgetsIt`
  and `TestWatermarkLagClampsAtZeroForAFreshAdoption` are the new proofs; the scheduler
  wiring assertion for `EnsureServiceFactPartitions` joined the leader-maintenance test.
- **Half-open boundaries**: both live gates use `>`; `TestMaintenanceEndsExactlyAtTheir
  EffectiveEnd` pins the EXACT boundary with a transaction-frozen now() (a window ending at
  now() is over; one microsecond of remainder flips it); the `>=` mutant killed.
- **Docs**: traceability row added; runbook gained the FR-021 operations section (metrics,
  wedged recovery, partition adoption, suggested alerts); the frontend count reads 30.
