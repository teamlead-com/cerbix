## 3. Changes

**P1-1 — current_health is the state AT as_of.** Final shape after the round-1 verdict
([175], §6): `ServiceHealthNow` evaluates `[as_of, as_of + 1µs)` — the right-continuous state
at as_of, with the epoch resolved at as_of. (The round-1 shape `[as_of − 1µs, as_of)` was the
left limit and was REJECTED by [175]; it is recorded in §6, not here.) Carry-in, maintenance
spans and freshness flow through the same helpers the materializer uses; inputs after as_of
are excluded (allowed_skew ≤ 5m). An exclusion in force at as_of reads as "unknown" — the
four declared categories, nothing invented. NOTE ([178], superseded forward): the window
premise "no breakpoint can fall strictly inside 1µs" is FALSE for derived freshness deadlines
(ns-granular durations); iter-0140 replaces the window with a true point evaluator.

**DISCOVERED phase-1 defect, fixed and disclosed prominently.** The P1-1 regression exposed a
latent bug in `observationsFor` (the MATERIALIZER'S input): a trailing `ORDER BY` after a
`UNION ALL` binds to the WHOLE union, leaving the carry-in `DISTINCT ON` with no defined
order — an ARBITRARY prior observation became the hold state whenever a member had more than
one row before the bucket (reproduced empirically: the older DOWN was returned over the newer
UP). Every phase-1 fixture planted exactly one prior observation, which is how a
sample-and-hold evaluator shipped with an undefined hold state. Fix: the carry-in branch is
parenthesized so its `ORDER BY monitor_id, ts DESC` belongs to the `DISTINCT ON`.
**Impact statement:** sealed facts whose bucket start had ≥2 prior observations of a member
may carry a wrong pre-first-observation slice; an operator restates any affected range with
the SHIPPED command `cerbix enqueue-service-repair` (added in this changeset's round-2 pass —
same store enqueue path: pending same-reason union coalescing, bucket flooring/ceiling, the
audited `admin` reason; the scheduler leader executes with the defined carry-in). Regression: `TestCarryInIsTheLatestPriorObservation`
(two prior observations inside the freshness window, old DOWN then new UP, no in-bucket rows
→ the bucket is GOOD end to end).

**P1-2 — burn verdict fields are computed before the status ladder.** The anchored window's
bucket count, continuity and coverage are queried FIRST, unconditionally; stale-watermark and
era-short statuses now QUALIFY the answer without relabeling a fully stored window as 0/N
with zero coverage.

**P2-1 — `AggregateWithheld` is a claim.** The spans-revisions label is set only when the
stored facts actually show more than one revision; a zero-fact gap keeps the empty label and
its known storage_gap reason.

**P2-3 — wording.** The FR-021 status row body reads "Phase 2 (IN_PROGRESS — iter-0138/0139
reporting compute core under review)"; the `ServiceHealthNow` domain comment now describes
the on-read at-instant evaluation.

## 6. Round 1/2 verdict [175] and the fix pass

Accepted at round 1: the carry-in SQL fix, burn verdict fields, the withheld-label rule and
the docs sync. Remaining findings, closed in this pass:

**P1 — left limit, not the state AT as_of.** [as_of − 1µs, as_of) sampled the state at
as_of⁻: an observation, a stale deadline, a maintenance start or an epoch boundary effective
EXACTLY at as_of was excluded. The evaluation window is now **[as_of, as_of + 1µs)** — with
µs-granular timestamps, as_of + 1µs is the next representable instant, so every input with
ts ≤ as_of is in force (in-window at as_of or carry-in before it), every future input stays
excluded, and the window still contains exactly one sample-and-hold state — the
RIGHT-continuous state at as_of, the same reading effective.go gives a deadline. The epoch is
resolved at as_of itself. A `serviceHealthNowTx(ctx, tx, projectID, serviceID, asOf)` seam
was extracted (mirroring the report seam) because boundary instants are not reproducible
through a wrapper that mints its own clock. `TestServiceHealthNowIncludesBreakpointsAtAsOf`
covers: an UP observation exactly at as_of (left limit says down), the stale deadline exactly
at as_of (unknown, with the −1µs probe still healthy), and a maintenance start exactly at
as_of (excluded → unknown, with the −1µs probe healthy — the boundary sits 15s ahead, inside
the freshness window, so staleness cannot mask the flip). The accepted-future negative and
all prior health regressions still pass.

**P2 — the repair disclosure is operator-executable.** `cerbix enqueue-service-repair
--config <path> --project <id> --service <id> --from RFC3339 --to RFC3339` enqueues through
the store's own path (union coalescing, flooring/ceiling, reason `admin`); execution stays
with the scheduler leader's audited repair machinery. Tested AS the artifact:
`TestEnqueueServiceRepairCommandEndToEnd` (own migrated database; two overlapping invocations

**P2 docs honesty.** The iter-0139 header names the carry-in fix as in-scope; the FR-021
status text reads iter-0138/0139.
