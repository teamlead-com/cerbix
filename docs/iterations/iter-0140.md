Mechanism, confirmed in code: `FreshnessPolicy.ActiveFloor` parses through
`time.ParseDuration` (nanosecond-granular, `domain/service.go`), and a stale deadline is a
µs-aligned observation timestamp PLUS that duration — derived breakpoints are NOT µs-aligned,
so no fixed-width window is safe. Only a true point evaluation is.

## 3. Changes

- **`reliability.StateAt(members, observations, maintenance, policies, t)`** — the point
  evaluator: the aggregated outcome in force AT t, right-continuous, composed from the
  reducer's OWN pieces (`buildSeries` → `censusAt(t)` → `aggregate`) — the exact computation
  `Reduce` performs for the sub-interval beginning at t — so the live signal and the facts
  cannot disagree about what a member's state at an instant means. No interval is involved;
  no width exists to split. Empty members mirror `aggregate`'s empty-tally semantics
  (UNKNOWN, never GOOD).
- **`serviceHealthNowTx`** maps `StateAt(...).Health` to the four declared categories
  (excluded → unknown). Input reads keep their instant bounds (observations `ts ≤ as_of`,
  spans in force over the instant, the epoch at as_of) — with `latestAt` ignoring later rows,
  the accepted-future fence is doubled.
- **iter-0139 report sync ([178] P2)**: §2/§3 now describe the changeset's final
  `[as_of, as_of + 1µs)` shape with the round-1 left-limit shape explicitly labelled
  rejected-in-[175], both annotated as superseded by this changeset's point evaluator; the
  §4 count reads 17 at the changeset's final state.
