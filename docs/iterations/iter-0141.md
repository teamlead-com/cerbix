different named thing" (§11.3), never a field of the percentage report.

## 3. Changes

- **Routes** (session-auth, project-scoped via `projectAccess`):
  `GET  …/services/{id}/reliability?window=24h|7d|30d|90d` (default 30d) → `domain.ServiceWindowReport` verbatim;
  `GET  …/services/{id}/health` → `domain.ServiceHealthNow` verbatim (its own endpoint — §11.3's
  "different named thing", never a field of the report);
  `GET  …/services/{id}/reliability/series?from&to&step=hour|day` → `{from,to,step,points[]}`
  with the span capped at the longest supported window (90d);
  `PUT  …/services/{id}/sla-target {window, objective}` (editor+) — the body accepts NOTHING
  else: `DisallowUnknownFields` turns any burn spelling into 400 (invariant 47's API fence),
  the store offers no burn parameter, the schema CHECK is the final fence.
- **Store 404 semantics** (the one compute-core touch, disclosed): `ServiceReliabilityReport`
  / `ServiceHealthNow` / `ServiceReliabilitySeries` return `store.ErrNotFound` when the
  service does not exist IN the project (checked inside the same snapshot for the report and
  health) — a nonexistent or foreign ID must be 404, not a no_sli/unknown-shaped 200 that
  doubles as an existence oracle. The tenant regression now asserts ErrNotFound with zero
  data leaked.
- **API Store interface** grew four methods; `fakeStore` grew tenant-checked canned fakes
  (compilation-enforced, as designed).
- **openapi.yaml**: four paths + ten schemas mirroring the domain payloads field-for-field
  (statuses, reasons, withheld label, burn verdict fields, the unstable flag, reconstruction
  label); TS schema regenerated (`gen:api`); the SPA production build is green against it.

## 6. Round 1/2 verdict [192] and the fix pass

Accepted at round 1: authz/tenancy, window validation, series bounds, snapshot checks, the
verbatim payload passthrough. Findings, closed in one pass:

**P1-1 (objective representability).** Migration 00078 widens `sla_targets.objective` to
`numeric(7,4)` — 100.0000 is representable. ONE objective rule for every scope:
`domain.CanonicalObjective` rounds half-up to FOUR decimals and requires (0,100] AFTER
rounding (0.00001 → rejection, not a CHECK-violation 500; 99.99995 → the representable 100);
both the service and the monitor handlers pass the canonical value through, and the echo IS
the stored number. Tests: `TestCanonicalObjective` (unit, 11 boundary cases),
`TestObjectiveIsCanonicalAndRepresentable` (REAL PG: 100 stored exactly; 99.9999 byte-exact;
the monitor scope holds 100 through the same column), API echo asserts (100 → 100,
99.99995 → 100, at the wire AND at the store boundary).

**P1-2 (transport owns request format).** `serviceIDParam` validates strict 8-4-4-4-12 hex on
all four routes: malformed → 400 before any store call (PostgreSQL never sees a uuid-cast
candidate), well-formed-but-absent → the store's honest 404. The API tests now use a seeded
uuid-shaped service (the fake's `svc-`+slug fiction cannot ride these routes), a valid absent
UUID for the 404 proof, and the literal `nonexistent` for the 400 proof on all four routes.

**P1-3 (single JSON value, fail closed).** BOTH shared decoders — `decodeJSONBody` and
`decodeJSON` (one decoder rule, deliberately not two) — now require the second decode to
return `io.EOF`: `{…}{"burn_alert":true}` is 400. Endpoint test added.

**P1-4 (series linearization).** `ServiceReliabilitySeries` runs the existence check and the
rollup read in ONE repeatable-read snapshot via the extracted `serviceReliabilitySeriesTx`
seam. `TestSeriesExistenceAndDataShareOneSnapshot`: pin the snapshot, DELETE the service
concurrently, the pinned seam still answers from the pre-delete world; a fresh call is
ErrNotFound.

**P2-1 (wire shape).** `points` is a NON-NULL array at BOTH layers (store initializes `[]`,
the handler normalizes nil); OpenAPI's nullable is removed; raw-JSON test asserts
`"points":[]`.

**P2-2 (prose).** `api.go` route comment rewritten (phase 2 has endpoints now); OpenAPI's
ServiceDetail description points clients at the three reporting endpoints; traceability
reads "+11 schemas: 10 response + 1 request".

**Round-2 mutants** (each compile+vet clean, killed on the discriminating assert, reverted):
M5 trailing-values-tolerated → the multi-value body test; M6 uuid-gate-dropped → three
malformed-400 asserts; M7 canonical-rounding-dropped → "echoed 99.99995 … want the canonical
100" + the 0.00001 rejection. DISCLOSED SURVIVOR: an M8 wrapper mutant that runs existence
and data on two SEPARATE snapshots survives, because the delete-between-barrier regression
proves atomicity AT the seam (`serviceReliabilitySeriesTx`) and the 6-line wrapper's
snapshot count is not observable without hooks; recorded here per the iter-0138 M9
precedent rather than counted.
