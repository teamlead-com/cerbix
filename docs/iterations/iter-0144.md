## 2. Failure-mode table (self-adversarial, before code)

| Change | How it could be wrong | Guard |
|---|---|---|
| Honesty states | a dash state accidentally renders 100%/0× or drops the reason | the component switches on the payload's `status`/`reason` constants; the spec asserts each state renders its reason text and no number |
| Spans-revisions | an aggregate sneaks into the ∅ state | `aggregate_withheld` forces the banner; the spec asserts NO availability figure is rendered anywhere above the segments |
| Provisional | provisional ticks read as sealed status | dedicated strip component: provisional at reduced opacity, unknown as a short tick — the two encodings the approved motif fixed |
| Live signal | current_health rendered as/next to a percentage | its own card, pill + "unstable" framing, never inside the KPI row |
| Objective editor | a second client objective rule appears | imports `canonicalObjective` from `lib/objective.ts` — the one rule |
| Series step | the UI requests an unbounded/wrong step | window→step mapping fixed (24h→hour, else day), both within the API's validation |
| Async context | a deferred response or typed draft from service A lands under service B | one load GENERATION checked after every await in load AND save; full state+editor reset on project/service/window change; deterministic deferred A→B tests |
| Subordinate transports | a failed /health or /series request poses as a product state (UNKNOWN pill / empty timeline) | explicit `healthError`/`seriesError` states with their own prose; the report never overwritten by a subordinate failure |
| Provisional tail | the reduced-opacity tail is unreachable because the series query ends at sealed_through | a SECOND bounded request `[sealed_through, min(ceil(as_of,step), sealed_through+90d))`, merged after the sealed points |
| Tick geometry | a boundary fragment occupies a full step's width | widths proportional to `point.buckets`; prose counts buckets; an unequal-count SVG assertion |
| Repair ranges | a point under an active repair renders its stored status as data | points intersecting `report.repairing` are masked with the work encoding (`repairing` state) |
| Objective mutability | a stored target cannot be changed (§11.3 requires mutable) | Edit control whenever a target exists, prefilled with the canonical current value |

## 3. Changes

- **`components/ServiceReliability.vue`** — the phase-2 surface on the service detail, per
  the approved mock's screens 2–3: the two-layer Health card (SLI pill / diagnostics pill,
  "current · unstable by definition", never merged, never a percentage); the window selector
  (24h/7d/30d/90d) with the KPI row (availability+objective, error budget, the burn pair
  with per-window verdicts — the payload REASON as operator prose where a rate would lie,
  never 0× and never the machine status token — and decidable coverage with the storage
  verdict); the ∅ "No single availability number" banner for spans-revisions windows with
  per-segment cards (rev/epoch chips, the `[from,to)` range, declared-reconstruction badge,
  own availability/coverage, and the segment's OWN strip sliced from the series by epoch and
  range); the reason panel for every non-quotable state, each dash carrying the payload's
  own reason; the repairing note ("work in progress, never data") with the series points
  under an active repair MASKED as work rather than drawn as data; the objective editor
  using the ONE client rule (`lib/objective.ts`), offered for setting AND editing (§11.3 —
  a mutable current-view parameter), prefilled with the canonical current value.
  Tenant-context discipline: every async assignment in load and save is gated on a load
  generation captured before the first await, and the whole state (report/health/series/
  editor/draft/errors) resets on any project/service/window change, with unmount bumping
  the generation too — a deferred response or a typed draft from one context can never land
  under another, nor touch a torn-down instance. Subordinate transports fail
  separately: a failed /health or /series request renders its own transport-error state,
  never the categorical unknown or an empty timeline. The series is TWO bounded requests —
  the sealed window `[rep.from, rep.to)` plus the provisional tail
  `[sealed_through, min(ceil(as_of to step), sealed_through+90d))` — merged deterministically
  (disjoint ranges, API-ordered), which is what makes the mock's reduced-opacity tail
  reachable from the production query.
- **`components/ReliabilityStrip.vue`** — the timeline motif as fixed by the mock: discrete
  ticks where UNKNOWN is a SHORT tick and PROVISIONAL is REDUCED OPACITY (so neither reads
  as a status colour), revision boundaries as accent marks, epoch markers as thin lines;
  worst-signal tick colouring documented in the component. Geometry is TIME-WEIGHTED: each
  tick's width is its bucket count (`weight`), so a 6-bucket epoch/revision/provisional
  boundary fragment cannot pose as a 24-bucket day; a `repairing` state carries the work
  encoding (accent fill at reduced opacity) distinct from every status colour.
- **`ServiceDetailView.vue`** mounts the surface between the header and the declaration.
- **ONE disclosed store touch**: the nothing-sealed report now carries the stored objective
  (`reportObjective` factored and called on both paths) — the objective is a CURRENT-VIEW
  parameter (§11.3) orthogonal to sealed data, and without this an operator who set a target
  could not see it anywhere until the first bucket sealed (no other read exposes service
  targets). No budget/burn are computed from nothing; a store regression pins the contract.
