## 2. Failure-mode table (self-adversarial, before code)

| Risk | Where it would bite | Countermeasure |
|---|---|---|
| a stale editor silently overwrites another writer's set | two operators on one service | the save sends the token READ WITH THE LIST; a 409 renders as itself with a Reload that RE-READS (asserted: the reload issues a GET and no second PUT) |
| every rejection collapses into "could not save" | cycle vs stale vs bound vs file-owned | the payload's own message is rendered; the stale case is the only one offering Reload (a cycle is the author's own edit to fix) |
| a network failure looks like an empty graph | offline / connection reset | `guarded()` normalizes a REJECTED fetch into the same `{error}` shape; a failed read renders the error, never the empty-list state |
| a late response from a previous service lands | switching services fast | a load generation captured before the first await gates every assignment (regression drives it explicitly) |
| an unknown neighbour health renders as healthy | `health` absent in the payload | absent health renders "unknown" in `ink-3`, never a green pill |
| a failed impact read reads as "no impact" | incident detail | `impacts_unavailable` renders its own dashed chip saying the read failed |
