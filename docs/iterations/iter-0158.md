## 1. Correction of record — the flake iter-0157 §4 could not name

`iter-0157` §4 records a `-race` run of `internal/store` that failed once and whose failing test name I
destroyed by piping the run through `tail`. Three runs did not reproduce it, and the report says plainly that
I could not name it.

**The merge run named it: `TestFenceRefusesAnExhaustedCallerTail`.** It is a phase-1 test (written 2026-08-16,
`4908c6c`), so it predates every requirement in the merged branch, and it fails like this:

```
the exhausted tail surfaced as store: adoption fence size …: timeout: context deadline exceeded,
want the budget refusal (never a net kill)
```

**The cause is a bet on the wall clock.** The test gave the caller a 5ms context deadline and asserted the
BUDGET refusal — but the refusal is decided by
`deadline = min(now + fenceBudget, callerDeadline - schedulingTolerance)`, and reaching that check takes
several statements. On an idle machine they fit inside 5ms; under load they do not, the context dies first,
and a query returns `context deadline exceeded`. That is an honest answer to a spent tail and not the property
under test. Measured: **0 failures in 15 idle runs, 2 in 12 with the CPUs busy** — which is why a full `-race`
suite loses it roughly once in fifteen, and why it survived on a quiet machine for three days.

**The repair splits one racy assertion into two honest ones.**

| what | how it is asserted now |
|---|---|
| the budget refusal exists | a one-NANOSECOND fence budget with a generous context: the budget is spent before the check by construction, and no statement is ever cut |
| a spent caller tail does no damage | the 5ms context stays, but the assertion is that it is refused WITHOUT DAMAGE — either error is honest, and the partition-state checks run for whichever path the run took |

Mutation: restoring a 30-second budget makes the deterministic half fail with "a spent budget cut a fence".
Twenty `-race` runs under the same CPU load that produced the failure are clean, and the whole package is
green.

**What this costs to admit.** The test as written could not keep its promise on a loaded machine, and it was
asserting the right property through the wrong instrument. A test nobody believes when it fails is worse than
a missing test, and this one had already cost me an investigation whose evidence I threw away.

## 2. Correction of record — two harness self-inflictions, named as a pair

Both happened while chasing §1, and both are the same shape: **a command whose pattern matched itself**.

- `pkill -f 'while :; do :; done'` killed my own shell, because the shell's command line CONTAINS that
  pattern. This is the second time in this arc; the first is in the FR-021 record.
- `until [ "$(pgrep -fc 'while :')" -le 1 ]` then waited forever on its OWN `pgrep`, which matches the same
  way. It burned a five-minute timeout doing nothing.

The rule that follows, and it is cheap: **never match a process by a pattern the matching command itself
contains.** Kill by PID, or bound the load with `timeout` and let it expire — which is what actually worked
here, since the loops carried their own deadline.
