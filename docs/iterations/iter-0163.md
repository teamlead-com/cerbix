### 1.5 Review of changesets 1–2, and the fix — `b7518b9`

The reviewer's independent read of `59dc96d..8cb12d6` (party [19]–[24]) found three P1 in the store core,
all of the class the FR-021 arc had already named — the clock a write compares against:

- **[19] transaction time after a lock wait.** `CreateGateOverride` judged `expires_at` against
  PostgreSQL's `now()`, which is frozen at `BEGIN`; a caller that waited on the service row lock could
  commit an already-expired override, and — [24] — the expired-slot closure and the status clock in the
  override columns had the same clock, so an override that expired during the wait was not closed and
  could be manually revoked as if active. Every gate write now reads `statement_timestamp()` AFTER the
  lock (`dbNow`), and every timestamp a gate write stamps — created_at, revoked_at, updated_at, deleted_at,
  the status clock — is `statement_timestamp()`.
- **[20] the budget did not bound BEGIN.** `evaluate_tx_budget_ms` is begin-through-commit (§5a), but
  `BeginTx` ran on the caller's unbounded context and the deadline wrapper existed only after Begin
  succeeded; under pool exhaustion a decision could wait past the contract. `decideGateOnce` now derives a
  context deadline from the same absolute deadline before `BeginTx`; `DeadlineExceeded` maps to
  `ErrGateBudgetExceeded`.
- **[21] the policy audit lacked the actor.** Both policy audit targets carried before/after and not the
  immutable label (invariant 11); they now end with `actor=<AuditLabel>`.
- **[22] retracted by the reviewer:** `no_objective` is unreachable because `sla_targets.objective` is
  `NOT NULL` since 00005; no artificial branch was added.

Regressions in `gate_clock_budget_internal_test.go`: a blocker holds the service row past a 700 ms expiry
→ the create is refused on `expires_at`; `created_at` of a row written behind a lock is at or after the
lock's release instant read on the blocker's connection; with every pool connection held a 400 ms budget
returns `ErrGateBudgetExceeded` within budget + net; a token-made policy write and delete read back with
`token:<name>` beside before/after. **APPROVED** at party [26]; the reviewer also ran the store package
`-race` in a detached worktree at `b7518b9`: PASS.
