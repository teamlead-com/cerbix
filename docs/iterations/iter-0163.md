## 1. What landed

### 1.1 The metric surface — `db16dfa` (task 4, Agent D slice)

`internal/metrics/gate.go` (+ `metrics.go`, three touches): nine families exactly as D9/D10/§5a name them.
`cerbix_gate_decisions_total{state,action,overridden}` with `action="none"` iff `state=NOT_CONFIGURED`
and `overridden` refused for it; `cerbix_gate_evaluate_rejected_total{reason}`,
`cerbix_gate_evaluate_errors_total{kind}`, `cerbix_gate_maintenance_errors_total{kind}` — each a closed
set of four values, a value outside it returns `ErrGateMetricLabel` and records nothing, so a bug cannot
mint series; `cerbix_gate_decision_duration_seconds`, the repository's FIRST histogram (fixed buckets
0.05 … 30, `le` inclusive, `_sum`/`_count`); the four unlabelled ledger gauges, absent until
`SetGateLedgerGauges` and absent again after `ClearGateLedgerGauges` — a deposed node does not speak.
Ten tests (`gate_test.go`): exact series, closed sets, histogram boundaries (0.05 inclusive, 31 → only
+Inf), set/clear absence, a 45-line golden exposition, a `-race` concurrency oracle.

### 1.2 The CLI — `d926568` (task 5, Agent A)

`internal/cli/gate.go` + one `case "gate"` and a usage line in `cli.go`: a pure HTTP client, no database,
no config file. `CERBIX_URL` / `CERBIX_TOKEN` / `CERBIX_CA_FILE` from the environment ONLY — `--token`
and `--url` do not exist and are refused as unknown flags (exit 2); TLS verified, no skip-verify;
redirects are NOT followed (a redirect would carry the bearer to an unnamed host). stdout is one line,
`state=… [action=…] [override=…] decision=…`, or the response bytes verbatim under `--json`; reasons and
diagnostics on stderr. Exit 0 for action ALLOW/WARN (UNKNOWN keeps its word on the line), 2 for BLOCK, 4
for NOT_CONFIGURED, 1 for transport/auth/4xx/5xx/429 — the 429 prints `Retry-After` and is never retried
(the fake server counts exactly one request). 23 tests against `httptest` servers including TLS with and
without the CA. Review [13] found the one deviation: `--json` appended a newline when the body lacked one,
and the test had encoded it; `92d5a66` writes exactly the body bytes and the test compares stdout to the
body for both a newline-terminated and a bare body. **APPROVED** with the metric surface at party [16].

### 1.3 Schema, domain, config — changeset 1 (task 1, Agents A + B; committed with changeset 2)

Migration `00093_reliability_gate.sql`: `gate_uuid_ms(uuid)` IMMUTABLE; `service_gate_policies` with a
generation `revision` and a `deleted_at` tombstone; `service_gate_overrides` with both attribution
triples, the closure CHECKs and the history index; `service_gate_decisions` RANGE-partitioned by
`evaluated_at` with no DEFAULT, PK `(evaluated_at, id)`, the id-binding CHECK, the byte CHECKs, a
presence CHECK and the two partitioned listing indexes; the `service_gate_decision_partitions` registry;
the bootstrap of `[today, today + 7 d]` — eight days, each built standalone (`LIKE … INCLUDING …`, day
CHECK, local `UNIQUE (id)`, `COMMENT … 'cerbix:gate-ledger:<token>'`, registry `created`) and ATTACHed
(`attached`) — idempotent with a NOTICE per day. `internal/domain`: `LateArrivalGrace` moved beside
`CanonicalBucket`, `MinSealLag` declared as the D8a formula, the gate vocabulary (`gate.go`): states,
actions, assignments, the V1 clause set, the reason codes, `ValidateGatePolicyV1` (ordered clause
entries so a duplicate is refused BY NAME before a map could swallow it), `GateOverrideStatusAt` (the
four-row precedence of D13a). `internal/config`: the ten `gate.*` keys with ranges and the two
cross-checks naming both keys; `docker/config.example.yaml` documents them.

Decisions taken where §5 leaves column detail to the implementation: the column is `window_name`
(`window` is reserved in PostgreSQL; the API field stays `window`, as `sla_targets` already does);
`[today, today + 7 d]` is inclusive — eight partitions; `updated_by` is the `AuditLabel` text.

**Agent B's adversarial pass** (`gate_b_test.go`, `config_gate_b_test.go`, `gateschema_b_internal_test.go`):

### 1.4 Store core — changeset 2 (task 2, Agent A)

`internal/store/gate.go` (sentinels, `GateActor`, the audit row inside the mutation transaction,
`newGateDecisionID` — UUIDv7 from the DB instant, SQLSTATE classifiers), `gatepolicy.go` (FOR UPDATE →
validate → CAS → no-op → write; revision as a generation; override closure `policy_changed` /
`policy_deleted`; audit `gate.policy.write` / `gate.policy.delete`), `gateoverride.go` (create under the
service lock with the expired slot released first, revoke by id, reads with the status computed in the same
statement as `now()` and the live revision), `gatedecision.go` (ONE `REPEATABLE READ` read-write
transaction under the deadline wrapper; `SELECT statement_timestamp()` first; service row → policy →
active override → `serviceReliabilityReportTx` → the window's target → `burnLatchTx` →
`FindOpenAutoIncidentByService` → `serviceAlertingStateOn` → governing revision → the ledger INSERT; retry
once on 40001; `DecideGateAlgebra` pure in the domain), `gateledger.go` (by-id read pruned to the day the
id names; the keyset listing with `LIMIT n+1` and the cursor from the last RETURNED row). Owner
extensions, thin: `ServiceWindowReport.SealLag()`, `burnLatchTx` returns the lease and the verdict,
`serviceAlertingStateOn(ctx, q dbConn, …)`. 28 `Gate*` tests in both storage modes (own database
`cerbix_test_cs2`); eight mutations killed — cursor from the probe row, BurnedPercent recomputed
locally, no-op before CAS, override rewriting `state`, an ignored clause's unavailability → UNKNOWN,
coverage lease in `facts_fresh_until`, seal-stale bound loosened, expired override applied.

Spec points resolved in code (for the reviewer): an override applies whenever the un-overridden ACTION is
BLOCK — state BLOCK, or UNKNOWN under `unknown_behavior: block` (D9: "the observed state stays BLOCK or
UNKNOWN"); `seal_lag` is stated by the report as a method and by the decision as a wire field, the
report's own JSON shape untouched; evidence-only absences (`no_governing_revision`, `never_evaluated`) are
`reasons[]` entries without a clause and never enter the algebra; NOT_CONFIGURED reads no owner;
`fact_revisions` are the distinct revision ids of the report's segments, digest SHA-256 over the sorted
ids; a burn clause with no rule of its severity is a KNOWN non-match, a firing rule with an expired lease is
`facts_stale`.
