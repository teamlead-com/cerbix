### 1.4 The adversarial pass on the store, and five fixes (task 2, Agent B)

Agent B broke the landed store in its own worktree (both storage modes: TimescaleDB `cerbix_test_0165b` and
a throwaway plain `postgres:16.14-alpine`) and pinned what it found; every fix has a regression that fails
on the unfixed code:

- **B-1 — the identity lock depended on the caller's SPELLING of the service id.** `hashtext(ServiceID + …)`
  hashed the string as given; PostgreSQL accepts an upper-case or brace-wrapped uuid everywhere else in the
  transaction, so two writers spelling the same service differently took DIFFERENT locks, both passed the
  order check, and two terminals landed in one group (proven on `c6c74dd` with both backends parked at
  their INSERT). The key now hashes `$1::uuid::text` — the canonical spelling — through ONE SQL fragment
  (`changeIdentityLockSQL`) shared by the writer and the purge; a non-uuid text is `ErrNotFound`.
  `TestChangeIdentityLockKeyDoesNotDependOnTheCaseOfTheServiceID`,
  `TestChangeRecordAcceptsEveryUUIDSpellingAndAMalformedServiceIDIsNotFound`.
- **[41] P1 — a backdated phase recorded after the open was linked.** The correlation's candidate
  universe is now rows with `recorded_at <= opened_at`; the anchor is each group's latest phase from that
  universe; the window test applies to it. `TestChangeCorrelationIgnoresPhasesRecordedAfterTheOpenHoweverTheyAreDated`
  (unfixed: a ghost link with lag 120 and a note). Five existing correlation tests now pin `opened` one
  minute ahead of the clock so their rows are recorded by the open.
- **[42] P1 — retention never took the identity lock.** `PurgeChangeGroups` is one transaction of three
  statements: select the keys (LIMIT, key order) → `pg_advisory_xact_lock` per key through the shared
  fragment → re-evaluate `max(occurred_at) < cutoff` in a post-lock snapshot and delete only the keys still
  old. The purge WAITS on a held lock, bounded by the caller's context (the scheduler's maintain timeout); a
  cancelled batch rolls back with nothing deleted; the counts are rows actually deleted.
  `TestChangeRetentionWaitsForAHeldIdentityLockBoundedByTheCallerAndDeletesNothingWhenCancelled`,
  `…KeepsAGroupWholeWhenAYoungTerminalCommitsBetweenSelectionAndDelete`,
  `…SerializesAWriterBehindThePurgeOfItsIdentity`. Named for the reviewer: up to
  `retention_groups_per_batch` (≤ 2 500) advisory locks per transaction, one lock-table slot each.
- **[43] P2** — the two-int key and the honest collision sentence (D4 amended); **[40] P2** — the authz
  test comment names `Can` and `VisibleScope`.
