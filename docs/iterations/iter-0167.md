## 1. What landed

**A library, not view logic** (`frontend/src/lib/scenarioBindings.ts`, 16 vitest cases). Every rule in
it is the server's rule from `internal/domain/syntheticbindings.go`: the grammar, the flat reference
key, the credential-bearing header set, the URL prohibition, duplicate headers case-insensitively,
declared-and-unused, and the malformed reference key that used to be ignored in silence. Two things the
client adds are the two only a client can know — which project secrets exist right now, and WHERE in
the form each refusal belongs. It invents no rule of its own: a client-only refusal would be a rule
nobody could discover from the API, and a client-only permission would be a lie.

**The three properties the mock was approved for** (`NewMonitorView.vue`, 6 vitest cases on the real
component):

- the mapping panel above the steps, where a binding name is never rendered without the project secret
  that fills it, with the flat key and the used-in list on the row;
- a credential-bearing header stops being a free-text box and becomes a binding picker — D7 taught by
  the control, with the refusal still shown in the server's words for a scenario that arrives carrying
  a literal;
- "save before test" at the button, with the Test control disabled and the reason stated, because an
  unsaved test has no envelope to carry a binding (D10).

And the residual in the same voice as the mock: a pasted-looking value in an ordinary header gets a
hint offering the inventory, never a refusal. cerbix cannot tell a credential from data there, and a
rule that guessed would refuse legitimate data and still miss the next credential.

**A defect the tests found, older than this work.** `canSubmit` required `form.target.trim()` for every
active type, while `showTarget` hides the target field for `synthetic` — the type has no target, and
`NeedsTarget()` says so on the server. So **Create monitor was permanently disabled for a synthetic
monitor**: the type could not be created from the SPA at all. It survived because no unit test and no
E2E had ever submitted this type, which is the same coverage gap FR-SYN-3's row already names. Fixed
with the scenario as the synthetic's own submit condition.

## 2. Gates

`npm test` 38 files / 416 tests (was 37 / 410); `npm run build` clean, `make spa-snapshot` regenerated
and committed with the change that produced it; `go build`; `make docs-check`.

**A test of mine that lied, caught by running the whole suite.** `e2e/tests/synthetic-bindings.spec.ts`
passed alone and failed as part of `make dev-test`, with "the monitor was created" false. The cause was
the test, not the code: it waited on `waitForURL(/\/monitors(\/|\?|$)/)`, and `/monitors/new` — the page
it was already on — matches that pattern, so the wait returned instantly and the list was read before
the POST had landed. Standalone it passed on timing luck. It now polls the API for the monitor, which
is the thing it actually means to wait for. Recorded because "passes alone, fails in the suite" is the
signature of a test waiting on the wrong thing, and the next reader should recognise it faster than I
did.

## 3. Not done

The editor writes bindings; it does not create project secrets — that stays in the inventory panel,
because a credential typed into a monitor form is the habit FR-028 exists to end. And D9 is untouched:
a synthetic monitor still cannot live in a Monitoring-as-Code bundle.

## 3a. The review's P1, and what it says about my tests

The reviewer read the shipped editor and refused it on a finding I should have caught myself: the
approved invariant is that a credential-bearing header **stops being a free-text field**, and the
implementation rendered the selector only once a binding existed. Worse, the default scaffold opened
with `Authorization: Bearer {{token}}` — which the server refuses under D7 — so **choosing Synthetic
opened a form whose own example could not be saved**, and two of my tests asserted that refusal as the
normal initial state. That is documenting a bug as behaviour, which is the failure mode I am most prone
to and the one an independent reviewer is for.

Three corrections:

- the default scaffold demonstrates `extract` → interpolate with an id used in the next step's path —
  what `extract` is actually for — and puts no credential anywhere. Under the server's contract an
  extracted `{{token}}` cannot be used in an `Authorization` header at all, so shipping that as the
  first thing an operator sees was wrong in principle, not merely inconvenient;
- the value control is a selector from the first keystroke of a credential-bearing header NAME: empty
  and disabled with "Add a binding first" until one exists. A free-text box until then is what invited
  the literal;
- three regressions instead of the one asked for — the form opens with no refusal and no free-text
  credential control; the selector appears (disabled, with its instruction) as soon as the header name
  is credential-bearing; and a literal that arrives **from another surface** is still refused in the
  server's words, so fixing the first two cannot silently delete the check that matters for an API or
  bundle write.

Also mine, and fixed at the source rather than by hand: every docker build in this repo wrote
`frontend/node_modules` and its caches as ROOT, so any tool later run as a developer — vitest creating
`node_modules/.vite-temp`, eslint, a plain `npm run build` — failed with EACCES on a tree it owned
nothing in. It stopped the reviewer from running the frontend tests at all, twice, because my first fix
was a `chown` and the next `make spa-snapshot` recreated the problem. `make spa-snapshot` now passes
`--user` and an in-container npm cache, the Makefile comment says why, and it names the one-time cleanup
a tree already built as root needs. For two rounds **the reviewer's verification was a
`vue-tsc` pass and a diff read and NOT a local vitest run**, recorded that way at their explicit request
because a green run of mine is not evidence of theirs. After the build fix it became reproducible: their
own run is 24/24 on the focused scenario-binding suites, then 38 files / 418 tests on the whole frontend
suite, plus `vue-tsc --noEmit` — with pre-existing `RouterLink` resolution warnings in the SlaView tests
as the only stderr, unrelated to this range and named rather than absorbed.
