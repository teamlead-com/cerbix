## 2. What the rule could not anticipate: two majors that are one decision

`vue-router@5` declares `peerOptional vite@"^7.3.0 || ^8.0.0"`. On Vite 6 the install fails outright
with `ERESOLVE`. So "each major alone" is not available here: **vue-router 5 and Vite 8 are one
decision**, and the honest sequence is Vite alone first (verified: 38/418 and a clean build), then
vue-router on top of it (verified again). That is what was done, and it is written here rather than
presented as two independent verifications that never happened.

## 3. Declined, with the reason

**TypeScript 5.9.3 → 7.0.2 — NOT taken.** TypeScript 7 is the native compiler port, and `vue-tsc`
3.3.11 cannot drive it: `npm run type-check` dies in `vue-tsc/index.js` resolving the tsc entry point
with `ERR_PACKAGE_PATH_NOT_EXPORTED`, before type-checking a single file. This is a toolchain
incompatibility upstream of anything in this repository, so there is nothing here to fix and nothing to
work around that would not amount to dropping the type-check from the build. The bump waits for a
`vue-tsc` that supports TypeScript 7. The dependabot branch stays open on purpose; closing it would
lose the reason.

## 6. A note on the test database, because it cost an hour

The full `-race` suite failed 43 tests with `TruncateAll` deadlocks and org-slug conflicts, and none of
it was the code. Another agent was running its own verification against the SAME `cerbix_test` database
at the same time — visible directly in `pg_stat_activity` as a `DROP DATABASE IF EXISTS
cerbix_test_utcprobe_…` issued from a connection to `cerbix_test`. Two suites truncating one database
deadlock, and the loser then finds every fixture's organization already present.

The fix is per-run isolation, not coordination: `CERBIX_TEST_DATABASE_DSN` pointed at a private
`cerbix_test_v019`. Note that the database NAME must contain `test` — `TruncateAll` refuses anything
else, which is a guard worth knowing about before naming a scratch database.
