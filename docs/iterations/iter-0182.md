## 1. Problem

The status-page service/component fix identified a repeatable failure mode: transport code enforced
same-project ownership, while a direct store or SQL writer could persist the forbidden edge. Alert
routing contained the analogous risk in the paths that decide who is woken:

- a monitor could be linked directly to another project's notification channel;
- escalation-policy JSONB targets were checked only by handlers;
- schedule create checked participants, but update did not;
- override channels were checked only by handlers;
- frozen service escalation snapshots could retain or receive foreign target JSONB;
- runtime target resolution loaded policy and schedule ids globally.

## 4. Acceptance evidence

- HTTP, direct store and direct SQL paths agree that a foreign routing reference is invalid.
- Rejected policy and schedule updates leave the stored value unchanged.
- Update methods cannot validate against one project and mutate an object from another.
- Frozen snapshots and live escalation resolution cannot select another project's target.
- Missing/foreign routing ids share one API response and do not create an existence oracle.
- Migration and runtime paths delete no heartbeat, incident or audit data.
