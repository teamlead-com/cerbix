# iter-0189 — service-first compact public status page

**Opened:** 2026-09-21
**Lifecycle:** CLOSED — implementation, regression coverage, live proof and delivery synchronization complete.

## Goal

Keep the public status page readable when many incidents are active by placing component state first,
compressing incident presentation without hiding the latest public update, and adding privacy-safe
component-to-incident navigation.

## Agent A — Implementation

- [`handlers_statuspage.go`](../../internal/api/handlers_statuspage.go) computes ordered,
  deduplicated, page-local `affected_component_ids` from the canonical monitor/service anchor without
  persistence. Public and authenticated preview share the relation while the preview retains its
  operator-only fields and public rendering keeps all internal anchors, actors, update authors and
  postmortem identities redacted.
- [`openapi.yaml`](../../openapi.yaml) makes the relation required and generated
  [`schema.d.ts`](../../frontend/src/api/schema.d.ts) carries the contract.
- [`PublicStatusView.vue`](../../frontend/src/views/PublicStatusView.vue) now renders the canonical
  service-first section order, deterministic compact incident accordions, truthful timelines and
  page-local component navigation without URL identifiers. [`style.css`](../../frontend/src/style.css)
  supplies the two-line preview clamp and narrow-width wrapping remains intrinsic.
- No database schema, feed, webhook, subscriber, incident-detail or persistence contract changed.
