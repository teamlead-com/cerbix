## 1. Problem

At the base commit, one public CLI was split across a manual top-level switch, command-local standard-library
`flag.FlagSet` parsers, manual `gate`/`change` dispatchers, and duplicated usage strings. Root help was a flat
synopsis. `help <command>` ignored the requested command, most leaf help paths exited `2`, `gate --help` and
`change --help` were unknown subcommands, and `version --help` executed the version encoder. Required flags,
defaults, environment contracts, exit classes, and examples had no one command-tree owner.

The migration had to improve discoverability without changing the application contracts that pipelines and
operators use: documented paths, canonical long flags, types, defaults, requiredness, environment variables,
stdout/stderr behavior, and semantic exit codes. The approved exception is explicit: six leaves that silently
ignored positional tokens now reject them with usage exit `2` before side effects.

## 2. Approved design and architecture

The owner approved [`cross-cli-command-tree.md`](../specs/cross-cli-command-tree.md) on 2026-10-02 before
production code changed. D-0265 records the implementation boundary:

- Cobra owns the root, groups, leaves, lookup, arguments, flags, required metadata, and help;
- `Main(args []string) int` remains public and `cmd/cerbix/main.go` remains the only `os.Exit` site;
- typed options separate parsing from parse-independent executors;
- `ExitError` keeps exit mapping application-owned;
- root uses `SilenceUsage`, `SilenceErrors`, explicit output/error writers, and disabled suggestions;
- the public completion command and implicit version flag are disabled;
- `internal/config` remains the YAML/config owner; no persistent pre-run or global registry exists;
- Viper is excluded;
- gate/change credentials remain `CERBIX_URL`, `CERBIX_TOKEN`, and optional `CERBIX_CA_FILE`, environment
  only, with no credential flag, remote-server `--url`, insecure mode, redirect following, retry, or TLS
  bypass.

The resulting hierarchy is:

```text
cerbix
├── serve
├── migrate
├── reencrypt
├── adopt-fact-month
├── enqueue-service-repair
├── gate
│   └── check
├── change
│   └── record
└── version
```

`root.go` derives the grouped catalogue from this Cobra tree. `help.go` renders leaf/group sections from
command and registered flag metadata. One registration helper records order, placeholder, and required
annotation; synopsis, validation, and help consume it, while defaults come from the registered Cobra flag
value rather than a second usage list.

## 5. Compatibility matrix

| Surface | Base behavior | Implemented behavior |
| --- | --- | --- |
| `cerbix` | exit `2`, flat usage on stderr | exit `2`, grouped catalogue on stderr |
| `cerbix -h`, `--help`, `help` | exit `0`, flat usage on stdout | exit `0`, grouped catalogue on stdout |
| `cerbix help <path>` | ignored the path and printed root usage | renders that group/leaf's structured help |
| runtime/recovery leaf help | exit `2`, native-flag usage on stderr | exit `0`, detailed help on stdout |
| `gate --help`, `change --help` | unknown subcommand, exit `2` | group help, exit `0` |
| `gate check --help`, `change record --help` | exit `2`, native-flag usage on stderr | detailed help, exit `0` |
| `version --help` | executed version JSON | command help, no encoder execution |
| unknown top-level command | exit `2`, diagnostic + root usage | exit `2`, diagnostic + grouped catalogue, no suggestions |
| unknown nested subcommand | exit `2`, diagnostic + group usage | exit `2`, diagnostic + structured group help, no suggestions |
| unknown/extra `help` path | exit `0`, ignored every supplied help path and printed root usage | exit `2`, deterministic unknown-path diagnostic, no runtime access |
| unknown flag / invalid duration on flag-owning commands | exit `2`, stderr, no runtime access | exit `2`, deterministic Cobra diagnostic, no runtime access |
| `version --bogus` | exit `0`, version JSON | unchanged through a Cobra flag-error compatibility seam; mixed unknown-flag/positional paths still exit `2` |
| missing required/value validation | exit `2` before config/request | same class and side-effect boundary |
| gate semantic outcomes | `0` ALLOW/WARN, `1` errors, `2` BLOCK, `4` NOT_CONFIGURED | unchanged |
| change semantic outcomes | `0` recorded/replayed, `1` transport/server errors, `2` 400/404/409 or usage | unchanged |
| gate/change streams and JSON | summary/raw body stdout; reasons/refusals/diagnostics stderr | unchanged |
| env/security | URL/token/optional CA environment only; verified TLS; no redirect/retry | unchanged |
| completion / implicit version flag | absent | absent |
| undocumented single-dash long flags | accepted incidentally by stdlib `flag` | not a compatibility invariant; canonical `--name` only, plus `-h` |
| six previously ignored positional paths | could reach config/runtime or version output | exit `2`, `unexpected argument`, empty stdout, executor not called |

## 8. Exit ownership and side-effect boundaries

`cmd/cerbix/main.go` remains:

```go
func main() {
    os.Exit(cli.Main(os.Args[1:]))
}
```

Cobra never exits. `Main` constructs the root with explicit writers and maps `ExitError`. Runtime commands
return typed command errors; already-rendered diagnostics carry `Printed=true`, so Cobra does not duplicate
or add usage. Root no-args and group no-subcommand remain usage exit `2`; explicit help is `0`.

The positional tests cover both the short form (`serve extra`, etc.) and otherwise-valid flags plus
`extra`. Each requires exit `2`, readable `unexpected argument`, empty stdout, and zero executor calls.
Gate/change extras retain zero HTTP requests.

## 9. Mutation evidence and harness limit

The permanent gate/change tests compare every semantic exit class to literal expected codes. A requested
mutation run temporarily changed gate BLOCK from exit `2` to exit `0`, but the harness security classifier
blocked executing the test while that weakening was present. The line was immediately restored, and
`TestGateCheckBlockExitsTwo` passed on the restored code. No attempt was made to bypass the denial, and the
remaining security/exit weakening mutations were not run. This is a documented **SKIP BY HARNESS**, not a
passing mutation result. The permanent tests and the forthcoming independent review remain the evidence.

## 12. Review

The first independent read-only review returned **REJECTED** with one Critical and six
Important findings:

1. root `--` / post-`--` could exit `0` without executing a requested gate;
2. direct pflag imports made module metadata and the sole-direct-dependency claim false;
3. manual `Use` strings duplicated flags/defaults and group usage drifted;
4. Cobra's default help command accepted unknown/extra paths and exposed a second inventory;
5. rejected `CERBIX_URL` diagnostics could echo embedded credentials;
6. `version --bogus` introduced an unapproved compatibility tightening;
7. source/dependency/complete-tree/version-zero-executor guards were incomplete.

All findings were reproduced and fixed under TDD:

- root argument validation now runs after Cobra parsing, with post-`--` zero-request regressions;
- exact-path application help replaces Cobra's default help command;
- one registration helper owns parser flag plus order/placeholder/required metadata, and a metadata mutation
  test proves synopsis/sections/defaults move together;
- direct pflag imports are gone, pflag remains transitive, `go mod tidy -diff` is clean, and an automated
  production import/module guard enforces the boundary;
- invalid URL diagnostics are generic/redacted for both gate and change;
- version handles legacy unknown flags through Cobra's `FlagErrorFunc`; raw-argument context prevents an
  unknown flag from consuming a positional, and an injected executor proves help/error zero calls;
- the complete grouped runnable leaf SET and every top-level GroupID are asserted.

The second independent re-review returned **WITH FIXES** with two Important findings:

1. pflag's unknown-flag whitelist consumed the next token, so `version --bogus extra` executed JSON instead
   of enforcing positional exit `2`;
2. the compatibility table incorrectly said old unknown help paths fell back to nearby help, while the base
   manual `help` case always ignored the path and printed root usage.

Both were reproduced and fixed. Version now uses a Cobra flag-error seam with raw-argument context:
unknown flags alone keep base JSON/exit `0`, while long/short/equals unknown flags followed by one or more
positionals return exit `2`, empty stdout, and zero executor calls. The spec/iteration baseline wording now
states the measured root-usage behavior. Fresh focused/full/build/vet/race/docs/diff/help/module/scope gates
are green again. The third independent review returned **APPROVED**: Critical, Important, and
Minor findings are empty, and all ten required-scope checks PASS. Technical review is complete; owner
implementation sign-off and commit authorization remain pending.

The owner then withheld sign-off after a newer independent high-effort review, which supersedes that
approval for closure purposes. The twelve required corrections were:

1. positional arguments must outrank trailing `--help` on gate/change/version;
2. misspelled nested gate commands with help must remain unknown-subcommand errors;
3. misspelled nested gate commands with leaf flags must not degrade to unknown-flag errors;
4. the same two nested-command rules apply to change;
5. command examples must be shell-safe and contain no `<...>` redirection tokens;
6. `serve --region` must describe worker and agent, empty = core;
7. adoption timeout addition must be overflow-safe before config/DB;
8. root construction must not mutate `cobra.EnableCommandSorting`;
9. hidden/unavailable commands must not enter the root catalogue;
10. help writer errors must have one public `--help` / `help` exit contract;
11. each item needs RED/GREEN, targeted/full CLI evidence, and real-binary probes;
12. all full gates and a new independent review must run before owner approval is requested again.

All implementation fixes and regressions are present. Public help is intercepted through the Cobra tree,
parsed with the target command's registered flags, validated before rendering, and returns typed exit `1`
on writer failure. Local command-order metadata replaces the global sorting mutation and filters hidden/
unavailable nodes. Help examples use concrete inert UUIDs. Adoption refuses timeout values whose context
margin would overflow. Targeted tests, the complete CLI suite, and the seven specified real-binary
invocations are green. Fresh full repository verification and a new independent scoped review remain
pending.

That fresh independent review returned **WITH FIXES** with three Important and two Minor findings:

1. raw argv help detection stole `--help`/`-h` when they were valid string-flag values;
2. assignment help forms (`--help=true`, `-h=true`) bypassed the typed writer-error path;
3. the hidden/unavailable fixture was absent from local order metadata, so its test did not reach the
   production availability filter;
4. lifecycle prose mixed already-green full gates with pending verification;
5. README omitted `change record --timeout 10s`.

All five were reproduced and fixed under TDD. Help intent now comes from Cobra's parsed boolean flag after
target parsing; string values travel normally, while exact and assignment help forms use the same
error-returning renderer. Hidden/unavailable fixtures enter the local order metadata, and a controlled
availability-filter mutation makes the regression RED before restoration. README and lifecycle evidence
are synchronized. Targeted tests, the complete CLI suite, and rebuilt-binary string-value/assignment-help
probes are green. Fresh focused/full/build/vet/race/docs/diff/help/module/scope gates and rebuilt-binary
value/help matrices are green. Independent re-review remains pending.

That re-review returned **WITH FIXES** with one Important residual: the candidate scan stopped at the first
raw `--`, even when Cobra consumed that token as a string-flag value and a later exact help flag was real.
This let config/external-id value `--` plus later help reach Cobra's void `HelpFunc`, masking a broken output
writer as exit `0`. The residual was reproduced and fixed by continuing the candidate scan and letting
`ParseFlags` decide whether each `--` was a value or end-of-options marker. Rejecting-writer regressions now
cover exact and assignment help after string value `--`; rebuilt-binary `/dev/full` probes return exit `1`
for migrate and change forms. Fresh focused/full/build/vet/race/docs/diff/module and binary matrices are
green. The final independent re-review is **APPROVED**: Critical, Important, and Minor findings are empty;
all twelve high-effort blocker checks and all ten original review scopes PASS. Technical review is complete;
owner implementation sign-off and commit authorization remain pending.
