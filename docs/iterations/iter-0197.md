## Root causes and RED record

1. `scanHelpFlagIntent` handled `-h`, `-h=true`, and `-h=false`, but `splitFlagToken` did not classify `-hh=false` or `-hhh=false`. pflag then interpreted shorthand clusters on its own, leaving help false and executing the command. Pre-fix `TestUnsupportedShorthandClustersFailBeforeRuntime/migrate/-hh=false` observed an instrumented executor call and a real `config_load_failed` with exit `1` instead of the expected typed usage exit `2`. The new matrix covers `-hh=false`, `-hhh=false`, `-hh=true`, `-hhh=true`, `-hh`, `-hhh`, `-hfalse`, `-htrue`, `-abc`, and `-config` across migrate, adopt-fact-month, enqueue-service-repair, gate check, and change record, plus root and group command positions.
2. `firstVersionPositional` used the string `""` both for a real empty positional and for absence. The version `FlagErrorFunc` used `positional != ""`; after an unknown flag it ignored a real empty positional, executed the encoder and returned JSON/exit `0`. Pre-fix `TestVersionEmptyPositionalsFailBeforeEncoder` failed on `--bogus ""`, `--bogus "" extra`, invalid help followed by `""`, and unknown+false-help followed by `""`, in both root and direct command execution. Empty `""` without a preceding parse error was already rejected by Cobra `noArgs`; the bypass was in the flag-error seam.
3. The writer failure contract was **already correct** at this base: the new injected-writer test passed without a production writer change. To prove that permanent test is sensitive, a temporary `go test -overlay` mutation of `version.go` suppressed the write error before any production fix. `TestVersionWriterFailureIsRuntimeErrorNotUsage` went RED: exit `0`, one attempted write, no `version:` diagnostic; restoring the unmodified source returned GREEN. This is mutation evidence, not a claim that writer handling was broken at `1ca047a`. The native-baseline `/dev/full` exit-0 behavior is the owner's supplied characterization; this iteration verified the rebuilt current binary's exit-1 behavior.
4. `TestCLIRollbackSpecRequiresBaselinePathRestoration` failed against former §15: it detected “rollback is a source revert of that commit” across a line wrap and absence of the baseline SHA/path-scoped recovery procedure. This is an executable guard against restoring the unsafe canonical prose.
