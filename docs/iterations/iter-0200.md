## Source

`.github/workflows/security.yml` had been failing on `main` (push and nightly) since at least
2026-10-03, so v0.3.5 was tagged with it red. Two independent causes, both read from the failed run
`37448133708`:

1. **`npm audit --omit=dev --audit-level=high`** — 3 high-severity production advisories:
   `@vue/server-renderer` < 3.5.42 (GHSA-g2v6-rqmx-r4w6, XSS via a missing CR in the attribute-name
   blacklist; reached through `vue`), and `source-map-js` (GHSA-68fv-2mgg-jv7q, event-loop DoS).
2. **`go install golang.org/x/vuln/cmd/govulncheck@latest`** — `x/vuln` v1.8.0 requires Go 1.26 while
   the job builds with the go.mod toolchain (Go 1.25, `GOTOOLCHAIN=local`), so the scanner never
   installed and nothing was scanned.

## RED (reproduced locally, before any change)

- `npm audit --omit=dev --audit-level=high` in `node:22-alpine` on the base lockfile: exit 1, 3 high.
- In `golang:1.25.13-bookworm` with `GOTOOLCHAIN=local`: `go install …govulncheck@latest` →
  "golang.org/x/vuln@v1.8.0 requires go >= 1.26.0". (A first attempt ran in a stale local
  `golang:1.25` image, Go 1.25.12, which cannot load this module at all; its printed "exit 0" was
  `tail`'s, not govulncheck's. That run is not evidence; the gate was re-run on 1.25.13 below.)
