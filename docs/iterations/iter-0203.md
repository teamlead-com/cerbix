## Source

The owner, 2026-10-08: the pilot's status page lists so many past incidents that the page is very
long; incidents will keep growing even after any noise is removed, so pagination is needed
regardless. Agreed in chat before the spec: ten past incidents on the page, a history page navigated
by month, history depth unchanged at 90 days.

Reading the code showed a second reason: `store.IncidentsForPage` returns every resolved incident of
the last 90 days with no `LIMIT`, each enriched with its timeline and postmortem, on an endpoint an
anonymous visitor can call — unbounded public render cost (§13.1).

**Deviations from the approved spec and mock, recorded rather than hidden:**

1. **`title` added to `IncidentHistory`** (spec §13.4 and `openapi.yaml` amended). The mock's history
   page shows the page title in its header and the response had no title; fetching the whole render
   for one string would cost exactly what NFR-033 bounds.
2. **Month labels end in ` UTC`** ("September 2026 UTC"), where the mock showed "September 2026". The
   project's own guard (`wallclock.spec.ts`, NFR-025b/c) requires every zone-less renderer to be one
   of two forms and every UTC phrase to end in ` UTC`; a month label is a UTC phrase. On narrow
   tiles the label may wrap to a second line.
3. **The partial month's start reads "10.07.2026 UTC"** (`utcDayLabel`), where the mock showed
   "10 Jul 2026" — the same guard forbids `toLocale*` formatting in product files.

## Tests and evidence

**Store** (`internal/store/incidenthistory_internal_test.go`, both storage modes): the page limit
and flag; the `id` tie-break; UTC month bounds, the window's open lower bound and a partial oldest
month; a keyset traversal that returns every incident once across pages and a tie; counts and list
in one snapshot (the seam writes between the two reads); the partial index in both query plans (round 0 version; replaced in review round 1, below).

- RED: the package did not compile against the old store (no limit, no `RecentMore`, no history).
- First GREEN run, two test faults found and fixed: the fixture's `UPDATE` needed explicit
  `timestamptz` casts, and one expectation had the order of two September instants backwards (the
  product was right: 23:59:59 UTC is newer than 22:00 UTC).
- Mutations, one per run: limit read exactly (flag never set), keyset `<=`, month start bound
  dropped, window bound dropped, list read outside the snapshot — each killed. **The `id`
  tie-break mutation SURVIVED the first version of the tie test**: through the index the rows
  already come out in `id` order. The test now disables index scans so only the `ORDER BY` can
  order six tied rows with random ids; the tie-break mutation is then killed in both the page query
  and the month query.

**API** (`internal/api/api_statushistory_test.go`, against the fake store; the SQL is the store
tests' business): the render's ten and flag; access rules of both routes (public, internal, unlisted
with and without token, member, outsider); every `400` before any store read; paging at 50 with the
cursor, the offered months and counts, `from` clipped to the window, the default month, the title;
the shared projection and redaction; the cache key and the component ceiling.

- These tests were written before the handlers but first RUN after them, so the RED was
  reconstructed by reverting to the pre-iteration behaviour (routes removed, flag false, page
  unbounded): all six failed.
- Mutations: cache key without month, month not checked against the offered months, cursor not
  bounded to its month, history without public redaction, history without the ceiling, `next_cursor`
  never set, offered months off by one — each killed.
- One fixture fault: the fake's incident ids were not UUIDs, which the cursor (rightly) refuses.

**Frontend** (vitest): `PublicStatusView.spec.ts` — scope label, link present only when more exist,
token kept; `PublicStatusHistoryView.spec.ts` — navigator with `aria-current` and disabled ends,
months navigated through the URL with the token and never a cursor, *Show more* appending with the
cursor, empty and partial months in words, a month outside the history explained, the internal
preview through the authenticated route, focus to the month heading on a month change (the route
mock is reactive, as vue-router's is). **The history spec found a real defect**: the view called
`load()` before declaring its accordion state, a `ReferenceError` the browser would have hit too.

**Live** (`e2e/tests/status-history.spec.ts`): a fresh project and public page, 52 incidents opened
