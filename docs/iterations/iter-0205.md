## Cause

`last_active_at` on `GET /admin/users` (`ListAllUsers`) and on the organization member list
(`ListOrgMembers`) was `(SELECT max(created_at) FROM sessions …)`. Sessions do not last: the
default TTL is 24 h (`internal/settings/service.go`), the scheduler deletes expired sessions
(`DeleteExpiredSessions`), and sign-out deletes its own (`LogoutHandler`). A user without a live
session therefore read "never"; a user with one read the time of that sign-in, not of their
activity. The owner's own row read "7h ago" only because their session was alive. Established from
the code; the pilot was not queried for this iteration.

Bearer tokens and client-credentials JWTs do not come through it. |

## Tests

**Store** (`internal/store/lastseen_internal_test.go`, both storage modes):

- `TestLastActiveSurvivesTheSessionsThatStampedIt` — three users sign in; one signs out
  (`DeleteSession`), one has every session swept (`DeleteSessionsByUser`), one's session expires
  and is purged (`DeleteExpiredSessions`); with no session left at all, both lists must show each
  sign-in time, and a user who never signed in reads never. **RED** before the fix: all six
  readings "never" — the screenshot's defect.
- `TestTouchUserSeenRefreshesOnlyAStaleStamp` — absent → stamped; 4 m 50 s old → unchanged;
  5 m 10 s old → now; `updated_at` unchanged throughout. RED: column missing.
- `TestLastSeenMigrationBackfillsFromTheNewestSession` — re-runs migration 00111's Up section
  over data: the newest of two sessions, a single session, no session → NULL, an existing stamp
  kept. RED: column missing.

**Auth** (`internal/auth/lastseen_test.go`, hermetic, injected clock):
`TestSessionRequestsRefreshLastSeenAtMostEveryFiveMinutes` — first session request stamps; 4 m 59 s
later no write; another user is stamped on their own schedule; at 5 m the first is stamped again; a
bearer-token request stamps nothing; a failing refresh keeps the response 204 and is retried on
the next request. RED: no stamp.

**Mutations** (12, each killed; the store ones on both storage modes): sign-in does not stamp;
users list reads sessions again; members list reads sessions again; SQL refresh guard dropped;
refresh moves `updated_at`; backfill overwrites a stamp; backfill takes the oldest session;
middleware never refreshes; throttle boundary inclusive (`<=`); no in-process throttle; a failed
refresh remembered; bearer tokens refresh too.

**E2E** (`e2e/tests/admin.spec.ts`, "users page: last active survives the user's sign-out"): the
OIDC fixture user signs in through Keycloak in a context of its own, signs out (`/me` → 401), and
the admin's user list must carry a `last_active_at` no earlier than that sign-in, with the row not
reading "never". Against the old code this list still had the older session `auth.setup` left
behind, so the assertion is on THIS sign-in's time.

- **First attempt was wrong, and dangerous.** Inside a Playwright test, `browser.newContext()`
  inherits the project's `use` options, including the admin's stored session. The "separate"
  context was the admin: `/login` went to the dashboard, the SSO click timed out (60 s) — on the
  old image and on the new alike, so that failure was no RED. Had it reached `/auth/logout`, it
  would have ended the session every other spec shares. Fixed: the context is created with an
  empty `storageState`, and before signing out the test asserts `/me` is `testuser@example.com`.
- **RED** (new spec on an image built from `main` = `c848883`): `last_active_at` was
  1 791 563 861 638 ms, earlier than this test's sign-in (≥ 1 791 563 863 119, which includes 2 s
  of slack) — the `auth.setup` session's time, since this test's own session was gone.
  Note on strength: in that targeted run `auth.setup` ran ~1.5 s before; had it run within the 2 s
  slack, the old code would have passed this assertion. In the full suite `auth.setup` runs
  minutes earlier.
- **GREEN**: the spec, inside the full `make dev-test` on an image built from this branch.

## Review round 1 — APPROVED (no P0–P2; seven P3)
