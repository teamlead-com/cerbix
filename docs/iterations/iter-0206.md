## Origin

On 2026-10-07 the owner reported that a user could not be given "Project Admin" from the Members
page. That turned out to be the role model (Project Admin is a project-scoped role, granted through
Invite with a project scope), but the same investigation found a real contradiction: the role table
promised a Project Admin "Manage project members & settings", while every member endpoint required
`org:manage`. It was noted and not tracked until 2026-10-17, when the owner chose to give the Project
Admin that power rather than correct the table.

## Tests

**Store** (`internal/store/projectmembers_test.go`, real database, both storage modes; two orgs with
two projects each) — written first, RED against stubs ("not implemented"), GREEN after:
`TestProjectMembersListsOnlyThisProjectsRows`, `TestProjectMembershipWritesAreScopedToTheProject`,
`TestCreateProjectMembershipTellsItsFailuresApart`.

**API** (`internal/api/api_projectmembers_test.go`) — written first, RED (routes absent → 404 where
200/403/400/409 was wanted; the org endpoints' 500 on a vanished membership; the org audit target
without the project), GREEN after. The API fake filters by project the way the SQL does; the store
tests are what hold the SQL scope.

**Mutations** (manual protocol; each killed, store ones on both modes):

1. scoped update/delete without `AND project_id` → store test;
2. members list without the project filter → store test;
3. inherited list without the org filter → store test;
4. gate on `project:read` → API (org viewer on another project got 200);
5. "membership of this project, else 404" — there is no separate handler check; the scope is the
   SQL's, so this is mutation 1;
6. `org_admin` through PATCH (handler check removed) → API (200 instead of 400);
7. machine-principal refusal removed → API;
8. membership loaded before the project gate → API (editor: 404 for an unknown id instead of 403);
9. org PATCH vanished membership back to 500 → API;
10. audit target without the project → API;
11. duplicate folded into 400 → API.

A first run of mutation 6 did not apply (two replacements, the first broke the second's match) and was
re-run alone; it is reported as killed only from that re-run.

**vitest** (`ProjectMembersPanel.spec.ts`, `SettingsProjectMembersTab.spec.ts`) — written after the
component, so their strength is shown by mutations, each killed: tab gated on project WRITE; invite
offering Org Admin; invite sending a `project_id`; self-removal not handed to the parent; panel
reading the ORG endpoint. (The script's summary line mislabelled the last one "SURVIVED"; its output
shows three failed tests — killed.) Two existing specs' session mocks gained `canProjectAdmin`
(SettingsView now calls it).

**E2E** (`e2e/tests/admin.spec.ts`, "project admin manages the members of their own project"): the
admin session makes the Keycloak fixture user `project_admin` of the E2E project through the new
endpoint; the fixture user, in a context of its own with an empty `storageState`, opens Settings →
Project → Members, checks the role options, adds `admin@cerbix.local` as viewer, changes the role,
removes them, and sees the org Members tab's unchanged message. Everything granted is removed in
`finally`.

**The first E2E run failed, and found a product defect.** The fixture user landed on another
organization ("Acme" from the retained dev database) without the Members tab. Two causes:

1. **Test.** The test pinned the E2E workspace in `localStorage` after sign-in, and the dashboard's
   workspace init, still in flight, wrote the user's first organization back over it. The test now
   pins the workspace with `context.addInitScript` before any page loads and asserts the SPA is on
   "E2E Harness" before looking for the tab.
2. **Product.** `/settings?tab=projectmembers` resolved the deep link at mount, before the workspace
   had its project. At that moment the project tab is not in the list, so the link fell back to the
   first tab. `SettingsView` now remembers a requested tab and selects it as soon as it appears. A tab
   the user picks by hand supersedes it. vitest "deep link /settings?tab=projectmembers" covers this
   with a workspace that gets its project only in `init()`. Disabling the deferred selection fails
   that test (1 failed, 11 passed).
