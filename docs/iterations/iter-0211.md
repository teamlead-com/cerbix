## Review of the branch (owner, at `1f1bbd8`): code accepted, three document and one code finding

1. **The runbook was wrong about a proxy that rewrites `Host` (blocked the merge).** It said every
   current browser sends `Sec-Fetch-Site`, so a rewritten `Host` is harmless. Browsers send
   `Sec-Fetch-*` only to potentially trustworthy origins (HTTPS, `localhost`). Over plain HTTP the check
   compares `Origin` with `Host`, and behind nginx `proxy_pass` without `proxy_set_header Host` every
   change — sign-in included — is 403. The runbook paragraph is rewritten (the order of the check, when
   a rewritten `Host` is harmless and when it breaks sign-in, the nginx fix with
   `proxy_set_header Host $http_host`, or HTTPS); the CHANGELOG has an upgrade note with the symptom and
   the fix; `docker-compose.prod.yml`'s comment and the Traefik section of `overview.md` say to keep
   `Host`. No example in the tree dropped `Host`: there is no nginx config, and the Traefik example
   keeps `passHostHeader`'s default. Two rows of
   `TestCrossOriginUnsafeRequestsAreRefusedBeforeAnyHandler` pin the behaviour (not a red test): cookie,
   no `Sec-Fetch-Site`, `Origin: http://cerbix.company.com`, `Host: cerbix:8080` → 403; the same with
   `Sec-Fetch-Site: same-origin` → 200. The guard's code is unchanged.
2. **A proxy that adds `Authorization: Bearer`** (oauth2-proxy `--pass-authorization-header`, or
   `--set-authorization-header` with nginx copying the header) makes every SPA request a Bearer
   request, whose cookie is never read: the whole SPA is 401. Upgrade note and runbook, with the fix
   (do not forward the header). `--pass-access-token` is named as harmless: it sends
   `X-Forwarded-Access-Token`.
3. **`withReferrerPolicy` compared the path case-sensitively**, while the SPA's routes match in any
   case: `/STATUS/<slug>` rendered the public page under `strict-origin-when-cross-origin`. No token
   reached another site (that policy sends no path), but S9a was broken to the letter. The prefixes
   are now compared case-insensitively. Three rows of `TestReferrerPolicyOnEverySurfaceOfTheApplicationPort`
   (`/STATUS/…`, `/Status/…/history`, `/API/V1/PUBLIC/…`) were RED before the fix (`dc03793`) and
   are green after it (`e778aa1`).

## Second external review: CHANGES REQUIRED — three findings, all accepted, no vulnerability

1. **The gate's POST refused an empty body of unknown length.** The first round's fix checked the
   content type first, and `auth.HasJSONContentType` admits only a DECLARED-empty body
   (`Content-Length: 0`). A body of unknown length (`ContentLength == -1`: HTTP/1.1 chunked, HTTP/2
   without content-length) that is in fact empty got 415, against "no body needs no type".
   `HasJSONContentType` is unchanged (every other decoder needs a body); `gateDecodeEmptyBody`, when
   the type is not JSON and the length unknown, reads at most one byte through `MaxBytesReader`: none
   (`io.EOF`) is "no body" and passes, one — a space too — is 415 and the rest is never read.
   `TestGateEmptyBodyOfUnknownLength` (bodies wrapped in `io.NopCloser`, because httptest gives a
   `*strings.Reader` a known length): red — zero bytes without a type and under `text/plain` were
   415; green after. The first round's cases stay green. Red `c4d402e` → fix `08f149a`.
2. **The Bearer exemption is asked of a `ServeMux`, not approximated.** The first round's predicate,
   `path.Clean(r.URL.EscapedPath())` under `/api/`, still disagreed with the router:
   `PATCH /%61pi/v1/status-pages/{id}` is routed by `ServeMux` to the `/api/` handler (it matches on
   unescaped segments) and was refused 403 by the guard. `forgeryGuard` now holds a `ServeMux` with
   the one pattern `/api/` whose handler is a comparable marker (`*apiMarker`, a pointer to an empty
   struct); a request is exempt when `apiRoutes.Handler(r)` returns that marker and
   `auth.HasBearerAuth(r)` holds — the way `CrossOriginProtection` asks its own mux about bypass
   patterns. Redirects for unclean paths are not the marker, so they are never exempt.
   `TestForgeryGuardAsksTheMuxWhichRoutesAreAPI`: red — Bearer, cross-site `PATCH /%61pi/…` was the
   forgery 403; green after (200, run as the token). Its cookie rows (`/%61pi/…`, `/%61uth/logout`,
