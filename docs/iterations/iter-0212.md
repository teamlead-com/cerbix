## Changes

- **H-7.** Migration `00116_users_totp_last_step.sql`: `users.totp_last_step bigint NULL`. `SetTOTPSecret`
  and `DisableTOTP` write NULL. `totp.Validate`/`ValidateAt` return the matched step (`totp.Step`). The local
  sign-in (`secondFactorOK`) accepts a code only if `store.AcceptTOTPStep` — the spec's compare-and-set —
  updates a row; a spent code falls through to the recovery-code check, which a six-digit code never
  matches. `totpEnable` records no step. `EnableTOTP(ctx, userID, recoveryHashes)` is now `UPDATE … SET
  totp_enabled = true WHERE id = $1 AND NOT totp_enabled` **and** the recovery-code replacement, in one
  transaction (`ErrTOTPAlreadyEnabled` otherwise, answered 400 as before). Recovery codes are otherwise
  untouched: still hashed, still single-use.
- **H-8.** `httpsrv.newHTTPServer`: `ReadTimeout` 15 s (unchanged), `ReadHeaderTimeout` 5 s, `IdleTimeout`
  60 s, no `WriteTimeout`. The ssh banner loop and the redis AUTH/PING replies read through one
  `io.LimitReader(conn, 4 KiB)` each; the WebSocket handshake response through `io.LimitReader(conn, 16 KiB)`.
- **H-9b.**
  - `internal/appmux`: `withReferrerPolicy` became `withResponseHeaders` — `X-Content-Type-Options: nosniff`,
    `X-Frame-Options` (`DENY`; `SAMEORIGIN` public), the spec's policy verbatim as
    `Content-Security-Policy-Report-Only` (`frame-ancestors 'none'`; `'self'` public), and the D-0278
    `Referrer-Policy`. "Public" is one predicate, `isPublicPage` (case-insensitive, `/status`, `/status/…`,
    `/api/v1/public/…`), asked once per response for all four headers. The header name is one constant,
    `cspHeader`: enforcement next release changes that constant.
  - `internal/httpsrv` sets `nosniff` on `/healthz`, `/readyz`, `/metrics`.
  - The pre-paint theme script is `frontend/public/theme-init.js`, loaded synchronously from `<head>`.
  - `POST /auth/logout` answers 200 `{"redirect_to": …}` (`Cache-Control: no-store`). `session.ts` posts with
    `redirect: "manual"`, reads `redirect_to` (falling back to `/` on any other answer) and navigates with
    `window.location.assign`; `AppShell.signOut` no longer pushes the login route itself — the full page
    load to `/` lands there.
  - `domain.PostLogoutURLAllowed`: a local path (`/…`, not `//…`, no backslash, no control byte) or
    `http(s)` with a host. `setOIDCSettings` answers 400 otherwise; `LogoutHandler` serves a failing value
    — from a row or from the config file — as `/` and logs `post_logout_url_refused`.
  - E2E: `e2e/tests/fixtures.ts` extends `test` with an automatic fixture that exposes a binding and adds
    an init script listening for `securitypolicyviolation` on every page of the test's context and of every
    `browser.newContext()` the test opens; violations on the cerbix origin fail the test (another site's
    page, such as the identity provider, answers to its own policy). All 37 specs import `test` from it.
    `csp.spec.ts` checks the headers on the live stack and commits a violation on purpose under
    `test.fail()`. `auth.spec.ts`'s logout test now signs out through the account menu in its own
    anonymous context.
- **H-10.** `domain.SupportURLAllowed` (`http(s)` with a host, `mailto:` with an address, or empty) in
  `Branding.Validate`; `publicBranding` serves a failing stored value as `""`. The admin read still shows
  the stored value, so it can be corrected.
- **H-11.** `server.ops_listen` (new, empty by default). With it set, `httpsrv.New` registers `/readyz` and
  `/metrics` on the application port as `http.NotFoundHandler()` and serves them, with `/healthz`, on a
  second server whose catch-all is 404. `ListenAndServe` runs both and returns the first failure after
  closing the other; `Shutdown` stops both. `config.Validate` refuses `ops_listen == listen`.
  `docker/config.prod.yaml` sets `":9091"`; `docker-compose.prod.yml` publishes `${CERBIX_OPS_BIND:-127.0.0.1:9091}`
  (also in `.env.prod.example`); `config.example.yaml` documents the key empty. Dev configs, `wait_ready` and
  the image are unchanged; no healthcheck.
- **H-12.** `metrics.Registry.readiness()` — the one predicate — feeds `Ready()`, `LastError()`, the new
  `Readiness()` (code and raw detail) and `cerbix_ready`. Order and codes: `starting` / `shutting_down`
  (the lifecycle flag, by whether the process was ever ready), `database_unreachable` (`cerbix_database_up`),
  `broker_unreachable` (`cerbix_broker_up`), `credential_unavailable`, `service_wedged`,
  `alert_evaluation_stalled`. `readyz` serves `{"status":"not_ready","error":<code>}` and logs `not_ready`
  with the code and the raw detail once per change (and `readiness_restored`). `pingDatabase` sets only
  `cerbix_database_up`.
- **OpenAPI** and `gen:api`: logout 200 with the `redirect_to` schema and its description;
  `post_logout_url` and `support_url` rules on the write schemas and in the PUT descriptions (both already
  documented 400).

## Departures from the spec

None in the six findings. Readings, stated (also in D-0279):
- **H-7.** The recovery codes are written in `EnableTOTP`'s transaction. The spec names only the
  `WHERE NOT totp_enabled` guard; with the codes written before it (as on `main`, for lockout safety), a losing
  concurrent confirmation replaced the codes the winner showed — `TestEnablingTOTPIsSingleUseAndKeepsTheWinnersRecoveryCodes`
  checks the winner's code signs in. "Recovery codes not touched" is kept in substance: generation, hashing
  and single use are unchanged.
- **H-9b.** `nosniff` is also set by `httpsrv` on the operational endpoints ("any surface"); the page headers
  stay on the application handler. The SPA falls back to `/` when the logout answer names no destination.
- **H-12.** The lifecycle flag answers `starting` before the first ready and `shutting_down` after; its
  free-text reason goes to the log only.
- **S12's "process".** The test drives the registry and `/readyz` exactly as the AMQP role wires them, not a
  live process with a stopped broker (see "Not verified").

## Found during the iteration, fixed in separate commits (owner, 2026-11-14)

`docker/config.prod.yaml` said in its header comment that "`config.Load` expands `${VAR}`". The loader
expands the whole file, comments included, and refuses an undefined name, so the production example failed
to start with `config: undefined environment variable(s): VAR` unless a variable named `VAR` happened to
exist — on `main` as on this branch. The compose file passes eight variables into the container, and `VAR`
is not one of them. The reference in the comment is now written `$${NAME}` (the loader's escape for a
literal `$`), and the comment says why.
- `TestTheProductionExampleLoadsWithTheComposeEnvironment` (config) reads the `environment:` block of the
  `cerbix` service in `docker-compose.prod.yml`, sets exactly those eight variables, and loads
  `docker/config.prod.yaml` through the real loader (it also checks `listen` 8080 and `ops_listen` 9091).
  RED before the fix:
  ```
  config_prodexample_test.go:46: docker/config.prod.yaml with the compose environment (8 variables): config: undefined environment variable(s): VAR
  ```
- `docker/config.example.yaml` had the same pattern in its header (`${ENV_VAR}`), so
  `cerbix serve --config docker/config.example.yaml` — the runbook's "Run locally" — failed the same way, and
  `TestExampleConfigGateBlockLoadsAndEqualsTheDefaults` defined `ENV_VAR` to get past it. Fixed the same way
  in a second separate commit, by the owner's ruling: the reference is `$${ENV_VAR}`, and the test no longer
  defines the variable (it removes it if the environment has one). RED with the workaround removed and the
  header unchanged:
  ```
  config_gate_b_test.go:103: Load(../../docker/config.example.yaml): config: undefined environment variable(s): ENV_VAR
  ```
  No other config under `docker/` names a variable in a comment (checked with grep for `$` in every
  `docker/*.yaml` comment line; the remaining hit, a regex ending in `$,`, is not a variable reference).
