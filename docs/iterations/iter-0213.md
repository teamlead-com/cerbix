## Changes

- **T-1a, T-1b** (`internal/prober/postgres.go`).
  - **Closed list.** `pgProber.Probe` checks `sslmode` against the closed list before anything else: an
    explicit value outside `disable|require|verify-ca|verify-full|prefer` ends the probe with
    `bad config: unsupported sslmode` and no dial. An absent key executes as `prefer`.
  - **TLS built by the probe.** `pgTLS` builds the TLS configuration with pgx's SNI rules: `prefer` is
    `require` plus one plaintext fallback to the same host and port; `verify-ca` verifies the chain
    without the name; `verify-full` always names the target. `pgProber.roots`, unexported, is the test
    seam for the root pool.
  - **Constant parse and reset.** `pgx.ParseConfig` gets only `pgConstantConnString`; `resetPgConfig` then
    sets every field of `pgconn.Config` and `pgx.ConnConfig` listed in `pgResetFields`.
  - **Messages.** `pgConnectMessage` names the two causes the spec gives. `hostPort` strips the brackets of
    a port-less IPv6 target.
  - **E2E.** `probers.spec.ts` sends `sslmode: "disable"` to the dev Postgres, and a new case proves that no
    `sslmode` (`require`) is down with `does not offer TLS`.
- **T-1c.**
  - **Registry.** The credential-settings registry gains `legacy` per `writeDefault` field: `sslmode` →
    `prefer`, `tls` → `false`, `query` → `SELECT 1`, `path` → `/api/overview`. It also gains
    `domain.DefaultedExecutionKeys` and `domain.StateLegacyDefaults`.
  - **Gate.** `dispatch.ValidateAndMaterialize` refuses an envelope-v2 job of a credentialed type whose
    body lacks one of those keys, with `ErrBodyOmitsDefaultedSetting`. `CredentialProbeErrorReason` maps
    it to `unsupported_version`, so it never costs an executor its readiness.
  - **Core.** `materializeRow` states the legacy values in the job body before sealing, on every carrier.
  - **Fixtures.** They now state the keys: `agent_test.go` (`m1`, `m-future`, `m-desync`, `m-null`),
    `carrierenvelope_test.go` and `amqptestcarrier_test.go`. That is exactly the list §2.6 item 5 gave.
- **T-1d, T-5.**
  - **Store.** `UpdateMonitorByPrincipal` and `updateMonitor` take `configSubmitted`. Without a config the
    store skips preparation, the credential carry-forward and the binding resolution. It writes the row
    through `updateMonitorTxKeepingConfig`: `config = COALESCE($11::jsonb, config)` with NULL, no
    reference rewrite, the usual epoch bump.
  - **Handler.** `updateMonitor` reads through `GetMonitorForWriter` after the access check, and passes
    `body.Config != nil`.
- **T-2.**
  - **Delivery clients.** `prober.RefuseRedirects` is the `CheckRedirect` of `Guard.HTTPClient` and of the
    nil-client fallbacks of `notify.New` and `webhook.New`.
  - **Agent client.** It refuses redirects with its own inline function, so `internal/agent` does not
    import the prober.
- **T-4.**
  - **Shared helper.** `notify.DeliveryFailure` classifies a failed request into the closed set of §3.6,
    in that order. `webhook` imports it, so there is one copy. `notify.ErrInvalidURL` replaces the quoted
    parse error.
  - **Guard predicate.** `prober.IsEgressRefusal` is the new exported predicate over `*blockedIPError`.
- **T-3.**
  - **Address rule.** `domain.ValidMailAddress` is the one rule. It is used by `mailer.BuildMessage`,
    `Subscriber.Validate`, `NotificationChannel.Validate` (email `from`, each `to` element) and
    `MailSettings.Validate`.
  - **Builder.** `mailer.BuildMessage` is the only message builder: subject from `subjectLine` and
    `foldHeader`, the fixed five headers, the body as given. `Mailer.SendContext` and `notify.sendMail` use
    it, and `notify.sendMail` trims the channel `from`.
  - **Startup.** `Config.Validate` refuses `mail.smtp_host` with an empty or refused `mail.from`.
  - **P3-4.** `docker/config.example.yaml` and the comment of `MailConfig.Enabled` say what the code does
    now.
  - **Unchanged.** `internal/subscribe`.

## Deviations from the spec, and notes

1. **TestPostgresProbeRefusesAnSSLModeOutsideTheList, the `sslrootcert` case.** On `main` it was red because
   it dialed, not because of the file-existence message §2.2 describes. On this host the default host is the
   socket directory `/private/tmp`, so pgx never entered `configTLS`, and the oracle needs a host where
   `defaultHost()` is `localhost`. The fix and the test are unaffected.
2. **The certificate tests use `localhost`, not `db.test`.** The probe keeps the parse's `LookupFunc` (§2.6
   item 3), so a name has to resolve. `localhost` resolves everywhere, and the cases are otherwise as
   specified.
3. **TestChannelMailRefusesAnAddressItCannotSend puts CR and LF inside the value.** Surrounding whitespace, a
   trailing CR included, is trimmed before the rule (§4.2, S18), so `"ops@example.com\r"` becomes
   `ops@example.com` and is sent. An interior CR (`"…\rBcc: …"`) is refused. The mailer, which does not
   trim, refuses a trailing CR too.
4. **The amqp test-carrier fixtures** (`amqptestcarrier_test.go`) need a broker. `make race-both` skips them;
   they ran separately against a throwaway broker (§ Gates).
5. ~~**A side effect for review.**~~ **Withdrawn by the code review (P1-1, below):** with
   `secrets.enabled: false`, a PATCH without `config` on a reference-based monitor succeeded at `6a90e5a`.
   It is refused 404 `feature_disabled` again, as on main.
