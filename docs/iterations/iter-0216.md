### The controller's rulings

- **A display name containing `@` is cut to the part before it; an empty name names no recipient**
  (`c58c6db`, `51bb6ec`), in one shared place, because the spec says a recipient is never named by an
  email. Cost if wrong: the login part of an email address is shown instead of a name.
- **Review minors routed into the groups that touched the same code** (revision-7 M-1…M-4, M-7;
  group-A M-1, M-3, M-4, M-5; group-B 1, 2, 3, 5; group-C m-2, m-3 fixed in a private-database test
  before `race-both`). Cost if wrong: none; each was reviewed with its group.
- **A service's recovery reads "Service alert · recovered"**, the mock's message-table form; only the
  monitor's recovery is unified as "Monitor recovery" (the owner's one label). Cost if wrong: one
  constant in `lib/phone.ts`.
- **After a provider error on a code send** (502 `provider_rejected` / `provider_unreachable`), both
  surfaces return to the mock's not-sent step ("1 · Send a code to <mask>") with the server's sentence,
  because the backend stored a code that ended the previous one and none reached the phone. Cost if
  wrong: none; no new wording.
- **Revision-9 backend rulings, accepted at its review:** `telephony_can_call` is telephony on **and**
  the provider can place calls (false when never saved); `via` absent or `null` means SMS, anything
  else is 400 `via_invalid`; the voice refusal comes after the number's state answers and before a code
  is issued, so nothing is stored or spent; `via` is not stored. Cost if wrong: a refused call shows
  the server's sentence and the page re-reads `/me`.
- **The spoken verification code's introduction is English** — "This is your cerbix verification
  code." then the six digits one by one, said twice — whatever the voice `language` attribute, as alert
  calls are. Cost if wrong: a non-English voice reads an English sentence; a localised text is out of
  scope.

### The SPA plan's rulings

- **A failed read of the incident's phone activity renders 4d** ("Phone activity could not be read —
  this is not “nothing was sent”.") whatever the switch says, because the deliveries are unknown. Cost
  if wrong: a panel on an incident with telephony off when the read fails.
- **The incident Phone panel is oldest first, as the API returns it** (revision 8, P3-2); the channel's

## Known limits

- **Text channels receive a retried event again** (the owner's words): when the phone provider is
  unreachable, the event is retried and the text channels receive it again, just as when any text
  channel fails. A phone channel the provider accepted is not sent again for that event (D19). A phone channel left `provider_unreachable` is called again
  on the retry. Closing it needs a per-channel delivery record for
  text channels, a change of the outbox for every project, outside FR-041a.
- **`make dev-test` needs the reset seed.** The hourly code limit counts the requester, so a second run
  within the hour would get 429 `send_limited` on the bootstrap admin's fourth code.
  `e2e/seed/e2e-phone-reset.sql` runs from `dev-ready-single`, so on every `make dev-up` and before every
  `make dev-test`; each time it deletes the dev admin's own phone number. A direct `./e2e/run.sh` re-run
  within the hour skips it and fails test 4.
- **The E2E leaves telephony `configured: true, enabled: false`** on the dev stack; "never configured"
  cannot be restored through the API.
- **The way of the last code is not stored.** After a reload, with calls possible, the code lines name
  neither SMS nor call.
- **"today" / "yesterday" are fixed when a delivery list renders**; a list left open past midnight keeps
  the earlier word until it is read again.
